# AS2-W 工程教训：本会话已犯并已修正的错误清单

> 适用对象：任何在本仓库做 AS2-W 仿真、评测、导出或部署的 agent。
> 这份清单只记录**实际发生过、且被数据或源码证实**的错误，不是泛泛的注意事项。
> 每条都给出：**现象 → 根因 → 规则**。看过这份清单不能保证不犯错，但可以保证不去重犯这些。

**统计**：本会话共 9 类、38 条已确认错误，其中 8 条是被操作员的算术或源码直接推翻的。
**最贵的一条**花了 4 轮排查（`launch_simulation` import 顺序），而正确答案是「与 known-good 脚本逐行 diff」。

---

## 0. 三条最高频的元规则

先记住这三条，它们覆盖了本清单里超过一半的具体错误。

### 元规则 1：**任何从仿真接口读出的量，必须能说清它由哪条代码路径产生**
说不清它是命令/估算/求解器输出、是否经过限幅或滤波，就标 `not_measured`，不要拿它下结论。
> 反例：把 `applied_torque` 当成求解器驱动力矩。已安装版 Isaac Lab 源码写明：> *"it clips the effort telemetry but is not pushed to the solver"* —— 它限幅的是**遥测**，不是求解器施力。

### 元规则 2：**改动比较协议前，先确认被改动的量依赖的所有状态在两端语义一致**
episode 计数、相位计数、零位参考、参考系、动作历史 —— 任一项没对齐，你造出来的差异就是自己的。
> 本会话因这条错了 4 次（见 C 类）。

### 元规则 3：**静态检查通过 ≠ 入口可用；必须实跑一次**
AST 解析、编码检查、BOM 检查都只能证明文件"能读"，不能证明流程"能走通"、产物"能复现"。

## A. 索引空间错误（7 条，本会话最反复的一类）

### A1. 链式索引写到副本，代码"跑完了"但什么都没发生
```python
d.qpos[qadr][idx] = qv        # WRONG: d.qpos[qadr] is a COPY
d.qpos[qidx[k]] = qv[k]       # RIGHT: write through real indices
```
**现象**：IK 的 residual 恒等于目标值（10.000 mm），日志显示"跑完了"，但姿态一步没动。
**规则**：numpy 花式索引赋值只在**直接对视图**写时生效；`arr[fancy][slice] = x` 永远写副本。读没问题，写必错。

### A2. 用关节名索引接触传感器的 body 顺序
`net_forces_w` 按**接触传感器自己的 body 列表**排序，不是 articulation body 顺序，更不是关节索引。
**现象**：站立时 `sup_tail = 0.000` 恒为零（不可能），修了**两次**才修对：第一次把 calf 关节换成轮体名，仍错；第二次改为按 `env.scene["contact_forces"].body_names` 解析才正确。
**规则**：任何"按名字取索引"的代码，必须打印一次解析结果（`sensor_bodies=N wheel_idx=[..]`）作为可审计凭据。

### A3. 支撑算在小腿关节而不是轮体上
同一缺陷在本会话出现 **3 次**（两个脚本），每次都让支撑恒为 0 或负值。
**规则**：任何"支撑"数字必须三查 —— 索引对象是**轮体**、键名正确、**站立时为正**。缺一即判无效。

### A4. 键名读错导致假矛盾
读 `support` 而实际键是 `support_tail` → 得到一组虚假的"矛盾"结论并据此推理了两轮。
**规则**：跨脚本读 JSON 时，先 dump 一次顶层与嵌套键名。

### A5. `MjContact` 没有 `body1`/`body2`
访问 `c.body1` 会失败或给错值；正确是 `m.geom_bodyid[c.geom1]` / `[c.geom2]`。

### A6. 腿关节数组是 part-major，不是 leg-major
```python
JOINTS = [f"{leg}_{p}" for p in ("hip","thigh","calf","foot") for leg in LEGS]
# 布局: [FL_hip, FR_hip, RL_hip, RR_hip, FL_thigh, ...]
tgt[i*3+k] = ...   # WRONG (leg-major)
tgt[k*4+i] = ...   # RIGHT
```
**现象**："抬 FL"却让 **FR** 卸载、FL 仍有载荷。
**规则**：对合同里的并行关节数组，先写一行注释标出布局，再写索引。

### A7. 四元数/矩阵约定不一致
MuJoCo `qpos[3:7]` 是 `(w,x,y,z)`；写入其它仿真器前必须确认它要的顺序，不能假设相同。

## B. 参照量与分母错误（6 条）

### B1. 分母重复打折：把已是 90% 的值又乘 0.9
`deploy.yaml` 写的是 `torque_limits_nm: # 90% of the verified hardware limit`，`wheel: 13.5`。**13.5 本身就是 90% 值**，硬件上限反推是 15。
```python
tau_frac_90 = tau / (0.9 * 13.5)   # WRONG -> 13.5/12.15 = 1.11
tau_frac_90 = tau / 13.5          # RIGHT -> 1.00
```
**后果**：报出"力矩饱和到 1.11×90%"并推论"急停超预算"，两条都作废。
**规则**：读任何 `*_limits` 字段时，先读它的注释确认它是否**已经**是降额后的值。

### B2. 把累计行进距离当漂移
弧线工况报出 `body drift = 5.4583 m` —— 那是 0.25 m/s × 20 s 的**正常行程**。
**规则**："漂移"只在**指令为零**的相位内统计。移动工况的行程不是误差。

### B3. 用稳态末段均值评判振荡系统
振荡系统的末段均值≈0，看起来"收敛很好"，实际在 ±100 rad/s 之间摆动。
**规则**：振荡系统用**峰值/过冲倍数、包络衰减时间、符号翻转次数、饱和帧占比**判，不用均值。

### B4. 均值与逐帧峰值混标
把逐帧峰值 `0.309 rad/s` 与均值 `0.076 rad/s` 混在同一个"最大差"标签下。
**规则**：均值与峰值**分开标注**，永不混用。

### B5. 无量纲比值不写分母
"偏航差 0.0015 rad/s（<2%）" —— 2% 的分母是什么没交代。
**规则**：给比值必须写明分母；分母不清楚就给绝对量。

### B6. 算法未自证就引用
支撑余量算法最初对同一工况给出**符号相反**的两个值（+0.0139 / −0.0173），且对**四轮支撑**也返回负值（不可能）。
自证（解析算例 + 顺序无关性 + 四轮必为正）之后才发现原实现只取 3 条边、四边形上无意义。
**规则**：任何新指标先用**解析可算的算例**自证，再用于结论。且自证脚本自己的期望值也要复核（本会话我写错过两次三角公式）。

## C. 改比较协议造出来的伪影（4 次，同一根源）

### C1. 对齐时未同步相位计数
MuJoCo 的 `ep` 从 150 继续，Isaac 跳过 settle 从 0 开始 → `obs_phase` 出现 8.49 的假差异。

### C2/C4. 跳过 settle 相位，重新激活了 Isaac 的 episode 起始逻辑
`code/as2w_isaac_robust_env.py` 里有两处 episode 起始逻辑：
```python
alpha = (self.episode_length_buf * self.step_dt / 2.).clamp(max=1.)   # 前 2 s 动作斜坡
action = self.hold_action.lerp(action, alpha)

self.vel_command_b[self._env.episode_length_buf < 100] = 0.            # 前 100 步指令强制归零
```
`episode_length_buf` 在 `reset()` 后为 0、每步 +1 → **这两处只在 episode 前 2 s 生效**。
**后果**：
- 第一次（转向比较）：误报「首个分岔点 = 2 秒动作斜坡」→ 撤回
- 第二次（接地零差速）：`settle=0` 又激活斜坡，首 0.5 s 的「偏航差 0.1925」全是伪影 → 撤回
**规则**：**两端都用 `settle ≥ 3 s`**，跨过斜坡与门控；不要为了"让初态同源"去跳过 settle。若必须跳过，**同时**把 `episode_length_buf` 置大并同步相位计数。

### C3. 在补丁未提交时做"干净检出验证"
`git clone` 取的是**已提交**状态；补丁还在工作树 → 验的是旧代码，误判"补丁没生效"。
**规则**：任何干净检出验证必须在 `git commit` **之后**执行。

## D. 把数当成了它名字声称的量（3 条）

### D1. `applied_torque` 不是求解器施力（已被源码推翻）
Isaac Lab `actuator_pd.py` 的 `actuator_effort_limit` docstring 原文：> *"it clips the effort telemetry but is not pushed to the solver"*
`ImplicitActuator` 用当前关节状态**估算** PD+前馈并限幅该估算；PhysX 在求解器内部**另行**施加驱动力矩。**两条路径都能出现上限值 13.5，因此"截断"不能识别求解器实际施力**。
**规则**：Isaac 隐式驱动的**实际饱和率标 `not_measured`**；只能报"估算力矩触顶率"。MuJoCo 侧 `d.ctrl` 即施力，路径单一可验证。

### D2. `get_observations()` 返回 TensorDict
`o[0]` 取到的是**键名字符串** `'policy'`，不是张量 → `float('policy')` 报错。正确用 `o["policy"]`。

### D3. 未核 `episode_length_buf` 语义就用它当时钟
见 C2。凡是"前 N 秒"的逻辑，先确认计时基准是 episode 时间还是绝对时间。

## E. 静态检查通过但实际不可用（3 条）

### E1. 导出脚本 AST+BOM 全过，实跑两处失败
- **缺 `onnxruntime`** → 对齐步骤裸 `ModuleNotFoundError`- **产物格式不同**：torch 2.11 默认 dynamo 导出器写 **external data**（`policy.onnx` 1,885 B + `.data` 174,080 B），  与发布的**单文件** 175,066 B 不是同一格式，哈希也不同
**修法**：`torch.onnx.export(..., dynamo=False)` → 字节级复现发布件（sha `680e0c72…`）。
**规则**：交付入口必须"在干净检出实跑一次 + 比对产物哈希"，静态检查只能当地一道闸。

### E2. UTF-8 BOM 让脚本从第一版起就无法执行
`export_policy_onnx.py` 以 `U+FEFF` 开头，Python 3 报 `invalid non-printable character`。**规则**：包内所有 `.py` 过 **ast + BOM** 双检。

### E3. 加废弃标注把文字放到 `from __future__` 之前
→ `SyntaxError: from __future__ imports must occur at the beginning`，且**该坏文件已被推送**。
**规则**：改文件头只能替换**模块 docstring**，不能在 `from __future__` 之前插入任何语句；改完立刻过 ast。

## F. 环境与启动（3 条）

### F1. `as2w_*` 的 import 放在 `launch_simulation` 之前 → USD 库冲突（本会话最贵的一条，4 轮）
**现象**：`libusd_tf.so: undefined symbol: pxrInternal_...` / `libusd_usdPhysics.so: cannot open`。
**我当时查错的顺序**：`LD_LIBRARY_PATH` → 磁盘空间 → kit 缓存/锁 → known-good 脚本能否跑。**全错**。
**真正原因**：先 import IsaacLab/rsl_rl 栈会加载冲突的 USD，必须在 `with launch_simulation(...)` **内部** import。
**规则**：新脚本报"库加载失败"时，**第一步**是与一个 known-good 脚本逐行 diff 结构（import 位置、启动顺序），**再**去怀疑环境。这一条能省掉 4 轮。

### F2. 负号开头的参数值被 argparse 当成选项
`--leg-bias-rad -0.2467,...` → `error: expected one argument`。必须用等号形式 `--leg-bias-rad=-0.2467,...`。

### F3. patch heredoc 里写多行字符串
**同一类错误 3 次**（`.format()` 与 `%` 冲突、doc 里的 `{...}`、`help=` 里的真实换行）。
**规则**：通过 heredoc 下发的补丁**只用单行字符串**；文档用字符串拼接生成，不用模板格式化。

## G. 实验设计（4 条）

### G1. 固定基座 + 刚性保持 DEF → 机器人塌陷
`DEF` 只是**动作默认偏移量**的定义值，**不是本模型的稳定站姿**（策略稳定姿态与 DEF 相差可达 1.7955）。
**现象**：站立用例四轮全零、高度从 0.3814 掉到 0.1143。
**规则**：**所有 settle 都用策略跑**（加载 checkpoint），不要用刚性 PD 保持 DEF。本仓库所有能正常工作的脚本都是这样做的。

### G2. 自由基座 + 刚性腿做接地隔离 → 机身剧烈晃动
四轮不跟踪目标、彼此差异巨大，记录到的力矩被不稳定主导。**这是病态工况，不是有效隔离**，数据全部作废。

### G3. 力矩只在 20 ms 采样点重算一次并在 32 个子步内保持
**现象**：目标 +0.5 rad/s 的首个 20 ms 样本末轮速达 **+24.5 rad/s**（49 倍过冲），随后反向振荡到 −100。
**根因**：`tau` 算在子步循环**之外**。若每 0.625 ms 重算，一个 20 ms 内即收敛到 **0.5000**。
**我是被操作员的算术纠正的**：`3 N·m × 0.020 s / 0.0025 kg·m² ≈ 24 rad/s`。
**规则**：力矩/控制量必须在**子步循环内部**用最新状态重算；只在采样点算一次会造出巨大的假过冲。

### G4. 选腿按关节误差而不是按支撑余量
按"关节误差最大"选腿，选到的**正是余量为负**（已在支撑三角形外）的腿 → 抬起来必然倒下。
**规则**：单腿动作必须**先按已自证的余量为正选腿**；且注意余量只有 0.1–2.4 cm 量级，抬升目标必须与之匹配（曾错误地要 10–30 mm）。

## H. 结论过度外推（4 条）

### H1. 单仿真改善就宣称改善
姿态偏置在 MuJoCo 上把零指令漂移从 14.5 cm 降到 2.5 mm，**在 Isaac 上却是 0.7 mm → 22–30 cm（65–350 倍恶化）**。
**规则**：腿姿/参数类结论**必须两端同口径复测**；单端改善不构成证据。符合 goal「不得以腿姿变化掩盖轮端执行不足」。

### H2. 从 1/8 个组合得出通用规律
"负载失衡先于卸载 0.7–1.0 s" 只在左原地转成立；扩到 8 个组合只有 1 个复现，其余多为 1–8 帧起始瞬态。

### H3. 从"零差速时两端一致"推出差异范围
零差速时轮子几乎不承担切向力，**带载轮速驱动根本没被检验** → 不能据此把差异缩小到"策略输出 vs 轮载重分配"。

### H4. 把自己的对齐伪影当成两端的分岔
见 C2。**规则**：报"首个分岔点"之前，先自查该窗口是否落在任何一端特有的瞬态里。

## I. 验证与交付流程（3 条）

### I1. 自动判据写得太严，差点否掉可用字段
我用"applied 与下发值差 <0.2 才算 APPLIED"，结果三个字段**全部**被判不可用 —— 因为该字段含阻尼叠加项。
真正判定靠的是**超限截断**这个不可伪造的特征（下发 20 → 读出 13.5）。
**规则**：判别字段语义用**限幅/截断签名**，不要用"是否跟随"这种会被叠加项污染的特征。

### I2. 清单在修复前生成 → 干净克隆 194/195
提交了脚本修正却忘了重生成 `SHA256SUMS`，包内清单与文件不一致，**但我当时已报告"推送成功"**。
**规则**：**先改、后规范、最后生成清单**；推送后必须从**全新 clone** 校验 `sha256sum -c`。

### I3. 只在工作树校验，没从远端 clone 复核
第一次推送后从远端 clone 才发现 194/195。**规则**：交付校验一律以远端 clone 为准，不以工作树为准。

## K. 一条正面经验：校验失败本身就是产出

本会话有一次 `loads_n` 开跑校验**失败**（站立四轮全零、抬 FL 却卸载 FR）。若跳过校验直接跑接地三档，会得到"腿映射错位 + 机器人倒伏"的载荷数据，并据此得出"哪只轮先卸载"的**完全错误**的定位。
**失败的自检装置本身就是正确产出** —— 它拦住了一个错误结论。**不要为了让数据"能用"而降低校验标准。**
