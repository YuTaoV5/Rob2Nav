# Go2 侧空翻训练手册

## 1. 目标与当前边界

本流程复现连续参考衔接、安静准备段和物理子步约束的侧翻续训。当前候选仍有翻转段目标突变/超速与落地失败，不保证训练后自动合格；左右翻需分别检查旋转方向。

## 2. 环境与前置条件

本手册使用Linux Bash；先完成[环境准备与路径约定](../../docs/环境准备与路径约定.md)。每个新终端在仓库根目录运行`source scripts/docs_env.sh`。变量只表示你自己的安装位置，不依赖原服务器。

训练必须使用Isaac解释器。运行前查看GPU占用，确认没有同名任务；本手册命令不会自动接管现有训练。

## 5. 输出与验收

检查`completion.json`、`env.yaml`、`agent.yaml`、`fixstand.json`、`contract.json`和模型。烟测的`physical_statistics.json`必须确认每个50Hz控制周期有10个物理样本；传感器周期与物理步长均为0.002秒。

完成训练后按仿真手册验收固定模型。至少独立四种子，记录失败；新训练不承诺与历史权重逐位相同。

## 6. 常见问题与下一步

找不到模块：确认当前目录为仓库根目录，并source环境文件。找不到解释器：核对`CPU_PY`与`ISAAC_PY`，二者不能混用。输出目录已存在：换一个新目录，不删除旧实验。显存不足：降低环境数，并把改变后的参数保存到新实验记录。

每次保留原始命令、实际配置、模型SHA256和完整日志；退出码0不等于动作通过。继续阅读[训练手册](训练手册.md)、[仿真手册](仿真手册.md)、[部署手册](部署手册.md)。

## 关节增益对照配置（研究试验）
网页“创建训练”选择侧翻原生 PPO 后，可编辑“关节位置增益 Kp”和“关节阻尼增益 Kd”；默认分别为 40 和 1。命令行对应 `--joint-kp 40 --joint-kd 1`。这些参数在左右翻中共用，作用于全部十二个关节，不是单独小腿的增益配置。

改变增益会改变实际动力学，不能只改导出 JSON 或部署配置后称为训练适配。训练器将参数写入实际执行器和 contract.json；导出时检查实际 env.yaml 与合约一致，单技能 MuJoCo 从导出合约读取增益。统一部署配置的十二项 kp/kd 也必须与模型一致，加载侧翻模型的 JSON 元数据时会拒绝不匹配。旧模型默认仍为 40/1。

当前 Kd=2 仅提交 32 环境、2 次更新的网页接口烟测，任务 df310a187da04c32 排队；它只检查配置能否实际训练，不代表动作达标，也没有提交该条件的正式长训练。必须等实际 YAML、导出核验和物理对照完成，再决定是否需要续训。所有独立动作、首尾 FIXSTAND、接地、逐物理步速度/限位及消抖门槛继续保留。

## 全动作目标连续性配置
仅准备段安静并不能保证空翻全程无抽动。最终左翻冻结权重在诊断种子27100的右前大腿目标于约2.78秒单个50 Hz周期跳变1.34541 rad；Kd=1.2仍跳变1.36954 rad。目标变化不是实测关节速度，两者必须分别检查。

网页侧翻参数新增“全动作目标变化率惩罚权重”（默认0关闭）与“起罚比例”（默认0.8）。命令行对应 `--target-rate-weight 5 --target-rate-margin 0.8`，要求启用边界残差控制。奖励读取映射后的目标增量，按每个关节URDF速度乘真实控制周期归一化，惩罚超出起罚比例的峰值；作用于整个动作，不只准备期，不修改物理状态或直接滤波关节。

侧翻单技能验收新增 target_continuity：相邻已记录目标变化率相对URDF速度的峰值必须不超过1。该门槛只约束指令连续性，不能替代实测速度、接地、姿态或录像复看；首帧无上一条目标记录，启动衔接仍需统一热切换验证。旧汇总不自动获得新门槛认证。默认奖励为0，因此现有右翻和阻尼有界续训计划保持原有奖励条件。
