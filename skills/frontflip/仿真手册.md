# Go2 前空翻仿真手册

## 1. 目标与当前边界

原生控制合约下完成正俯仰前翻，首尾四足站稳。现有v1四种子均没有完成动作，不能把“没翻倒所以约束通过”视为前翻成功。

## 2. 环境与前置条件

本手册使用Linux Bash，先完成[环境准备与路径约定](../../docs/环境准备与路径约定.md)，每个新终端先在仓库根目录`source scripts/docs_env.sh`。这是独立正俯仰任务，不能倒放后翻视频或取旋转绝对值冒充前翻。

CPU推理需ONNX Runtime、MuJoCo等依赖；按环境准备安装，不用普通CPU环境启动Isaac训练。

## 3. 选择权重与配置

```bash
export SOURCE="$ROB2NAV_UPSTREAMS/GO2_backflip"
export RUN=outputs/reproduction/frontflip_run01
test -f "$RUN/completion.json"
MODEL=$(find "$RUN" -maxdepth 1 -name 'model_*.pt' | sort -V | tail -n 1)
test -n "$MODEL"
"$CPU_PY" -m skills.backflip.export_cpu --checkpoint "$MODEL" --output "$RUN/exported"
```

导出器名称包含backflip，是共享60维网络和电机合约的工具；任务方向来自保存元数据，不代表把前翻当后翻。

## 4. 执行与观察

```bash
"$CPU_PY" -m skills.backflip.simulate --source "$SOURCE" \
  --onnx "$RUN/exported/policy.onnx" --direction front --seconds 5 --physics-hz 1000 \
  --fixstand-roundtrip --diagnostics --video --seed 15500 \
  --output outputs/reproduction/frontflip_seed15500
```

固定同一权重，再用15501–15503和新目录复测。方向与导出合约不一致时程序应拒绝，不能删除校验。完整预算后的四种子也可由evaluate_fixstand_run.py完成，但该脚本当前的外部源码路径需要先按本机适配，不把旧实验启动脚本当成通用安装入口。

## 5. 输出与验收

查看summary.json、diagnostics.json、trace.json和原速完整录像。检查expected_direction=front、direction_pass、action_completed、fixstand和hardware_constraints_pass；所有项联合通过才考虑切换测试。反向整周或只有站立都失败。

## 6. 常见问题与下一步

缺policy.onnx时先完成导出，缺输入模型时回到训练手册。缺配置/方向不符时检查同一轮导出元数据，不能拼接别轮文件。仿真通过后另做连续技能与设备验证，见[部署手册](部署手册.md)。
