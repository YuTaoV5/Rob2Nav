# AS2-W 训练方 → 部署方交付清单 v3

日期：2026-11-12。适用于滚动、步行、爬楼、倒地起身、站姿保持等不同策略。**这是一份按技能裁剪的交付清单，不要求每个策略做前进、刹车、回固定站或所有双仿真场景。**训练方先声明本版本要解决什么任务、从什么状态开始、输出什么、已在哪些场景测试；部署方只对声明的能力做相应 sim2sim 和真机验收。未声明的能力不自动视为支持。

核心要求只有一条：**部署方拿到交付物后，能在不猜测训练时开关和接口的情况下，重现“真实输入 → 模型 → 后处理 → 控制目标”的结果，并知道测试证据的适用范围。**下面的“所有策略必交”指足以达到这一点的最小信息；“按需模块”只在策略使用或声称支持该能力时启用。字段不适用写 `not_applicable + 原因` 即可，**无需为不适用能力补做实验**。

## 1. 先用一页 README 声明范围

训练方交付的 `README.md` 首页用下面的表填实值。不要只写“训练好了”“仿真可用”。

| 项目 | 要说明什么 |
|---|---|
| 策略身份 | 名称、版本、交付日期、负责人、最终权重/模型 SHA256；本次训练输出与初始化所用旧权重分别列出 |
| 技能 | 例如“倒地后起身”“本体盲爬楼”“平地轮式滚动”；是单策略还是多个策略/状态机组合 |
| 输入与输出 | 输入是关节/IMU/速度/命令/历史中的哪些量；输出是腿位置、轮速、力矩、模式还是高层指令；实际维度与频率 |
| 入口与终点 | 允许什么姿态/速度开始，成功终点是什么；是否依赖外部 FixStand、恢复策略或原厂运控 |
| 已验证的范围 | 各仿真器、场景、初态、速度/地形/跌倒类型、通过数/总数；哪些是仅视频演示、哪些是正式验收 |
| 未验证与已知失败 | 不支持的能力、失败案例、危险动作、依赖的支架/地面/设备条件；真机是否测试及测试到哪一步 |
| 建议用途 | `research_only`、`sim2sim_candidate`、`bounded_field_candidate`、或列明具体已通过的真机动作；说明理由 |

**示例**：起身策略可以写“支持左侧倒地与俯卧起身，输入需要机体系速度，输出12腿关节位置；不接受行走速度命令，终点为站立2秒；楼梯/前进/停车不适用”。滚动策略则要说明 `vx/vy/wz` 哪些轴生效以及松杆行为。这样部署方不会把“会站”“会走”“会爬楼”混为同一合同。

## 2. 所有策略必交的最小核心

允许文件名不同，但必须有一份 `manifest.yaml` 或等价总索引，以**相对路径**指向下表材料。大文件可用部署方有权限访问的固定下载地址，但要附大小、SHA256和获取方式；训练服务器 `/root/...` 只能作为溯源，不能是唯一交付路径。包外另给压缩包 SHA256；包内清单校验除自身以外的文件，避免自引用哈希。

| 核心项 | 训练方交什么 | 部署方拿它做什么 |
|---|---|---|
| C1 版本溯源 | 本次**实际输出**的选中权重/checkpoint与部署模型（ONNX若使用）各自 SHA；初始化用旧 checkpoint 另列；训练 run ID、准确命令、训练当时不可变代码 commit/tag 或源码快照、解析后的配置、依赖/环境版本 | 确认没有拿错权重或较早 run 的合同，能够重建模型和接口 |
| C2 模型接口 | 输入/输出名称、形状、dtype、控制周期、hidden state/历史是否内置、ONNX opset和验证过的 Runtime/架构（若交付ONNX）、导出脚本与checkpoint→部署模型的同输入差值 | 在x86/ARM64正确加载并排除导出错误 |
| C3 观测合同 | **每一维**名称、索引、单位、坐标系、正方向、来源、缩放/裁剪/滤波、时间戳/数据龄、缺测处理；历史/相位/上一动作的含义及重置规则 | 用AS2-W实际传感器构建同一输入，不把仿真真值错当实机可得值 |
| C4 输出到控制目标 | 原始模型动作到最终可执行目标的全部步骤、源码与**本次实际生效参数/开关**：关节/轮顺序、尺度、偏置、限幅、补偿、插值、PD/前馈或速度模式；包装内部状态如何初始化/更新/复位 | 做逐帧 parity，并移植成部署控制器；不从模型输出直接猜电机命令 |
| C5 入口/退出语义 | 策略能从哪些状态启动、首帧历史/积分器/相位怎样设置，何时算成功或失败，结束时输出什么、控制权怎样交给外层；若依赖外部状态机，列出依赖和未定义部分 | 设计安全接管、退出和按键；不把策略终点误认为整机已站稳 |
| C6 训练仿真与资产 | 所用机器人URDF/XML/mesh、碰撞、质量/惯量、接触/摩擦、执行器模型与增益、物理/控制步长、传感/动作延迟和随机化；对应文件版本和SHA，至少给训练仿真可复跑入口 | 在第二仿真器重建尽可能相同条件，解释sim2sim第一处分歧 |
| C7 已有验证证据 | **该版本实际跑过**的命令、配置、种子/初态、分母、逐例结果、失败样例；可以只有训练仿真，没跑MuJoCo就明确`not_run` | 判断目前证据能支撑哪种候选状态；不用新报告替旧权重背书 |
| C8 最小回放样本 | 几段与本策略相关的固定输入/状态序列，以及每帧模型原始输出、包装后输出和下一帧历史值；提供能重算的脚本或精确伪代码 | Python↔C++、checkpoint↔ONNX逐帧对齐；定位第一处分歧 |

**最低严谨度**：C3/C4 必须描述策略**实际使用的**每个字段/开关；没用到的功能不用填写。若训练时源代码后来改了，当前 `code/` 目录不代表当时版本；必须给旧 commit/快照。`resolved_config` 是那次运行实际解析后的值，不能只抄命令行或代码默认值。训练、正式评估、计划部署如果有不同开关，给一张差异表，逐项写“值、原因、是否已验证”。权重SHA相同而包装不同，仍是两个不同运行时版本。

### 推荐的轻量目录（组织方式可调整）

```text
<policy-version>/
  README.md                    # 上面的一页能力/风险声明
  manifest.yaml                # 相对路径、来源run、SHA、状态
  SHA256SUMS.txt
  model/                       # 本次输出权重、部署模型和导出脚本
  source/                      # 训练当时源码/commit、启动命令、resolved配置
  runtime/                     # 观测、命令(如有)、动作包装、入口/退出、增益
  simulation/                  # 本策略使用的仿真资产、运行入口与现有结果
  replay/                      # 本策略代表性的逐帧输入/输出与比较脚本
```

目录不存在某项时，在 manifest 写 `not_applicable` 或 `not_run`。例如无速度命令的起身策略无需 `runtime/velocity_command.yaml`，没跑过 MuJoCo 不必造一个空的“MuJoCo通过”报告。想申请 **sim2sim 已通过** 状态时，才必须补第二仿真器的复跑材料与逐例结果；训练方若没有第二仿真器，可交足 C1–C8，由部署方负责完成第二仿真器并标明实际执行者。

## 3. 按策略能力启用的模块

下表的测试和文件**只在策略使用该功能，或README声称支持它时**才需要。没有相关能力就写 `not_applicable`，无需做实验。

| 触发条件 | 额外需交接的语义与证据 | 不适用的例子 |
|---|---|---|
| 有外部速度/方向命令 | 哪些 `vx/vy/wz` 真正使用，机体系/世界系、单位与符号，训练范围/命令采样分布、摇杆映射所需物理语义、死区/斜率/超时、零命令含义；对应方向/速度逐例跟踪结果 | 不接受运动指令的倒地起身 |
| 声称能松杆停车/驻停 | “零速请求”“刹轮”“轮角锁定”“固定站姿”的区别、制动距离/时间、停住后保持时长/漂移、失联时输出、停车状态初始化 | 仅执行定长起身动作 |
| 涉及站立/接管/策略切换 | 支持的起始姿态及误差、策略零速平衡/固定PD站的区别、首帧目标连续性、退出终点、是否可从运动中回站；给相应阶段时序 | 独立离线图像分类器 |
| 有轮速或轮角输出 | 轮半径/减速比、轮速单位、顺序与符号、角回绕、停车参考/里程计、轮地接触与四轮载荷证据 | 只控制腿而无轮的策略 |
| 有历史/相位/积分/动作包装 | 历史堆叠顺序、上一动作是raw还是**最终包装后**、启动填充、模式切换重置、补偿/滤波状态；给包含启动/切换的逐帧样本 | 完全无状态的单帧策略 |
| 起身/恢复 | 支持哪些倒地姿态及初始角速度，是否需要机体速度估计，起身成功和稳定保持的定义，失败后停止/重试语义；各姿态逐例证据 | 只在站立状态滚动 |
| 楼梯/复杂地形 | 台阶高度/深度/摩擦、盲走还是有地形感知、成功定义、允许的命令、失足/非轮接触与终点稳定性；训练/留出地形分开 | 仅平地站稳 |
| 接触/步态/高速能力 | 脚/轮离地与非轮接触口径、地面碰撞体、峰值与持续时间、偏航/横漂、力矩和目标变化；只按该策略声明的速度/步态域测试 | 慢速原地起身且不声明移动 |
| 多策略组合或原厂交接 | 每个策略的入口/出口合同、切换顺序、历史/轮角/相位如何重置、外层FSM所需的保持与超时条件 | 单一离线策略、无切换需求 |

**训练方提供的是策略/仿真的物理与接口假设，部署方负责现场硬件映射。** 训练方写清策略关节序、正方向、默认姿态和期望的 `q/dq/kp/kd/tau`；部署方用这台 AS2-W 的实测 `hardware_contract.md` 核 DDS 槽位、编码器零位、LowCmd/轮轴模式、控制权和急停。不能让训练方从 Go2、As2 等别的机型猜 AS2-W 槽位。某策略不使用所有16轴，也要写明其余轴由谁控制以及目标保持/失能语义。增益按**该策略及实际状态**记录；没有跨策略固定的55/2。

## 4. sim2sim 怎么验收，谁做什么

训练方至少提供其训练/正式评估仿真中**当前版本**能复跑的起点、资产、配置和代表性样例。部署方把同一权重、观测与最终动作包装接入第二仿真器；如果训练方已有两套仿真结果，就一并交出。两边先比**同一个输入帧的输出**，再比闭环；输出不一致时不要先用成功率讨论策略优劣。

1. **模型/运行时逐帧对齐**：checkpoint→导出模型的原始输出；训练参考实现→部署实现的包装后输出/最终目标；下一帧历史、相位、轮角参考是否相同。给最大误差、最差字段/帧和第一处分歧。误差阈值按本策略 dtype 和平台事先商定，不套用别的模型的1e-5。
2. **闭环同条件**：相同初始根姿态、相关关节 `q/dq`、命令/触发信号、包装内部状态、物理和控制步长；记录摩擦、执行器、质量/碰撞差异。可以先用理想仿真初态，再加部署方提供的实测初态。**只跑该策略有意义的场景**：起身就测目标倒地姿态，楼梯就测声明的楼梯，滚动就测声明的速度与停车。
3. **结果口径**：每个场景列种子/初态、通过数/总数、通过条件、失败条件、首次失败时间/原因、关键接触部件及峰值/持续时间（若涉及接触）、实际姿态/目标/速度/力矩时序。训练与部署两边的“成功”定义若不同，列出差异。视频可辅助看动作，但不能替代逐例数据。
4. **声明边界**：训练方没跑第二仿真器就写 `not_run`，部署方完成后补自己的报告；两个仿真器使用不同接触模型/初态时报告差异，不将独立诊断结果混作训练方正式验收。仿真没有的真实电机内环噪声/声音，也不能由“仿真平顺”推断真机无抖动。

阈值由**该能力**事前约定，写明依据和版本。例如平地滚动关心停车位移、轮载、稳态振荡；起身关心支持的倒地类型、起身时间、终点保持；楼梯关心通过率、失足和终点姿态。不能把某次复演器的 `0.18rad` 或 `50N` 当 AS2-W 官方通用门槛。凡是“只有跟踪成功，没有站稳/退出成功”，报告时必须分开写。

## 5. 进入真机前的交接边界

| 阶段 | 需要的材料与结果 | 缺项时怎么处理 |
|---|---|---|
| R0 收包 | C1–C8 与当前能力对应的按需模块、SHA一致、真实输出权重溯源正确 | 可阅读研究；不能宣称部署接口已对齐 |
| R1 离线对齐 | checkpoint/ONNX（若用）、包装/最终目标和历史逐帧一致 | 修接口/包装并升版；不发布电机命令 |
| R2 sim2sim | 所声明技能在第二仿真器的明确结果和失败记录 | 只列为未通过/未运行；可继续诊断，不扩大宣称范围 |
| R3 CPRO只读 | ARM64模型加载、输入范围、推理周期、预测目标与安全预检正确 | 修环境或合同；不能把 shadow 当作实机控制通过 |
| R4 有界实机 | 部署方按场地/姿态/急停/监测计划逐级测试，记录实际观感及保护流 | 失败即停，回传证据，再交修订版本 |

R2 未完全通过时，如果用户仍希望进行**某个明确范围的研发首测**，部署方需把未通过项、可能运动、短时上限、监测和退出写给现场人员，并取得**该次动作明确同意**；这只授权那一次受控实验，不等于模型可自由遥控。训练方不负责猜测 AS2-W 固件的 `ReleaseMode/SelectMode` 与 LowCmd 安全语义，但要写出策略对外层控制器的前提。现场日志由部署方保留并回传训练方，训练方据此交新版本而非在旧权重上悄悄改包装。

## 6. 交接记录模板

双方在 `handoff.md` 留一页即可，复杂数据放相对路径附件：

```yaml
policy_id: <版本>
skill_and_supported_cases: <实际声明>
selected_output_weight_sha256: <值>
initialization_weight_sha256: <值或not_applicable>
deployment_model_sha256: <值>
source_commit_or_snapshot: <值>
train_run_id: <值>
runtime_flags_actual: <文件相对路径>
observation_contract: <文件相对路径>
action_wrapper_and_gains: <文件相对路径>
entry_exit: <文件相对路径>
training_sim_replay: <文件相对路径>
second_sim: <结果路径或not_run；注明由谁补>
known_failures: <文件相对路径或none_with_scope>
not_applicable_modules: <模块及原因>
training_owner: <姓名>
deployment_owner: <姓名>
open_questions: <问题、责任人、预计答复>
```

`manifest`/`handoff` 不必照搬此文件名，但**每个实际用到的字段必须能找到值和源码**。若策略没有命令、没有站姿保持、没有轮，写清楚即可；不要求做相应的行走/停车/轮载实验。反过来，若 README 声称“支持摇杆前后滚动并能松杆停住”，就必须交该命令链与停车证据，不能只给一个站立视频。

## 7. 可以直接发给训练同事的话

> 请按《AS2-W 训练方→部署方交付清单 v3》交下一版策略。先在 README 说清它**实际支持的技能与范围**，再给该版本真实输出权重/部署模型、训练当时源码和解析后配置、逐字段观测、实际动作包装与增益、入口/退出条件、训练仿真资产和已跑过的逐例结果、几段可对齐的输入→最终目标回放。只需交与你这版策略有关的按需模块；不适用的行走、停车、楼梯或起身项写 `not_applicable`，未跑第二仿真器写 `not_run`。请区分本次输出权重与初始化旧权重，不要只给视频或训练服务器绝对路径。我会用这些材料完成 sim2sim，再按实际通过的范围规划真机验收。
