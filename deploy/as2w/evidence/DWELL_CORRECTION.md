# 🔴 重要更正：**长驻留一直存在（10 秒），我此前说「从未实现」是错的**

操作员此前两次收到我的说法：「`AS2W_AB_TURN_DWELL_*` 只打印未生效 → armB/armC/armD 的所谓长转从未真正发生，只能评价采样配比」。本轮实现长驻留时**核对了真实生效值，发现该说法需要更正**。

## 1. 真实生效值

`train_armE_support2p0.py` 里 **`resampling_time_range` 只有一处赋值**：

```python
cmd.class_type = RollingCommands
cmd.resampling_time_range = (10., 10.)     # 第 123 行，唯一一处
```

**→ 该赋值对 control / armA / armB / armC / armD 全部生效：每条指令**本来就保持 10 秒**。**

## 2. 所以错在哪、对在哪

| 我说过的 | 判定 |
| --- | --- |
| `AS2W_AB_TURN_DWELL_MIN_S/_MAX_S/_DWELL_S` **只被打印、从未被读取** | ✅ **正确**（全文件搜索确认它们只出现在 print 里） |
| 「armB/armC/armD 的**长转从未真正发生**」 | ❌ **错误**。驻留来自 `resampling_time_range=(10.,10.)`，**一直是 10 秒** |
| 「B/C/D 只能评价采样配比」 | ⚠️ **部分正确**：它们确实**只**在采样配比上与 armE 不同，**但那个差异是在「10 秒驻留」这一共同前提下取得的** |

**→ 正确表述应为：armB/C/D 与 armE 的唯一差异是采样配比，而所有臂的指令驻留都是固定的 10 秒。****→ 我此前「长驻留这个假设在 B/C/D 中根本没被测试」的说法是错的：它在 10 秒固定值上一直被测试。**

## 3. 这对「长驻留是否有独立效果」的含义

**所有臂驻留都是 10 秒 ⇒ 无法用已有臂之间的比较来判断「驻留时长本身」的效果。**要测它，必须做一个**只有驻留时长不同**的对照，例如 10 秒 vs 2.5 秒，其余完全相同。

**→ 操作员要求的「只有驻留时长不同的短对照」正是唯一能回答这个问题的实验，此前没有做过。**

## 4. 本轮实现的东西

`training/as2w_long_dwell_curriculum.py` —— 新类 `LongDwellCommands`，在父类行为之上加三件事：

| 能力 | 实现 |
| --- | --- |
| **8–12 s 随机驻留** | 每个长样本 `time_left` 设为 U(8,12) 秒 |
| **按类别分比例** | 纯转的 37.5%（= 全体 15 pp）与弧线的 40%（= 全体 10 pp）标记为长 |
| **事件日志证明生效** | `LONG_TURN_START` / `LONG_TURN_END`（含实际时长、是否完成）/ `LONG_TURN_SUMMARY` |
| 统计 | `started/completed/truncated`、`mean_actual_dwell_s`、`actual_turning_step_share` |

**短样本的关键修正**：非长样本必须重置为**父类节奏的新值**，否则一个「上一轮是长」的环境会把短指令也保持 8–12 秒。**这个 bug 是自检抓出来的**（见下节第 3 项），已修。
