# 第 2 项：两个安全口径的确认 —— **`1.11×90%` 是我的分母算错了**

## 1. 轮端力矩口径：合同写的是「已验证上限的 90%」

`runtime/deploy.yaml` 第 87 行原文：

```yaml
torque_limits_nm:            # 90% of the verified hardware limit, includes PD + feedforward
  hip: 54.0
  thigh: 54.0
  calf: 81.0
  wheel: 13.5
```

**→ `13.5 N·m` 这个数字本身就是「90% 值」，不是 100% 值。** 反推已验证硬件上限：

| 轴 | 合同写的 90% 值 | 反推硬件上限 | 校验 |
| --- | --- | --- | --- |
| hip | 54.0 | **60.0** | 60.0 × 0.9 = 54.00 ✅ |
| thigh | 54.0 | **60.0** | 60.0 × 0.9 = 54.00 ✅ |
| calf | 81.0 | **90.0** | 90.0 × 0.9 = 81.00 ✅ |
| wheel | 13.5 | **15.0** | 15.0 × 0.9 = 13.50 ✅ |

**四个轴完全自洽**（60/60/90/15 × 0.9 = 54/54/81/13.5）→ **已验证硬件上限是 15 N·m（轮），13.5 就是 90% 边界。**

## 2. 🔴 我的 `1.11×90%` 是**分母重复打折**的错误

我的评测脚本里写的是：

```python
LIMIT = {"hip": 54.0, "thigh": 54.0, "calf": 81.0, "foot": 13.5}
... tau_frac_90 = tau_peak / (0.9 * LIMIT["foot"])   # = tau / (0.9 * 13.5) = tau / 12.15
```

**`13.5` 已经是 90% 值，我又乘了一次 0.9 → 分母变成 12.15。** 于是「施加到 13.5」被算成 13.5/12.15 = **1.11**。

**正确口径：**

| 量 | 正确值 | 我之前报的 |
| --- | --- | --- |
| 已施加轮力矩峰值 | **13.5 N·m** | 13.5 N·m |
| 相对**90% 预算**（13.5） | **1.00 —— 正好在 90% 边界，未超** | ~~1.11~~ |
| 相对**硬件上限**（15） | 0.90 | — |

### 结论（更正）

**「`1.11×90%`」这个说法作废。** 实际情况是：
- 施加值 **13.5 N·m = 声明的 90% 预算的 100%**，即**恰好用满 90% 预算，没有超出**
- 相对硬件上限 15 N·m 是 **90%**
- **不是「超过预算 11%」**

**但仍有实质问题值得保留**：施加值**持续顶到** 90% 预算上限（限幅生效），说明该瞬态确实在预算边界工作；按 goal「每轴控制在已验证可用力矩上限的 90% 内」，**恰好等于 90% 是合规的**，但没有余量。

### 两端分母已统一

**统一口径：分母一律用 `deploy.yaml` 的 `torque_limits_nm`（即 90% 值 54/54/81/13.5），比值 ≤1.00 即合规。**MuJoCo 与 Isaac 两侧都按这个分母报告，不再乘第二次 0.9。

## 3. 膝部 3.2 mm 是「实际离地」，不是「距门槛余量」

脚本实现（`r11_mj_bias_regression.py` 第 168–174 行）：

```python
p = d.xpos[b].copy()                                   # 膝/小腿 body 原点
numpy_ray = mujoco.mj_ray(m, d, p, (0,0,-1), ...)       # 从该点向地面打射线
dist = ...                                             # 该点到地面的垂直距离
```

**→ `0.0032 m` 是「膝/小腿 body 原点到地面的实际垂直距离」，单位米，不是某个门槛的剩余百分比。**

### 但有两个必须说明的限制

1. **测的是 body 原点这个「点」，不是连杆几何的最低表面。** 若连杆几何延伸到原点下方，   **真实净空会小于 3.2 mm**。3.2 mm 应视为**上界估计**。2. 该值是**整段运行时窗内的最小值**（逐帧取 min），不是某一帧快照。

### 对「摆腿是否具备试验条件」的影响

| 问题 | 回答 |
| --- | --- |
| 3.2 mm 是实际离地吗 | **是**（body 原点到地面），但**是上界**（未含几何外廓） |
| 摆腿时净空会变小吗 | **会** —— 抬前腿时后腿承重增加，后膝会**更贴地**；抬后腿时前膝承重增加 |
| 3.2 mm 够不够试摆腿 | **不足以保证** —— 余量只有毫米级，且摆腿会重新分配载荷 |

**→ 建议：把「净空」改为测**连杆几何最低点**到地面的距离（而非 body 原点），并同时报告**几何最低点**与**原点**两个数，否则 3.2 mm 无法判断是否真的会碰地。**
