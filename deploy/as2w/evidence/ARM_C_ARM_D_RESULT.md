## 2. 三条可支持的因果判断

**(a) 转向曝光下降会压垮弧线。** armC 把曝光从 65% 砍到 25% 后，右弧 0.76 → 0.58 跌破门槛、左弧 0.71；恢复曝光后左右弧同时回到 0.83 / 0.76。**→ 曝光是弧线能力的必要条件。**

**(b) 配比不是纯转的解。** armD 的曝光与对照相同，但四项纯转仍在 0.02–0.35，**比对照的 0.18–0.39 还差**。**→ 纯转缺的不是曝光。**

**(c) 训练量不是纯转的解。** armD 从 1k 练到 6.6k，四项纯转没有一项改善（turn_left_0.10 0.35 → 0.30 反而略降）。**→ 纯转不是「训练量不足」。**

## 3. 未解释的现象：右向不对称在加深

| 检查点 | arc_left | arc_right |
| --- | --- | --- |
| armD@1k | 0.83 | 0.76 |
| armD@6.6k | **0.93** | **0.17** |

**→ 同一权重、同一协议，左右弧在 5,600 轮内分裂到 0.93 / 0.17。**这是**结构性左右不对称**，不是采样波动。goal 提示的「策略对角分量约为左右差速 2.57×」与「右向不对称」正是下一项应查的方向。

## 4. 🔴 重大缺陷：所谓「长转」从未实现

`code/as2w_ab_curriculum.py` 中 `AS2W_AB_TURN_DWELL_MIN_S / _MAX_S / _DWELL_S`**只出现在一行启动打印里，没有任何代码读取它们**。
**→ armB 与 armC 的「长转课程」从未产生长驻留转向，唯一真实变化是类别配比。****→ 本交付包中的 armD 同样是纯配比实验，不含长转。**

## 5. 遥测缺陷

验收脚本的 `tau_max` 与 `ff_max` 在**全部用例**恒为 `0.00`，而机器人明显在动（直行跟踪 0.87）—— **这是零读数缺陷，不是真零**。**力矩余量项因此标 `not_measured`。**
## 6. 边界

1. 全部为 Isaac 侧结果；armD 权重的 **MuJoCo 正式矩阵未跑**（`not_run`）
2. armC/armD 均为**单次**训练，非多次重复
3. 种子 311 的 armD@6.6k 结果在评测收尾阶段取得，未纳入本表的逐例明细
4. 曝光比例是**类别占比**，与「实际轮差步数占比」不完全等价
