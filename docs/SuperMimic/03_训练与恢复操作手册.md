# 训练与恢复操作手册

## 1. 先明确训练目标

当前优先级：平地速度指令行走 → 盲越障/楼梯。追球、跟随、钻杆及旧空翻训练已暂停，不应被恢复脚本自动重启。平地任务不是楼梯任务；不能把 `--task` 改名后就认为已接入楼梯。

本章的正式命令复现**历史 v1**：未启用 reset-hold 修复。它用于复现基线，不建议在已有 model_12000 的原服务器重复运行。当前下一步是诊断并修复接地和目标连续性，再做有依据的新实验，不是无条件再跑 12000 轮。

## 2. 检查已有进程，避免重复训练

```bash
cd "$SUPERMIMIC_HOME"
pgrep -af 'train_velocity.py|eval_velocity.py|velocity_.*queue'
nvidia-smi
find logs/supermimic -name 'model_*.pt' -printf '%T@ %p\n' | sort -n | tail
```

进程 PID 会随重启改变，不能根据旧 PID 杀进程。先核对命令、工作目录、日志和检查点时间。SSH 断线不等于训练退出；不要仅因网页不可访问就再启动一份。

## 3. 先跑 32 环境、12 轮烟测

```bash
cd "$SUPERMIMIC_HOME"
mkdir -p reproduction/velocity
export MUJOCO_GL=egl
"$VENV/bin/python" -u scripts/train_velocity.py \
  --task Go2-Velocity-Blind-Flat \
  --num-envs 32 --iterations 12 --warmup-iterations 2 --buffer-len 40 --imag-batch 32 \
  --seed 32001 --log-interval 1 --save-interval 12 \
  --run-name velocity_flat_smoke_reproduction \
  > reproduction/velocity/smoke.log 2>&1
tail -n 30 reproduction/velocity/smoke.log
find logs/supermimic -path '*velocity_flat_smoke_reproduction/velocity_audit.json' -exec cat {} \;
```

烟测检查：程序正常结束，保存 checkpoint；world model、actor、critic 均发生更新；实际合约 task 正确、actor 350 维；`velocity_audit.json` 的奖励误差小于 1e-5，命令和历史填充通道全零。本烟测显式把 warmup 从正式 300 缩短到 2，以便 12 轮覆盖策略更新；这是链路检查，不能冒充正式参数，也不能据此判断行走效果。

`training_completed=true` 只代表运行完成。审计保留 `capability_qualified=false`，不得手改为 true。

## 4. 历史正式训练参数与启动

在没有其他训练占用且决定复现基线时执行：

```bash
cd "$SUPERMIMIC_HOME"
RUN=velocity_blind_flat_v1_reproduction
mkdir -p reproduction/velocity
nohup "$VENV/bin/python" -u scripts/train_velocity.py \
  --task Go2-Velocity-Blind-Flat \
  --num-envs 4096 --iterations 12000 --buffer-len 400 --imag-batch 4096 \
  --seed 32011 --log-interval 50 --save-interval 500 \
  --run-name "$RUN" \
  > "reproduction/velocity/$RUN.log" 2>&1 < /dev/null &
echo $! > "reproduction/velocity/$RUN.pid"
```

查看状态：

```bash
tail -n 40 "reproduction/velocity/$RUN.log"
ps -fp "$(cat "reproduction/velocity/$RUN.pid")"
nvidia-smi
```

| 参数 | 历史值 | 作用 |
| --- | ---: | --- |
| num-envs | 4096 | 真实并行环境数量 |
| iterations | 12000 | 训练外循环总轮数，不是 PPO update 数 |
| collect-steps | 1 | 每轮真实采样步数 |
| buffer-len | 400 | 每环境回放长度；减少可降低显存但改变训练 |
| wm-window | 8 | 世界模型自回归拟合长度 |
| wm-batch / wm-updates | 2048 / 2 | 每轮模型更新配置 |
| imag-batch / horizon | 4096 / 32 | 想象批量与展开步数 |
| warmup-iterations | 300 | 模型先拟合，再开始正常策略更新 |
| lr | 0.0002 | 优化器基础学习率，另有退火/actor ramp |
| actor-hidden | 512 256 128 | Actor 隐藏层，ELU |
| wm-hidden | 1024 1024 1024 | 世界模型隐藏层 |
| save-interval | 500 | 检查点间隔 |
| seed | 32011 | 训练随机种子；独立评估使用其他种子 |

完整参数及默认值保存在 `evidence/config/velocity_contract.json`，并可用 `scripts/train_velocity.py --help` 查看。bool 参数使用 `--compile true` 等形式，不要写成没有值的开关。

L40 历史执行耗时和显存不是新服务器保证。模型更快跑完不等于通过；GPU 空闲也不应触发无依据的并发长训。

## 5. 训练产物与可信恢复

每次 run 写入新的时间戳目录：

```text
logs/supermimic/<时间戳>_<run_name>/
  model_500.pt ... model_12000.pt
  velocity_contract.json
  velocity_audit.json
  events.out.tfevents...
```

完整 checkpoint 包含 actor、critic、世界模型和已保存的优化器状态。原项目发布的 `flat.pt/obstacles.pt/terrain.pt` 是 actor-only 权重，不能当作完整训练续训文件。

恢复前验证文件存在且可加载：

```bash
export RESUME="$ROB2NAV/skills/supermimic/checkpoints/velocity_blind_flat_v1_model_12000.pt"
sha256sum "$RESUME"
"$VENV/bin/python" -c 'import os,torch; c=torch.load(os.environ["RESUME"],map_location="cpu",weights_only=False); print(c.keys()); assert all(k in c for k in ("actor","critic","world_model"))'
```

仅在已明确需要新实验时，以下展示如何把总轮数继续到 12200，不是当前必须执行的任务：

```bash
cd "$SUPERMIMIC_HOME"
"$VENV/bin/python" -u scripts/train_velocity.py \
  --task Go2-Velocity-Blind-Flat --num-envs 4096 \
  --iterations 12200 --buffer-len 400 --imag-batch 4096 \
  --resume "$RESUME" --continue-run true \
  --seed 32012 --log-interval 50 --save-interval 100 \
  --run-name velocity_resume_example
```

`continue-run=true` 让 iteration、课程与学习率沿用原计数，`iterations` 是最终总轮数；false 则按新任务计数重新开始。新环境、回放缓冲和部分采样状态会重建，不是逐位精确续训。改变奖励后需考虑 `--reset-critic true` 和相应 warmup，先烟测；不能把加载成功当作奖励适配正确。

## 6. reset-hold 修复如何用于下一轮训练

本次提供的历史训练 wrapper 保留原执行方式，**没有训练 CLI 的 `--initialize-hold-targets` 开关**；该开关目前用于评估。不要把评估开关传入训练器，也不要声称历史训练已使用修复。

下一轮训练适配应在 Trainer 创建环境之前给训练 env cfg 安装 `rob2nav_reset_targets.install(cfg)`，并把是否启用、模块哈希、实际事件配置写入 `velocity_contract.json`。必须先验证 registry 返回的训练配置确实包含该 reset 事件，再做小规模训练；不能仅修改 `flat_cfg()` 后忽略注册时已经生成的 cfg。历史版本保留不覆盖，新实验独立目录。

## 7. 如何认定训练“完成”

完整检查点、末态审计和日志正常退出是执行完成证据。随后必须进行独立种子物理评估、接触检查、原速录像和控制部署合约检查。当前网页 Jobs 尚未纳入本架构，网页没有任务卡不等于训练没有运行；以此独立目录的进程、日志和产物为准。
