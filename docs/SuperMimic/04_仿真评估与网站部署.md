# 仿真评估与网站部署

## 1. 加载现有模型，不必重新训练

安装章节的变量仍需有效：

```bash
cd "$SUPERMIMIC_HOME"
export CHECKPOINT="$ROB2NAV/skills/supermimic/checkpoints/velocity_blind_flat_v1_model_12000.pt"
mkdir -p reproduction/velocity
```

当前模型只能按本任务合约加载：350 维 actor、5 帧历史、逐关节动作尺度。不要放入旧空翻或 MoE 加载器直接调用。

## 2. 八阶段完整评估

先用 2 环境短测确认运行，再运行 128 环境完整测试：

```bash
"$VENV/bin/python" scripts/eval_velocity.py \
  --checkpoint "$CHECKPOINT" --seed 32200 --num-envs 2 --stage-seconds 2 \
  --initialize-hold-targets --audit-body-contact \
  --output reproduction/velocity/body_smoke.json
```

四个独立种子逐个执行，避免重复启动：

```bash
for seed in 32120 32121 32122 32123; do
  "$VENV/bin/python" scripts/eval_velocity.py \
    --checkpoint "$CHECKPOINT" --seed "$seed" --num-envs 128 --stage-seconds 10 \
    --initialize-hold-targets --audit-body-contact \
    --output "reproduction/velocity/full_${seed}.json" \
    > "reproduction/velocity/full_${seed}.log" 2>&1 || break
done
```

这条命令**新增了原 hold 四种子报告没有的接触检查**，得到的是新的完整报告，不应与旧报告混用。预计存在失败项，不能为了生成绿色结果关闭检查。

阶段依次为：站立、前进 0.6m/s、后退 −0.3m/s、左右侧移 ±0.25m/s、左右转向 ±0.6rad/s、停止，每段 10 秒，总计 80 秒。每报告必须有 16000 个物理回调样本；每个样本覆盖全部并行环境。

跟踪 RMSE 忽略每阶段起始的 settling 区间，**关节/接触检查不忽略任何入口或命令切换样本**。目标变化率来自相邻原始目标关节角，不是实际关节速度，两者必须分别记录。

检查字段：`falls_total=0`、`max_joint_limit_excess_rad=0`、实测速度比与力矩比不超过 1、原始目标变化率比不超过 1、无非足触地、采样数准确；速度跟踪阈值需在新实验前固定，不能看结果后调整。报告保留 `capability_qualified=false`，最终人工审阅和完整条件尚未做成自动资格证书。

接触检查直接读 Warp 活跃 contact 缓冲，排除命名足底、机器人自碰与无效槽位，只记录真实地面接触。当前烟测检测到了 calf 几何碰地。还需要检查接触点和力，排除几何命名导致的保守误判；不能把整个 calf 都改为足底来消除失败。

## 3. 初始化超速对照复现

```bash
cd "$SUPERMIMIC_HOME"
export DIAG_CHECKPOINT="$CHECKPOINT"
DIAG_SEED=32024 DIAG_ENVS=4 DIAG_OUT=reproduction/velocity/entry_baseline \
  "$VENV/bin/python" scripts/diagnose_velocity_entry.py
INIT_TARGET_HOLD=1 DIAG_SEED=32024 DIAG_ENVS=4 \
  DIAG_OUT=reproduction/velocity/entry_hold \
  "$VENV/bin/python" scripts/diagnose_velocity_entry.py
cat reproduction/velocity/entry_baseline/summary.json
cat reproduction/velocity/entry_hold/summary.json
```

脚本分别运行 policy 和零动作，输出初始状态、每子步状态和峰值；对照初态必须相同。不要用不同 seed 的低峰值代替失败 seed 的修复验证。

## 4. 录制新视频

```bash
cd "$SUPERMIMIC_HOME"
export MUJOCO_GL=egl
"$VENV/bin/python" scripts/video_velocity_latest.py \
  --checkpoint "$CHECKPOINT" --seed 32130 --stage-seconds 4 \
  --output-dir reproduction/velocity/video_latest
```

输出 MP4、元数据和轨迹。默认 8×4 秒、25fps、800 帧，是原速视频。录像显式安装 reset-hold；页面和元数据必须注明“历史权重 + 控制初始化修复”。该短视频不能替代 128 环境四种子测试，也不能证明未实现的楼梯能力。

制作浏览器兼容副本和封面：

```bash
cd "$SUPERMIMIC_HOME/reproduction/velocity/video_latest"
ffmpeg -y -i velocity_model12000_hold.mp4 -c:v libvpx-vp9 -crf 32 -b:v 0 -an velocity_model12000_hold.webm
ffmpeg -y -i velocity_model12000_hold.mp4 -frames:v 1 velocity_model12000_hold.jpg
```

若浏览器不支持原 MP4 编码，可先用 `ffmpeg -c:v libx264 -pix_fmt yuv420p -movflags +faststart` 转为另一个文件后检查；不要在输入输出路径相同时执行。

## 5. 集成 Rob2Nav 视频页面

本次仓库自带已发布的最终视频及独立页面源文件。复制该页面到网站静态目录并构建：

```bash
cp "$ROB2NAV/skills/supermimic/resources/supermimic.html" \
   "$ROB2NAV/studio/frontend/public/supermimic.html"
cd "$ROB2NAV/studio/frontend"
npm ci
npm run build
```

Node 使用项目要求的版本（服务器实测 v22.14.0）。训练 Python 环境不负责 Node 构建。原网站已有视频概览组件可继续保留；本页面独立工作，不覆盖其他人的概览和扩展代码。

新录像上传时复制生成的四个文件到 `$ROB2NAV/artifacts/supermimic/`，更新页面的文件名、模型轮数、限制说明和元数据。已归档录像不要覆盖成另一模型却保留旧标题。

Rob2Nav 后端 `/api/files/artifacts/...` 必须允许 `.webm`、`.mp4`、`.jpg`、`.json`；若旧版本安全扩展名列表缺少 `.webm`，只补这个后缀，不开放任意路径。视频需要 Range 响应以支持拖动。

启动网站使用仓库已有启动方式；现有服务器受 supervisor 管理，修改静态资源后构建、只重启 studio，不能重启训练。不要将原服务器 supervisor 的绝对配置路径作为新服务器安装前提。

## 6. 从自己电脑访问服务器

在自己电脑另开终端，保持 SSH 隧道运行：

```bash
ssh -N -L 8766:127.0.0.1:8765 -p SSH端口 用户名@服务器地址
```

浏览器访问 `http://127.0.0.1:8766/supermimic.html`。这里的 127.0.0.1 是自己的电脑；没有隧道时它不会自动指向远程服务器。

在服务器检查后端，在电脑检查隧道，两边分别运行：

```bash
# 服务器
curl -I http://127.0.0.1:8765/
curl -H 'Range: bytes=0-1023' -D - -o /dev/null \
  http://127.0.0.1:8765/api/files/artifacts/supermimic/velocity_model12000_hold.mp4
# 自己电脑（需要 curl）
curl -I http://127.0.0.1:8766/supermimic.html
```

视频范围请求预期 206；若首页正常、视频 404，检查文件和 API 后缀；若拒绝连接，先检查网站进程及隧道；若页面加载慢，保留已有 jobs/catalog 避免重复扫描 TensorBoard 的修复。不要通过反复刷新或重训解决网络问题。

## 7. 实机边界

当前没有 SuperMimic 的 Go2 EDU 实机部署完成证据，也没有盲楼梯资格。实机适配还需导出 actor+归一化、映射 SDK 关节顺序、匹配增益/动作尺度/延迟、5 帧历史与初始化、坐标系和命令单位、失联/停止行为，并做 MuJoCo 与运行时同输入数值对照。不能将这里的 `torch.load` 仿真脚本直接当作实机底层控制程序。
