# 网站部署与迁移

## 1. 目标与适用范围

将网站运行在你自己的机器上，不依赖原服务器。Web资料浏览可用Windows或Linux；GPU训练和本文Bash仿真步骤面向Linux。先完成[环境准备与路径约定](环境准备与路径约定.md)，其中有克隆、Python/Node环境、构建、变量和Windows命令。

仓库已有精选模型、配置、轨迹和视频；不需要先下载全量历史训练、旧数据库或恢复旧PID。新任务队列不会自动续训。外部源码按技能手册另行准备。

## 2. 准备环境并构建

尚未克隆时，先按环境准备第1节操作。已经在仓库里，不要再次clone到自身目录。每个新终端从仓库根目录开始：

```bash
source scripts/docs_env.sh
python3.11 -m venv "$ROB2NAV_ENVS/rob2nav-studio"
"$WEB_PY" -m pip install -r studio/requirements.txt
cd studio/frontend
npm ci
npm run build
cd "$ROB2NAV_ROOT"
"$WEB_PY" scripts/deployment_check.py --mode web
```

预期预检输出`missing: []`。提示前端缺失时检查构建是否真正成功；模型校验失败时检查Git资源，不跳过哈希检查。

## 3. 启动网站与选择解释器

只浏览资料时，在前台终端执行并保持终端运行：

```bash
"$WEB_PY" -m studio.api --root "$ROB2NAV_ROOT" --port 8765
```

浏览`http://127.0.0.1:8765/`。另开终端执行`curl -fsS http://127.0.0.1:8765/api/health`，确认`ok: true`。`mujoco_available: false`表示尚未配置CPU物理环境；`simulator_available: false`表示尚未配置Isaac入口。

要运行网页单技能仿真，先完成环境准备的CPU步骤，再关闭旧Web并重启：

```bash
source scripts/docs_env.sh
test -x "$CPU_PY"
"$WEB_PY" -m studio.api --root "$ROB2NAV_ROOT" --port 8765 --mujoco-python "$CPU_PY"
```

需要显式提交真实训练时，先安装Isaac，关闭旧Web后再运行：

```bash
source scripts/docs_env.sh
test -x "$ISAAC_PY" && test -x "$CPU_PY"
"$WEB_PY" -m studio.api --root "$ROB2NAV_ROOT" --port 8765 \
  --sim-python "$ISAAC_PY" --mujoco-python "$CPU_PY" --allow-training
```

开关只允许显式提交任务；提交后才由独立worker执行。它不使未实现的适配器变成可训练，也不恢复旧任务。端口占用时先核对已有实例，不重复启动。

## 4. 运行物理仿真服务

单技能仿真由网站按需启动独立CPU进程。导航与虚拟手服务需要单独启动，每个新终端先source环境：

| 功能 | 进程 | 端口 | 操作手册 |
|---|---|---:|---|
| PPO导航 | `skills.navigation.live` | 8768 | [PPO仿真](../skills/navigation/仿真手册.md) |
| SCAN导航 | ROS桥与`skills.navigation.live --planner scan` | 8769，内部UDP 8771 | [SCAN仿真](../skills/navigation/SCAN仿真手册.md) |
| 虚拟手托爪 | `go2_nav.paw_contact.server` | 8767 | [托爪仿真](../go2_nav/paw_contact/虚拟手托爪仿真与部署手册.md) |

资料页面可用但物理worker未启动时，画面入口会提示不可用。每种服务只保留一个实例，按Ctrl+C关闭对应前台实例。打开网站不等于物理引擎或GPU训练已启动。

## 5. 远程访问与长期运行

远端服务仍绑定loopback。在操作者电脑设置自己的SSH_HOST、SSH_USER、SSH_PORT，再建立隧道：

```bash
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -L 127.0.0.1:8766:127.0.0.1:8765 \
  -p "${SSH_PORT:?请设置SSH_PORT}" "${SSH_USER:?请设置SSH_USER}@${SSH_HOST:?请设置SSH_HOST}"
```

浏览`http://127.0.0.1:8766/`。8766是本机隧道端口，8765是远端Web端口。相同隧道已存在时不重复绑定，不把密码写入文档或脚本。

长期运行可将已验证命令放进自己的tmux/systemd服务。[systemd示例](https://github.com/YuTaoV5/Rob2Nav/blob/main/deployment/rob2nav-studio.service)的User、WorkingDirectory、解释器按本机修改，它不是原服务器Supervisor恢复脚本。不要执行旧command.json或导入队列后直接重放任务。

## 6. 验收与排错

确认首页、中文手册、旧文档书签、实际模型和录像可用。实时仿真再按对应手册验收动力学与哈希。网站安装校验不代表重跑全部训练，也不代表实机合格。

```bash
"$WEB_PY" -m pip install pytest httpx
"$WEB_PY" -m pytest studio/tests/test_documents.py studio/tests/test_registry.py -q
python3 scripts/check_documentation.py
```

| 现象 | 检查 |
|---|---|
| 空白页或资源404 | 前端构建、仓库根目录、Web日志 |
| 远程页面连不上 | SSH隧道、端口映射和服务进程 |
| 物理画面不可用 | 对应worker、CPU解释器和EGL |
| 缺模型或源码 | 实际文件、完整Git资源、固定提交 |
| 训练导入失败 | 是否误用CPU环境，Isaac是否实际安装 |
| unknown或中断任务 | 保存的process.json与真实PID，不能凭超时盲目重启 |

数据和条款见[模型与数据目录](模型与数据目录.md)、[第三方说明](../THIRD_PARTY_NOTICES.md)。
