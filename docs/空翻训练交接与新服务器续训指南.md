# 空翻训练交接与新服务器续训指南

本文件是下一位 agent 的入口。范围只有 Go2 前、后、左、右空翻：全程连续无突变、准备段无抽动、动作前后标准四足站立（FIXSTAND）、完成正确方向的一圈并稳定热切换。不要恢复已取消的直立或踏步训练。

这是 2026-10-23 的可恢复快照，不是四技能均已达标的声明。接手时必须重新读取进程、网页任务和实际日志；下表进度与 PID 都会变化。

## 3. 新服务器从零准备

使用Linux GPU主机。按[环境准备与路径约定](环境准备与路径约定.md)安装已记录的环境组合：Isaac Sim 5.1、Isaac Lab 2.3.2、RSL-RL 3.1.2；Web和CPU MuJoCo分别建环境。历史freeze用于核对，不要把旧机器整个环境跨机器覆盖安装。

```bash
git clone https://github.com/YuTaoV5/Rob2Nav.git
cd Rob2Nav
# 覆盖为新机器实际安装位置；不要照抄旧服务器路径
export ISAAC_PY="$HOME/isaacsim/python.sh"
source scripts/docs_env.sh
export PACK="$ROB2NAV_ROOT/artifacts/空翻续训交接_20261023"
python3 scripts/acrobatics_handoff.py --verify
```

校验应显示全部资源通过，且 `training_submitted: false`。模型已随Git提供，不依赖旧outputs目录。校验报错先检查下载和Git行尾，不能更新清单掩盖缺失；只有有意更新交接资源时才运行 `prepare_acrobatics_handoff.py` 重新构建清单。

## 4. 新服务器执行顺序与明确门槛

先做小烟测，再排有依据的正式任务。每份JSON都可继续编辑，网页字段与命令行参数来自同一schema。不要一次把7份全部提交，避免尚未通过的门槛被跳过。

```bash
# 只预检，不创建任务、不训练
"$CPU_PY" scripts/acrobatics_handoff.py \
  --config "$PACK/新服务器任务配置/04_关节增益配置烟测.json"

# 确认环境和配置正确后，显式提交同一份配置
"$CPU_PY" scripts/acrobatics_handoff.py \
  --config "$PACK/新服务器任务配置/04_关节增益配置烟测.json" --submit
```

工具走网页同一预检/保存/提交接口，打印任务ID。默认没有副作用；`--submit`才排队。同名同配置任务会复用；同名不同配置会报错；创建响应不明确时不会盲目重试。脚本不替你判断动作合格或自动跳过下列门槛。

## 5. 验收不能缩减

独立四种子均须满足：正确方向完整一圈、首尾FIXSTAND、准备段目标步长≤0.08rad/实测关节速度≤3rad/s/机身角速度≤1rad/s、无不允许的身体接地、每个物理步URDF速度和关节限位通过。新侧翻评估还要求全程相邻目标变化率/URDF速度≤1；目标变化率与实测速度不同，两者都要检查。首帧无前一条记录的入口衔接必须由统一热切换另验。

确认evaluation.json的四个episode及status，不只看进程退出码。之后复看原速未剪辑录像，再做stand→walk_moe→技能→walk_moe→stand、多朝向、多次重复的统一MuJoCo验证。后翻保持action_clip=8、真实入口合约、逐关节电机曲线、SDK顺序动作历史。Go2 EDU实机资格必须另验，仿真通过不代表硬件已稳定。

保留实际配置、完整父/候选权重、SHA、四种子summary与诊断、至少一段原速录像、热切换证据。不要只改网站文案；未通过的技能继续标研究候选。

## 6. 目前证据支持的优化顺序

1. Kd2虽降速却只翻半圈，不做该条件长训。Kd1.2单种子保留整圈、降低超速和越限，仍未通过，所以只做200次有界探索。
2. 原侧翻在2.78秒有1.345rad目标单帧突变；调阻尼未消除。已接通 `target_rate_weight` / `target_rate_margin`，先核验烟测，再据阻尼对照结果设计奖励续训，暂不同时混入多个未验证改动。
3. 直接将末段髋渐收50改0使末姿误差变差，不能作为现成修复。
4. 原参考腾空COM加速度残差明显大于真实物理采样误差；这提示物理一致性偏差，不是完整不可行性证明。不要盲目强化原参考跟踪；需要改参考时保留原数据、产生新hash、先验运动学与动力学，再经网页motion参数提交。
5. 前翻先看增强起跳奖励是否实际产生腾空，再决定奖励/初始化；不要把无腾空的600次原条件训练继续加长。不得倒放后翻视频冒充前翻。

完整失败机制和原始证据见[四向空翻迭代记录](四向空翻迭代与网页验收说明.md)。接手后按结果更新本文件和项目交接记录，再上传必要资源。已有每15分钟汇报监控属于原聊天；换聊天不会自动迁移监控，需在新会话重新授权设置，避免两个agent同时控制同一任务。

## 7. 可直接交给下一位 agent 的提示词

> 继续 Rob2Nav 前后左右空翻。先完整阅读 docs/空翻训练交接与新服务器续训指南.md、项目交接记录.md末尾与 docs/四向空翻迭代与网页验收说明.md。运行 python3 scripts/acrobatics_handoff.py --verify。若接管原服务器，先核对真实任务、进程和条件脚本，不重复创建训练或预留种子评估；若换服务器，用交接包的7份便携配置和新种子，通过网页同一API预检/提交，先完成实际YAML烟测再按门槛排正式训练。不要执行绑定旧任务ID/旧解释器的条件脚本。四技能目标是完整正确方向、全程无突变、准备无抽动、首尾FIXSTAND、无身体接地、逐物理步URDF速度/限位合规，并有独立四种子、原速录像与统一热切换证据。当前只有后翻达到限定仿真水平，原速连续复看和实机资格未完成。其余模型不能晋级。已有代码检查通过不能代替动作通过。保留实际配置、必要完整检查点与证据并及时推GitHub；原服务器训练保持运行，除非所有者明确要求迁移停机。每15分钟汇报真实进展；新聊天需重新设置其监控。
