# Rob2Nav 项目上传守则

| 材料 | 放置位置 |
| --- | --- |
| 技能入口和正式配方 | 现有 `skills/` 对应技能目录 |
| 可复现训练源码、解析配置、初始化来源和资产索引 | 现有 `training/as2w-backup/` 对应目录 |
| AS2-W 研究权重、同权重 ONNX 和诊断证据 | `training/as2w-backup/as2w-current/runs/<skill>/<run>/`。交付证据使用该 run 下的 `v3-evidence/` |
| 评测框架和正式评测入口 | 现有 `rob2nav/` 或对应技能评测目录 |
| 通用部署代码和版本化交付包 | `deployment/` 与 `deliveries/as2w-deploy/` 各自已有位置 |
| 研究分析、历史产物和工作台 | 分别沿用 `research/`、`artifacts/` 和 `studio/` |

1. 上传前以远端 main 为基线，先读 [项目层级](LAYERS.md)。滚动、踏步和恢复各用既有技能目录。保留脚本引用的相对路径，新增文件前先找现有入口。
2. 逐项暂存，审阅 `git diff --cached --name-status` 与文件大小。校验预期路径、关联文档与调用入口。移动、删除、根目录新增和跨模块修改需要有对应任务依据。
3. 仅选有复现或验收价值的检查点、报告、短回放与视频。原始大日志、缓存、全量中间权重、账号凭据和未获发布授权的实机日志留在仓库外。外部大文件记录固定版本、获取地址、字节大小和 SHA-256。
4. AS2-W 逐候选执行 [v3 交付清单](../../training/as2w-backup/as2w-current/AS2-W-training-delivery-checklist-v3.md)。记录输出权重、初始化、源码、解析配置、ONNX、运行时合同和证据的对应关系。相同权重更换包装须升版。缺项写 `not_run` 或 `not_applicable` 并说明原因。研究归档按实际结果标明通过范围。
5. 提交后正常快进推送，核对远端分支、提交哈希和新增路径。目录索引记录的是快照，有新增交付时更新对应入口或候选清单。
