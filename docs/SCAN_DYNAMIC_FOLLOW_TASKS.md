# SCAN网页：多房间动态行人与指定人物跟随任务

## 操作入口

导航页默认选择SCAN。在画面右侧选择任务/场景/难度；更改后点击“重置并加载任务”，等待READY，再点开始。任务一可点击地图空地改终点；任务二通过人物01/02/03选择要锁定的人，并设置0.9–2.5m跟随距离。换人需要重置，不自动切换到最近的人。

左键拖画面旋转、右键平移、滚轮缩放；停止保留实际物理状态。页面失联2.5秒停车，单次任务上限120仿真秒，碰撞或跌倒锁定FAULT。地图展示静态墙体、人物、目标、全局路线和实际机器人轨迹。

## 任务一：相连多房间与动态避人

`rooms_dynamic`包含上下两排、每排三个区域；隔墙设门洞互相连接，入口是较宽开口。三个有头/躯干/腿碰撞几何的脚本行人在房间和门洞间行走，开始任务后运动。不同难度改变行人速度。终点默认在末端房间内，亦可自行选择其他房间。

已知建筑静态平面图用于膨胀网格A*与路线前视；低阶梯挑战的目标高度取自该已知场景地形高度图；SCAN原生局部规划和闭环轨迹控制读取MuJoCo实际射线点云与机身里程计。移动人物没有作为真值障碍直接塞进全局A*图。动态任务额外传递没有回波的有效雷达射线供地图清空；丢帧不是自由空间，不能用于清空。

在原生SCAN输出之后，增加来自可见仿真人物轨迹的2秒恒速相对运动预测保护：接近/预测冲突时先降低平移速度，仍不满足预测间距则停止平移。这是保守停车层，不是具有完整人体意图预测的动态时空优化器，无法保证所有拥挤交互可通行。

### 动态地图实验补丁与复现

动态任务尝试启用`rob2nav_dynamic_map_v1`源码补丁：固定上游提交之上增加参数`grid_map.rob2nav_occupancy_timeout`，默认0（关闭），网页动态任务设为2秒。某体素超过该时间没有命中证据，便撤销该体素的占用及对应膨胀，回到unknown；不是声称测到了自由空间。老化只在收到新点云并更新地图时发生。实机禁止直接继承此配置：SCAN对unknown的处理可能允许穿过未重新观测的区域，单独老化地图不能作为人员或静态物体的安全保证。已知建筑A*图及近人保护也不能替代完整安全地图。

参数、补丁名称由API的`scan.map_occupancy_timeout_s`和`scan.source_variant`返回。旧版不带补丁的原生二进制不支持新参数；先应用并构建，再启动桥接服务：

```bash
cd /root/gpufree-data/Rob2Nav
python3 deployment/patch_scan_dynamic_map.py /root/gpufree-data/scan-reproduction/upstream
source /opt/ros/jazzy/setup.bash
cd /root/gpufree-data/scan-reproduction/upstream
source install/setup.bash
colcon build --packages-select plan_env scan_planner --parallel-workers 2 --cmake-args -DCMAKE_BUILD_TYPE=Release
cd /root/gpufree-data/Rob2Nav
bash deployment/start-scan-bridge.sh
```

补丁脚本检查固定上游提交并可重复执行；需要停止已有桥接服务后再按部署手册启动，避免UDP端口占用。静态回归场景使用0秒超时。不得将此分支称为未经修改的原版SCAN。

行人采用脚本运动与近机器人侧向避让；慢/常规模式的领路人会等落后的机器人。这是合作行人场景，不能将无碰撞成绩归因于机器人单方处理了任意非合作人群。快速难度下领路人不等待。人体是运动学碰撞角色，不是经过生物力学训练的自由人体策略。

## 任务二：锁定人物与地形挑战

| 场景 | 实际模拟内容 | 不应推断的能力 |
| --- | --- | --- |
| follow_obstacles | 家具、横穿行人与移动领路人 | 不代表真实相机识人或任意拥挤人群通过 |
| follow_stairs | 四级2.5cm刚性台阶、0.35m踏面、平台和下阶 | 不代表标准楼梯、楼层导航已通过 |
| follow_sand | 粗糙刚性小块、摩擦0.38 | 无沙粒/沉陷/土壤塑性，不能等同真实沙地 |
| follow_mixed | 家具、低阶梯与后段沙地接触近似 | 不代表综合路线已完成验收 |

机器人仍是自由基座Go2，由RoboGauge MoE输出关节目标/力矩闭环，再由MuJoCo产生移动与接触；不通过跟随目标直接写机器人位置，也不在失败后自动扶正。台阶不是播放动画，爬不上或跌倒会保留实际结果。

人物观测使用**仿真标签ID和位姿，并用雷达原点的射线测试可见性**；不是图像检测、相机ReID或基于真实点云完成的识人模型。遮挡即停止追赶，保留同一个ID；重新可见后只恢复这个ID，不改跟另一人。地图淡色人物属于显示真值，不代表控制器始终能观测它。

规划前视点位于人物运动方向后方、比期望停止位置更靠前；实际人物距离达到设置值附近时由独立距离门控停止接近。前视点随人物更新；静态墙体阻塞则先走全局路线。人物近距离时保持，目标不可达/观测无效时等待。移动目标周期更新会显式触发原生规划器重新接收意图，避免只收到一次旧轨迹后长期停滞。

## 可观测指标与验收

API仍是`/scan-live-api/api/state`，新增task、people、selected_person、tracking、person_distance、safety_reason、route、local_goal、terrain和task_metrics。任务指标包含最小人物中心间距、跟随距离平均绝对误差、跟随/失联样本数及路线失败数。中心间距不是机器人外形到人的最小表面距离。

到达任务用ARRIVED及真实终点距离判定；跟随是持续任务，RUNNING不表示已通过。完整验收还需记录整条路线完成率、每段地形的进入/退出、目标身份错误次数、可见时间内距离误差分位数、碰撞/跌倒、停车时间和人工介入。短时在楼梯前移动不能算穿越楼梯。

```bash
cd /root/gpufree-data/Rob2Nav
# 会重置当前SCAN仿真；使用新目录，并保留失败记录
python3 scripts/verify_scan_tasks.py --output outputs/scan_tasks_check_new
# 原有静态场景的回归检查
python3 scripts/verify_scan_mujoco_web.py --output outputs/scan_static_check_new
```

固定一次测试只用于集成检查；不同调参版本的失败与结果分开保留，不合并为成功率。需要再扩展不同起终点、门洞尺寸、速度、遮挡、随机种子、不同选定人物、传感器延迟/掉帧、规划器退出和目标被长时间阻挡等测试，才可讨论鲁棒性。

## 真实部署与进一步开发

当前提供的是两个**可操作的仿真任务入口**，不是全部能力已验收。多房间已有固定场景到达记录；地图老化补丁启用后，人物跟随的固定综合场景已完成低阶梯与沙地近似的进入/退出。此前无补丁版本持续跟随停滞，失败记录保留；单次地形穿越不能作为任意楼梯、真实沙地、长期跟随或实机可部署的证明。

复现地形停滞时，应先查看`outputs/scan_web/planner.log`：原生规划器会把被判占用的局部目标调整到附近自由点，可能退回机器人身前，随后重复`Close to goal`、规划失败和停车。动态人物膨胀占用、移动目标更新以及地面/台阶碰撞包络均须联合排查；当前日志不足以单独认定是某一个因素。不要靠删除人体碰撞、隐藏台阶点云或写机器人位姿来“通过”测试。下一步须给出可通行地形表达、受机器人运动能力约束的目标高度/轨迹，以及对应运动策略的独立物理验收。

实机版本仍须完成[D435i/MID360标定](GO2_D435I_MID360_INSTALL_CALIBRATION.md)、[SCAN完整导航链](../skills/navigation/SCAN_DEPLOYMENT.md)，另加人物检测/跟踪/ReID、米制3D目标与协方差、遮挡/身份确认、受控执行与人工接管。当前向下60°的托爪相机未必能长期看清行人上半身；人员跟随应单独验证视野，必要时增加前向相机，不能假设掌面机位已满足ReID。

真实楼梯还需要经过对应机器人/载荷验收的地形感知运动策略、脚步/支撑约束与下降保护。真实沙地需土壤接触模型或DEM/MPM耦合仿真，以及实测沉陷/滑移参数和现场验证。本次没有训练或认证新的楼梯/软土运动策略。
