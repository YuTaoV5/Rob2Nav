# 在线仿真与任务遥测

> 文档类型：使用指南。新环境先阅读[环境准备与路径约定](环境准备与路径约定.md)，从当前仓库根目录设置变量。历史报告中的成绩、模型编号和运行状态属于记录当时；当前是否可执行、是否通过，以对应技能中文手册及实际模型/评估文件为准。原始配置和日志仍保留在归档中，不能原样执行其中的机器路径。


## 使用

1. 打开 Studio → 实验与曲线 → 任务队列。顶部显示实际活跃的 Studio GPU 任务；外部 GPU 进程无法关联时会明确显示未知轮次。
2. 训练任务保存权重后，点击“最佳候选 → 仿真”。详情中的候选也可跳转。跳转只选择权重，不会自动运行。
3. 仿真页选择权重、地形、原始/前置几何、难度、种子和最长时间，点击“启动仿真”。任务通过单 GPU 队列执行，不训练策略。
4. 在三维视窗左键拖动旋转、右键拖动平移、滚轮缩放。“定位机器狗”重新对准当前帧。时间轴支持回看和播放；勾选“跟随最新帧”查看服务器新产生的状态。
5. 任务详情显示轮次、阶段、吞吐、TensorBoard 标量标签、多曲线、实际命令、参数与奖励覆盖配置。每8秒刷新；至多同时选择16个TensorBoard指标，各曲线保留末点并采样至约2000点。逐轮日志中的嵌套 loss 也显示为独立曲线。

## 最佳的定义

只比较**已实际保存检查点对应迭代**的 `Train/mean_reward`，选择最高者并显示依据。未保存的奖励峰值不参与权重选择。若没有此标量，回退到最终评估权重或最新保存点。界面明确标注这不是“独立严格评估最佳”；目前训练流程只对最终检查点执行严格套件，没有各检查点的同协议排名。仿真任务可再次打开其输入权重。

## 执行边界

- 感知 MoE `model_*.pt` 在 **原生 Isaac Sim** 中加载并执行；从检查点 provenance 恢复 navigation、teacher_map、sensor_rig、memory_lifetime 和空间注意力。地形/难度由页面选择。
- 支持的是 `moe_perceptive` 训练格式，不能将 AME、NJU、旧 MLP 或 TorchScript 文件当作同一种格式使用。界面筛选已知感知 MoE 目录；运行时仍严格检查元数据和 state_dict。不兼容则失败，不回退到基础权重。
- MuJoCo 模式运行现有基础 MoE / IK / NJU 历史组合；当前此面板提供平地、阶梯、高台。历史组合的其他导航场景仍由原“运行新仿真”入口选择。
- 新生成的三维回放使用服务器物理模拟的 root position、wxyz quaternion 和按名字映射的12关节角，不在浏览器重新模拟动力学。视角改变只影响显示。
- 原生地形用与训练相同的几何函数重建显示；显示使用 RoboGauge 的 Go2 URDF/OBJ 运动学模型，碰撞、惯性和接触仍由服务器原生模拟器负责。
- 旧视频若未保存关节状态，无法转换为可旋转的三维回放，仍播放原视频。单个短回合不是能力通过率或跨模拟器迁移证明。特权完整地图教师始终单独标识。

## 数据与接口

新任务数据位于 `outputs/studio/runs/<id>/`：`scene.json`、流式 `replay.jsonl`、视频、summary、原始轨迹。队列控制元数据位于 `outputs/studio/jobs/<id>/`：`command.json`、`resolved_config.json`、日志。

- `GET /api/jobs`：状态、实时轮次、保存权重候选。
- `GET /api/jobs/<id>/telemetry?tags=Loss/surrogate|Train/mean_reward`：标签与选定标量、逐轮日志、实际 argv 和参数。
- `GET /api/jobs/<id>/replay?after=0`：场景、最多600个新帧及下一游标；未完成JSON行留到下次读取。

接口必须对应已知任务ID，权重必须位于可信项目 artifacts、outputs 或服务器 MoE-runs 路径。推理继续使用现有单GPU锁与显式提交机制。自动探索保持暂停。
