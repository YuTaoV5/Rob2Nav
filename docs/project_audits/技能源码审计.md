# Rob2Nav skill source audit

> 文档类型：研究记录。新环境先阅读[环境准备与路径约定](../环境准备与路径约定.md)，从当前仓库根目录设置变量。历史报告中的成绩、模型编号和运行状态属于记录当时；当前是否可执行、是否通过，以对应技能中文手册及实际模型/评估文件为准。原始配置和日志仍保留在归档中，不能原样执行其中的机器路径。


Read-only audit, 2026-10-19. No upstream program, model, training, or simulation was executed. API tree/blob evidence is saved beside this report. Availability means source availability, not tested behavior.

## Verdict

- **LeggedSkillDeploy Go2 policies are the strongest simulation integration candidate.** Included TorchScript policies, robot MJCF, motion references, and MuJoCo runtime remove the need for Isaac Gym at inference. Actual execution and quantitative validation remain outstanding.
- **uw-himloco high/hop cannot directly deliver Go2 skills.** Both current branch trees contain only the custom Dog morphology and no policy weights. The `hop` branch currently implements recovery, not hopping. The `high` branch README support table overstates the actual branch tree: there are no Go2 configurations/assets.
- **himdog is a custom hardware deployment example**, with ONNX weights but hardware-specific calibration, motor communication and morphology; these are not Go2 policies.
- **walk-these-ways-go2 is a genuine Go2 gait-control source**, but its provided play path requires legacy Isaac Gym, not Isaac Lab/Isaac Sim. A new simulator adapter is work, not an already verified capability.
- **go2-mid360-navigation is a genuine Go2 navigation demonstration stack**, using CHAMP gait control and Gazebo Classic rather than an RL skill controller. It supplies a clean planning-layer reference, not a ready Isaac Lab integration.

## LeggedSkillDeploy exact Go2 formats

Files under `policy/unitree_rl_lab/go2/` are explicit Go2 contracts, not inherited Go1 hop weights.

- `go2_loco/config.yaml`: input45, no observation history; gyro, gravity, velocity commands, joint position/velocity, previous actions.12 DOF; .005s physics and decimation4 ->50Hz. Action scale.25, RL Kp25/Kd.5.
- `go2_jump/config.yaml`: input69, no observation history; motion command (reference joint position/velocity), motion anchor orientation in body frame, gyro, joint positions, joint velocities, previous actions. Reference `go2_jump.csv`,50fps,time .5–2.6s.12 actions, PD Kp20/Kd.5, action scale.25; mapping `[3,0,9,6,4,1,10,7,5,2,11,8]`.
- Same framework includes separate `go2_back_filp` and `go2_silde_filp` configs, policies and CSVs. These are motion-reference policies, not obstacle-aware autonomous traversal. Their use requires motion timing and reset semantics from the supplied runtime.
- Dependency list has torch>=1.10,mujoco>=3,dm_control,numpy<2.3,PyYAML,input/UI packages. Isaac Gym is not an inference dependency. Training provenance links include unitree_rl_lab but the deployment repository does not establish a reproducible training command for every supplied checkpoint.
- `policy/issacgym/go1/go1/Mar24_22-05-56_hop.pt` is explicitly Go1; do not assign this checkpoint to a Go2 slot.

## Integration acceptance gates

Use separate labels: upstream demonstration; source contract audited; local dependency ready; simulator execution verified; quantitative evaluation complete. This audit only establishes the first two. A first run should prioritize LSD Go2 locomotion and jump in isolated MuJoCo with its exact morphology, ordering and observation code. Success requires recorded simulation and episode outcome metrics, not merely importing policy.pt. No evidence here establishes that Rob2Nav currently executes, switches, navigates with, or recovers using any of these policies.
