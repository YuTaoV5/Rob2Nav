更新：2026-10-24。使用现有 v8/model2200，在同一 MuJoCo 物理状态下完成三次后翻，每次先站稳、完成动作、恢复 FIXSTAND，再开始下一次。不插入行走，不重置机器人。这是带站稳间隔的三连，不是连续弹跳式空翻。

## 在网站运行

1. 打开统一部署页面的技能编排区域。
2. 点击“填入连续三次后翻”，确认时间线为站立、后翻、后翻、后翻、站立，循环轮数为1。
3. 默认采用原过渡流程。要比较短过渡，显式勾选“重复后翻缩短过渡（实验仿真，仍等待站稳）”。开关不会自动开启。
4. 点击运行序列，保持页面连接。观察实时画面、三个动作及末尾站姿；不要只看步骤编号或通过标签。
5. 等待报告返回。页面显示的总时间还包含初始化；不要把有效驻留秒数当作总动作时间。

只有相邻重复后翻步骤才允许开启短过渡。修改模型或控制合约后，原报告不再代表新配置；不同Kp/Kd的合约不会匹配同合约短路径。

## 命令行复现

先按[环境准备与路径约定](环境准备与路径约定.md)准备依赖和模型。在仓库根目录、已安装项目依赖的 Python 环境运行：

```bash
python -m rob2nav.deployment.verify_mujoco \
  --asset source \
  --sequence artifacts/backflip_triple_20261024/sequence.json \
  --seed 28100 --initial-yaw-deg 0 --max-seconds 150 \
  --experimental-compact-backflip-repeat \
  --video --video-fps 50 \
  --output outputs/my_triple_backflip_28100
```

输出目录必须不存在；重复验证请使用新目录，不覆盖原证据。去掉 `--experimental-compact-backflip-repeat` 可运行默认过渡。网页导出的序列JSON保存动作顺序，短过渡是执行选项，命令行复现仍须显式传此参数。

四朝向验证分别使用0、90、180、-90度，并分别保存输出。不要仅改机器人朝向截图来替代物理复验。

## 如何判读报告

检查 `summary.json` 中：

- `backflip_validation_complete` 为true，`backflip_validation`恰有3项，每项动作方向、完整旋转和首尾FIXSTAND通过。
- `whole_sequence_joint_constraints`：1000Hz逐物理步覆盖完整，速度与关节限位通过。
- `whole_sequence_ground_contacts`：覆盖完整，无非足部区域接地。
- `whole_sequence_command_continuity`：相邻下发目标的变化率通过，且采样覆盖完整。第一条目标没有前一条指令，不在差分范围内。
- `experimental_compact_backflip_repeat` 与实际选择一致，模型和源码哈希可追溯。
- 录像时间轴覆盖完整，并另行复看原速未剪辑录像。

目标变化率检查不证明原始策略输出连续、加速度或jerk有界，也不代替视觉抽动检查。不要只依据顶层 `passed` 判断实机可用。

## 控制逻辑

同名后翻每执行一次必须获得新的epoch；重新准备独立的策略历史，避免编排器把仍在ACTIVE的同一个动作重复计数。短过渡仅在相同后翻合约、动作完成且实测站稳时，省去额外的标准站姿绕行，并按姿态距离安排进入时间。完成、承重稳定、增益收敛和策略预运行检查继续保留。此仿真选项不解锁硬件路径。
