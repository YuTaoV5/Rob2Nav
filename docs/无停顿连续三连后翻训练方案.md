# 无停顿连续三连后翻训练方案

更新：2026-10-24。用户明确要求中间没有等待过渡，连续翻三个。现有约45秒录像不符合该目标，保留为三次独立单翻的回归基线，不能作为连续三连验收。

## 目标动作

FIXSTAND → 起跳翻转 → 落地吸收并再次起跳 → 第二次翻转 → 落地吸收并再次起跳 → 第三次翻转 → FIXSTAND。

中间保留真实足部接触、压缩与蹬伸过程，不插入站立保持、策略预热或独立技能切换。无等待不表示接触时间为零。整组作为一个技能，只在首尾切换；执行期间不重置机器人位置、速度或仿真状态。

## 为什么现有权重不能直接删等待

当前 skills/fixstand.py 的 configure_backflip 在末段奖励恢复站立，configure_backflip_delayed_entry 固定5秒单翻与1秒入口，阶段观测在动作末尾封顶。单翻落地速度、腿部压缩与第二跳的入口分布不同。简单重复时间或删除等待既没有训练过二次起跳，也会与恢复奖励冲突。

## 实施顺序

1. 新增独立连续后翻训练合约，保留已验证的单翻模型与默认配置。先检查上游终止条件、阶段观测和接触采样，避免继承单翻成功提前结束条件。
2. 以v8/model2200初始化可匹配的网络层，新增阶段与剩余次数观测时记录数值兼容性；不声称优化器或随机状态精确续训。
3. 采用接触驱动阶段：入口、蹬伸、腾空、落地吸收、再次蹬伸、最终恢复。翻转计数必须同时具备正确方向完整转角、独立腾空区间和真实落地，不能只用累计角度计数。
4. 先训练两连的落地到起跳衔接，再扩展三连。中间阶段移除静止保持奖励，最终阶段才启用FIXSTAND奖励；关节速度、限位、目标连续性和非足部触地约束全程有效。防止用额外反向摆动或连续小跳刷奖励。
5. 将次数、接触确认阈值、允许的落地至再起跳时长、奖励权重与课程参数接入网页schema、预检和提交接口，并核对实际YAML、导出合约和MuJoCo执行一致。
6. 先32环境2更新配置烟测，核对阶段能跨越两次真实接触、不会中间重置，再进行有界训练。新任务不得抢占现有队列；本方案尚未提交连续三连训练。

## 验收与证据

每组必须有三个独立的完整后翻腾空周期；中间不进入FIXSTAND等待状态，无额外小跳或站立过渡。记录两次落地到再次离地的时间、各段接触和转角曲线，并在训练前固定时间上限，不能在看到结果后放宽。

| 参数 | 当前烟测值 | 含义 |
|---|---:|---|
| 中间接续时限 | 0.45秒 | 从首次接触到再次离地确认，包含吸收时间 |
| 落地吸收时限 | 0.25秒 | 允许接触后继续完成落地旋转 |
| 纯腾空最小转角 | π弧度 | 与整个动作转角分别检查 |
| 落地朝上余弦 | 0.9 | 确认周期的姿态门槛 |
| 映射目标速率惩罚权重 | 5 | 对超出比例的目标变化率施加平方惩罚 |
| 惩罚起点/URDF限速 | 0.8 | 逐关节计算，使用实际控制周期 |

惩罚读取入口映射和裁剪之后的SDK顺序指令，不修改指令或物理状态。默认`legacy_v1`保持旧行为；v2参数不能静默用于旧版本，吸收时限不能超过总接续时限。
