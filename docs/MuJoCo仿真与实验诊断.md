# MuJoCo 仿真与实验诊断

## 在工作台使用

- **创建实验**。选择机器人、技能、起始权重。进入奖励编辑，检查函数来源、候选代入值、变更，以及当前配方支持的编辑、训练统计、回放和逐步奖励能力。最后核对训练预算、初始化方式和评估地形，保存草稿，再到任务队列提交。AS2-W 独立配方和旧作业入口保留在折叠区域。
- **在线仿真**。工作台技能的 MuJoCo 画面旁显示机身姿态、局部角速度、速度、重力投影和各关节位置、速度、执行器力矩。模型带有 IMU 传感器时同时展示其读数。选择任一信号查看最近的时间曲线。
- **模拟控制**。选择「Go2 步态 · 手柄与键盘」并启动。控制器完成站姿接管后，启用键盘或手柄。W/S 前后，A/D 横移，Q/E 偏航。标准手柄按住 LB 后启用双摇杆。命令租约为 350 ms，超时回零。页面分别显示输入请求和控制器使用的限速后指令。
- **任务诊断**。任务详情的训练曲线按 PPO 迭代查看。MuJoCo 诊断按回合秒数查看。选场景、点曲线或拖动共同时间轴，可定位视频和当步数据。未录制的项保持空缺。
- **历史视频与地图**。保留旧视频、地形和轨迹。带新版逐步数据的单次录制还可以展开关节、传感器和奖励。旧记录沿用其原始采样时间和证据范围。

Go2 手动步态会话的在线奖励来自实际导航环境步，包含目标进度、时间代价、指令变化、到达奖励及碰撞或倒地惩罚。每条记录带环境步与模拟时间。其他技能如果没有已接入的奖励数据，界面明确显示该能力不可用。AS2-W 楼梯继续用已注册的只读配方，侧翻继续用其原有工作流。

## 观测与评分契约

实时遥测来自仿真状态。机身角速度和姿态是 MuJoCo 真值。只有 MJCF 定义了相应传感器才显示实际传感器通道。关节力矩取 MuJoCo 执行器贡献，单位 Nm。

R13 起身使用同一次 MuJoCo 仿真的视频和逐步评分。每个控制步结束后记录视频帧、姿态、轮载、动作及奖励。视频从 0 秒开始，对应首个控制步结束时的物理状态，物理时钟单独记录。站稳计数从回合开始维护，失去门控时归零。分项记录原值、符号权重、控制门控、加权贡献，贡献未乘控制步长。MuJoCo 接触定义与 Isaac Lab 传感器存在后端差异。

原生 Go2 单次翻腾支持每 20 ms 同步写入帧和遥测。导出记录包含所需上下文与权重时，可复算偏航、横向重力、阶段性俯仰和竖直速度项。落地与历史依赖项缺少等价状态时保持不可用。配对以严格评估协议相等、场景种子一致为条件。

## 接入另一技能

1. 在服务器奖励清单注册稳定项名、训练函数、配置版本、参数范围和生效阶段。编辑器只提交已注册参数。实际训练记录应保存生效值。
2. 在该技能的评估器中，于同一个控制步采集视频、帧编号、视频 PTS、模拟时间、诊断物理量及可复算项。历史计数在回合起点初始化，终止后不再累计。
3. 保留训练日志、权重哈希、严格验收协议和模型输出。用固定留出场景复测。支持基线对照的评估器应拒绝混配不同协议的结果。
4. 扩展验证先用一个失败场景检查同步、门控和数据单位，再用完整留出集评价候选。旧任务缺字段时继续读取现有结果。

## 当前验证范围

- AS2-W R12 左倾 seed 12004 的 MuJoCo 回放，300 个视频帧与 300 个控制步逐一对应。逐帧核对奖励原值、门控、权重与贡献。
- Go2 已归档后翻候选的 MuJoCo seed 20000 回放，251 个视频帧与 251 个物理采样逐一对应。该已归档导出未提供当前编辑器所需的完整奖励上下文。
- 独立的 Isaac Sim 5.1.0 / Isaac Lab 2.3.2.post1 / Python 3.11 环境通过 L40 GPU 探针。通过 `ROB2NAV_LEGACY_ISAAC_PY` 将 AS2-W 原生训练及 Go2 前后翻配方指向该环境，其他配方继续使用 Studio 主运行时。启动包装器隔离 ROS/Kit 的 Python 路径，并将虚拟环境内 `nvidia/cuda_nvrtc/lib` 加入动态库路径。
- AS2-W 队列 `72d79ddc44104fb3` 运行 12 轮、40 环境，日志实测站稳权重 1.1。平地对照和候选均通过 16/16。抽查 `flat:back:12001`，两侧各 300 帧且逐步时间与视频一致，候选草稿指向 `model_11.pt`。
- Go2 父实验 `3292df538e274524` 与候选 `d5c6e8d2bd34466c` 各执行 3 轮。使用同一严格四种子协议，导出及复算分别确认偏航权重 −0.12 和 −0.11。两者均为 0/4，链路验收保留这些失败。种子 20000 两侧各 251 帧并逐帧对齐。可从该失败场景复制草稿，带入父实验、场景和 `model_4.pt`。
