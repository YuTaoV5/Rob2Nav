## Scope and evidence

The registry `studio/skill_registry.json` is the shared source for capability progress, project pins, robot contracts and experiment recipes. The workbench joins it with actual jobs and evaluation/video records. Source demonstrations, local inference, training completion and independently scored capability performance are separate evidence classes. A completed job never automatically marks a capability passed.

The initial integration covers RoboGauge and historical MoE, NJU agility, both AME variants, PIE Go2, HIM high/recovery, himdog, WMP Go1, LeggedSkillDeploy main/WMP, Walk These Ways Go2 and MID360 navigation. The three audit reports in `docs/project_audits/` explain selection and compatibility limits.

## What is executable

* Native Go2 perceptive MoE PPO: stairs, platform and mixed recipes with explicit budgets, observations, learning rates, freezing phases, rewards, checkpoint initialization, curves and nine-case evaluation.
* PIE Go2 source ONNX inference: real MuJoCo depth camera, 45 proprioception values, 450 history values, two 60x86 depth frames and recurrent state. Flat/stairs only. One 10-second stairs recording completed; this is not an independently measured traversal rate.
* LeggedSkillDeploy Go2 jump/backflip/sideflip inference adapters: source TorchScript and motion references, source joint mapping and PD gains, flat-floor MuJoCo recording. Runtime validation is tracked as jobs. Motion references are not autonomous gap detection or perceptive obstacle selection. The adapter adds a flat floor and a fixed-PD 0.8-second stand-up prelude; that prelude is not learned recovery.
* Other recipes are exportable reviewed plans, explicitly blocked from execution until their runtime, observation contract and robot assets are integrated. A UI recipe is not evidence that an upstream trainer is connected.

Go1, custom Dog, Go2 and G1 checkpoints are not interchangeable. Neither are 45-value locomotion, 69-value reference-motion and depth/history policies. The API rejects mismatched recipe/robot/algorithm combinations.

## Reinstallation

First follow the existing Studio deployment guide for the API, frontend, simulator dependencies and SSH tunnel. Run `python -m pytest studio/tests -q`; build with `cd studio/frontend && npm ci && npm run build`. Start the API on loopback with the existing single-worker mechanism. Never run a second GPU worker for the same queue.

External source assets are deliberately not vendored. On the simulator host, clone PIE at `fb0db87924a9731913ad1011381c01db6945a9c8` into the sibling directory `Rob2Nav-upstreams/go2_PIE`, and LeggedSkillDeploy at `9126dad84708fc2714c6a1158897c86844d0cc1c` into `Rob2Nav-upstreams/LeggedSkillDeploy`. Retain their original file trees, models and mesh files. `studio/upstream_lock.json` lists every required file and SHA256; `studio.upstreams.source(root, project)` validates the cache before execution. Missing or modified files fail closed. Review upstream license/permissions separately; absence of a root license is not permission to redistribute its code or weights.

PIE uses the sibling environment `envs/go2-pie/bin/python`: Python 3.11, Torch 2.7.1, mjlab 1.2.0, MuJoCo 3.5.0, mujoco-warp 3.5.0, Warp 1.18, rsl-rl-lib 5.0.1, tyro 1.0.16 and ONNX Runtime 1.31. This isolated inference environment has run successfully. The upstream training CLI loads, but a complete PIE training adapter and native training verification remain pending. Do not install this stack over the historical Isaac environment.

LSD inference uses the existing MuJoCo environment with Torch, dm_control and imageio/ffmpeg. All external inference produces `scene.json`, `replay.jsonl`, `trace.json`, `episode_0.mp4` and an explicitly unscored `summary.json`. Unscored inference must not enter benchmark pass-rate comparisons.
