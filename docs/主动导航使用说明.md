# 目标点驱动的感知越障

> 文档类型：研究记录。新环境先阅读[环境准备与路径约定](环境准备与路径约定.md)，从当前仓库根目录设置变量。历史报告中的成绩、模型编号和运行状态属于记录当时；当前是否可执行、是否通过，以对应技能中文手册及实际模型/评估文件为准。原始配置和日志仍保留在归档中，不能原样执行其中的机器路径。


本模块实现并评估：目标点 → 当前深度/点云与短时历史 → 局部绕障 →
台阶摆腿间隙修正 / 深坑判断与跳跃 → 落地后继续接近目标。

它是感知驱动的分层控制基线。局部规划、摆腿 IK、技能调度不是新训练的端到端 RL；
RoboGauge MoE 和 NJU BBC 权重保持不变。NJU TSC 没有被直接套用，因为原策略没有任意目标点接口。

## 运行

从仓库根目录运行，环境沿用原 Python 3.11 与 requirements.txt：

```bash
export MUJOCO_GL=egl
python -m go2_nav.active_run --scene slalom --goal 8 0.8 --episodes 3 --video --output outputs/active_slalom
python -m go2_nav.active_run --scene stairs --height .08 --episodes 3 --video --output outputs/active_stairs
python -m go2_nav.active_run --scene gap --gap-width .30 --episodes 3 --video --output outputs/active_gap
python -m go2_nav.active_run --scene gap --jump-backend nju_runup --config configs/nju_active.json --episodes 3 --video --output outputs/nju_gap
python -m go2_nav.active_run --scene course --goal 13 0 --jump-backend nju --config configs/mission_runup.json --episodes 3 --video --output outputs/course
```

`--goal X Y` 使用起点所在的仿真里程计坐标系，单位米；不提供时使用场景默认终点。
目标坐标不包含预设路径或通行路点。目标必须位于可站立区域；本版不支持空中目标。

`--sensors both|depth|lidar` 进行传感器消融，`--no-lift` 关闭主动抬腿。
`--jump-backend primitive|nju|nju_all|nju_runup|disabled` 的区别：

| 后端 | 行走 / 接近 | 跳跃 | 落地后 |
|---|---|---|---|
| primitive | RoboGauge MoE | 手工关节轨迹状态机 | MoE |
| nju | MoE，感知到坑后切 BBC 接近 | 冻结 NJU BBC | MoE |
| nju_all | NJU BBC | 冻结 NJU BBC | NJU BBC |
| nju_runup | NJU BBC，从起点开始形成跑动状态 | 冻结 NJU BBC | MoE |
| disabled | MoE | 不起跳 | MoE |

`nju_runup` 适合检查独立跳坑技能，不代表适用于任意混合路线。
`nju` 的跨策略衔接必须看评估结果，不能由独立跳坑成功推断混合任务成功。

## 感知与控制边界

- D435i：带安装俯角的射线深度模型，加入距离噪声与随机丢点；并非完整 RealSense 光学仿真。
- Mid-360：理想化多仰角扫描，加入噪声与丢点；不复现真实非重复扫描及全部运动畸变。
- 两路有效点在机体系融合，用 IMU 对齐重力方向。摆腿修正保留约 1.5 秒可见点历史，坑边默认保留约 5 秒，蓄跑配置延长为 12 秒。
- 不构建全局占据地图/ESDF，不将障碍位置、预设路点或地形标签送入控制器。
- 当前位姿与目标相对位置来自仿真真值，作为理想里程计。实机仍需 LiDAR/IMU 或视觉里程计。
- 地形元数据只用于物理生成和评估，不能把“没有地图输入”解释为没有定位或没有短时记忆。

台阶修正使用感知到的前方表面高度，在原 MoE 摆腿时通过阻尼 Jacobian IK 补足足端间隙。
仅修正离地摆动腿，不抬起承重腿；默认额外抬脚幅度上限 5 cm，输出仍受关节和电机力矩限制。
“提前抬腿”不等于完全没有足端碰撞，需结合冲量对照评估。

负障碍需观察到下降证据、估计坑边，并确认对岸落地区域。坑宽估计不是精确测量；
默认只允许估计宽度不超过 0.40 m。未知或超范围时接近阶段停车。
对完全无回波、没有可见边缘的悬崖，本版感知仍不充分，不应用于实机无人值守。

## 场景与成功判定

`course` 默认包括实心障碍、两级 8 cm 台阶、平台上的 30 cm 宽/80 cm 深坑、平台终点。
通过额外 JSON 配置 `course_descent: true` 可启用下台阶再跳坑的更难版本，必须单独评估。

成功需进入目标 0.45 m 范围，身体站在终点表面上方且至少两足支撑；
含坑任务还需身体中心经过坑区时持续腾空不少于 0.06 秒。
躯干撞地/障碍、翻倒等判失败。视频和逐帧数据保留失败过程。

`mission_runup.json` 在发现坑后检查最近经过的平坦轨迹，允许沿来向后退、制动，
留出约 2.7 m 接近距离，再用 BBC 建立跑动状态并起跳。后退方向观测到近障碍或坑边记忆失效时停止。
这是为减少 MoE→BBC 动态切换差异而加入的准备过程，尚非连续高速跑酷。
默认关闭该准备过程的混合任务可能失败，应保留为消融对照。
BBC 跳跃后需前后腿都出现支撑、身体保持直立且离支撑面有足够高度，才交回 MoE。
当前终点 `(13, 0)` 的三种噪声种子通过，但更换终点 `(13, 0.6)` 的测试仍失败；详见根目录评估报告。

`riser_contact_impulse` 是用 50 Hz 接触力采样估算的立面碰撞冲量；它不是 500 Hz 物理子步的精确积分。

输出包括 `summary.json`、`trajectory_*.json`、`events_*.json` 和可选视频。
视频展示目标、控制模式、抬腿次数、落地判断及深度缩略图。
