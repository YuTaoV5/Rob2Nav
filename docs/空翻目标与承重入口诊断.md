## 侧翻目标审计

`scripts/audit_sideflip_targets.py`使用原始控制帧观测、动作、实际导出元数据和固定参考重建关节目标，逐帧核对观测前24维与参考位置/速度一致，并按照SDK/actor关节顺序映射。它不运行仿真、不写入机器人状态，也不把目标越界当作实际关节越界。

v10原记录的400控制帧中，4帧目标超出URDF。2.78秒FL_calf_joint目标为+0.03935rad，超过上限0.87711rad；整个动作最大单帧目标步长1.34017rad，而0–2.4秒准备段最大步长为0.05224rad。突变不仅是旧的参考边界硬切问题，当前翻转段仍有异常策略输出。

v11中间model_10800（从10695恢复后的约105更新）在seed13710的500Hz诊断中，首尾站姿通过，无身体触地，整周约−6.256rad，但轴占比0.74866、速度比1.62236，完整动作失败。目标仍有4帧越界，峰值0.90987rad，最大步长1.33234rad，准备段0.04684rad。这是中间检查，不提前终止或判定整轮训练最终失败。

对相同v11权重、相同seed13710，仅将实际下发目标裁剪到URDF范围：7个控制周期受到改变，速度比1.38128，新增身体触地，最大高度降至0.41330m，末端站姿失败。**直接给旧策略加裁剪不能作为发布方案。** 若后续需要有界目标映射，应当重新训练并同时验证完整动作，不能只展示更低的速度。

旧v10子步审计seed12600速度比1.74862与新v11 seed13710属于不同种子诊断，不单凭这两个数字推导训练改善的因果结论。同种子v10对照另行保存。

```bash
PYTHONPATH=. python scripts/audit_sideflip_targets.py \
 --trace outputs/sideflip_v10_physics_substeps_20261022/trace.json \
 --policy-metadata outputs/fixstand_sideflip_landing_v10_20261022/exported/policy.json \
 --motion outputs/fixstand_finetune_20261021/sideflip.npz \
 --urdf ../Rob2Nav-upstreams/GO2_backflip/resources/robots/go2/urdf/go2_description.urdf \
 --output outputs/sideflip_v10_physics_substeps_20261022/target_audit.json
```

0.15在统一stand→walk_moe→backflip60→walk_moe→stand的四朝向探索中，严格后翻动作/首尾/关节门槛4/4；全程报告速度比约0.785–0.990，尚无实机资格。相同种子已用于旧配置，是受控对照而非新增独立验收集。又补齐统一执行全过程每物理子步速度/限位及样本覆盖验收，并验证后翻旋转符号，防止500Hz控制采样漏掉1kHz瞬时峰值或把前翻算成后翻。
