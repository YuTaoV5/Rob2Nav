# SCAN：台阶、窄门与带台阶的路线导航

> 文档类型：研究记录。新环境先阅读[环境准备与路径约定](环境准备与路径约定.md)，从当前仓库根目录设置变量。历史报告中的成绩、模型编号和运行状态属于记录当时；当前是否可执行、是否通过，以对应技能中文手册及实际模型/评估文件为准。原始配置和日志仍保留在归档中，不能原样执行其中的机器路径。


## 网页操作

1. 打开网站“导航”→“SCAN 原生规划器 + MuJoCo”。独立窗口为 `/scan-live`。
2. 场景选择“新增 · 台阶后过窄门”或“新增 · 带台阶的路径导航”。
3. 点击“重置并加载任务”，等待 READY，然后点击“开始导航”。默认目标均在台阶后的区域，不能通过留在起点完成任务。
4. 也可在地图上点击选择其他终点，再开始。灰色区域是可通行低台阶，橙色是不可穿越的墙体／家具，绿色虚线标出门洞位置，绿线为规划路线、蓝线为真实轨迹。
5. 画面可左键旋转、右键平移、滚轮缩放。右侧显示台阶是否进入／驶出、窄门是否穿过和机身最高位置。完成后为 ARRIVED，目标容差仍是0.40米。

## 场景尺寸

| 场景 | 台阶 | 顶部平台 | 窄门 | 默认终点 |
|---|---|---|---|---|
| `stairs_door` 台阶后过窄门 | 上行2级×5cm，下行2级×5cm；踏步长45cm | 高10cm，x=2.9–4.4m | x=3.5m，净宽0.95m、相对平台净高1.10m；门前已经是实体台阶 | (7.2, -0.9)m |
| `stairs_route` 带台阶的路径 | 上行2级×8cm，下行2级×8cm；踏步长45cm | 高16cm，x=2.9–4.4m | 没有门，含路线两侧的家具障碍 | (7.2, 1.0)m |

台阶从x=2.0m开始、4.85m结束，横跨走廊，不能沿地面绕开。窄门场景在台阶顶面设置门框，机器人必须先上台阶，再通过门洞，最后下台阶到终点。

## 规划与运动如何配合

- 使用固定提交 SCAN ROS2 原生局部规划与轨迹跟踪器，以及 RoboGauge MoE 关节策略，未新增导航训练权重或逐足落点规划器。新台阶场景额外启用下述可选目标高度补丁，不冒称未经修改的上游版本。
- 已知静态建筑地图提供墙体／家具的A*路线；低台阶不作为堵路墙体。已知地形高程用于设置局部目标的Z坐标。这是有静态地图的2.5D导航场景，不能称为未知地形自动识别。
- 点云仍来自实际 MuJoCo 射线。新场景单独启用支撑面相对高度过滤：接触脚位姿估计当前支撑高度，过滤低于支撑面0.20m的低回波，保留门框与高障碍。过滤不读取台阶几何ID，但会把某些其他低物体也视为可跨越候选，不能直接迁移到未知实景。
- 0.20m是此受控场景的点云过滤阈值，**不是已经验证可攀爬20cm台阶**。目前实际验证尺寸只有表内的5cm和8cm踏步。
- 即使没有行人，也保留有效无回波射线和高程目标，避免静态台阶场景丢失正确的地图清空／目标高度信息。无回波射线不包括传感器掉点。
- 台阶路线对家具使用0.60米静态规划余量，窄门场景保留0.37米余量。A*起终点会连接到实际可见的空闲网格点，修复“连续位姿可通行，但四舍五入后的网格在障碍里”造成的停滞；不能靠跳过碰撞恢复。
- 社区版本的手动目标默认固定起始高度。`deployment/patch_scan_goal_height.py`新增默认关闭的`fsm.rob2nav_use_goal_height`参数；只在新台阶场景开启，接收有限且限制在0.20–1.00m的目标Z，其他场景保留原行为。
- 新台阶场景把原生规划与优化最大速度对齐为0.30m/s，不再先规划0.75m/s再仅在执行端截断。原生碰撞检查、加速度与动态可行性约束没有放宽。曾出现距目标约0.44m处短轨迹动态可行性失败，相关中间版本记录保存于`before_speed_alignment/`；ARRIVED容差仍为0.40m。
- 低台阶任务对 SCAN 输出做速度限幅：前进最多0.30m/s、侧向0.12m/s、转向0.50rad/s；没有人工指定转向、瞬移机身或切换到预录轨迹。
- 门框／家具碰撞仍会停止；机身直接碰到台阶也会停止。正常足端接触台阶是运动支撑，不是导航碰撞。

新场景没有动态行人，因此占用老化参数保持0（关闭）。以前的多房间和跟随场景仍可从下拉框选择，保留原有行为。

## 验收与复现

最终固定场景测试：两个场景分别使用种子200/201/202，**6/6到达，零碰撞、零跌倒**。台阶窄门约38.6–39.5个仿真秒，8cm台阶路线约39.2–41.5秒。地图另选目标(约6.28,-1.20)m也已通过，上下台阶和穿门标记均成立；相机拖动、手机布局与旧跟随场景加载通过。运行时长不是实机耗时保证。

完整测试要求同时满足：SCAN真实产生轨迹和指令、到达终点、进入并驶出台阶、无碰撞无跌倒；窄门场景还要求机身完整穿过门平面。仅显示规划绿线不算通过。

首次路线种子201在平台家具旁超时的记录也保留为`initial_stairs_route_201_*`；最终结果不能由首次成功个例代替。

证据目录：`artifacts/scan_step_door_20261022/`，保存按场景与种子分开的原始状态采样、结果、网页截图与代码指纹。运行脚本通过真实8769导航服务测试，不直接写机器人位姿。

```bash
# 以下是当前Jazzy仿真服务器上的命令，前提是既有SCAN工作区已部署
# 编译前停止SCAN仿真和桥，保留其他服务
supervisorctl -c "$ROB2NAV_WORKSPACE/deployment/rob2nav-supervisord.conf" stop rob2nav-scan rob2nav-scan-bridge
# 首次部署新台阶功能：应用并重编译可选目标高度补丁
cd "$ROB2NAV_ROOT"
"$CPU_PY" deployment/patch_scan_goal_height.py --source "$SCAN_WS"
source /opt/ros/jazzy/setup.bash
source "$SCAN_WS/install/setup.bash"
cd "$SCAN_WS"
colcon build --packages-select scan_planner --parallel-workers 2 --cmake-args -DCMAKE_BUILD_TYPE=Release
cd "$ROB2NAV_ROOT"
# 重启桥和SCAN仿真，无需重训
supervisorctl -c "$ROB2NAV_WORKSPACE/deployment/rob2nav-supervisord.conf" restart rob2nav-scan-bridge rob2nav-scan
# 验证地图和桥接契约
"$CPU_PY" -m unittest tests.test_scan_step_routes tests.test_scan_step_bridge tests.test_scan_goal_height_patch -v
# 已启动ROS桥和MuJoCo服务后，运行证据目录中的evaluate.py
/opt/conda/bin/python artifacts/scan_step_door_20261022/evaluate.py --scenes stairs_door stairs_route --seeds 200 201 202
```

验收仅覆盖固定场景、给定步高、门宽与当前机器人模型。这里的编译命令针对当前x86/Jazzy仿真服务器，不是机载Noetic/Foxy安装流程。没有连接Go2 Edu；实机还需要真实定位、标定后的地形感知、适配载荷的运动策略与独立安全验收。不能由本结果推导标准楼梯、任意窄门或任意低障碍都能通过。
