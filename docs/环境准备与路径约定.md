# 环境准备与路径约定

## 1. 适用范围与目录

Web资料工作台可在Windows或Linux使用。训练和本文的Bash仿真步骤以Linux为准；本文记录仓库已使用的版本组合，不承诺任意硬件最低配置。先安装Git、Python 3.11与Node.js 22；需要GPU训练时，另行安装兼容的驱动、Isaac Sim 5.1、Isaac Lab 2.3.2及RSL-RL 3.1.2。

在你选好的父目录运行：

```bash
git clone https://github.com/YuTaoV5/Rob2Nav.git
cd Rob2Nav
source scripts/docs_env.sh
printf '项目目录：%s\nCPU解释器：%s\nIsaac入口：%s\n' "$ROB2NAV_ROOT" "$CPU_PY" "$ISAAC_PY"
```

`docs_env.sh`只设置变量并进入仓库，不下载文件、不启动服务、不恢复训练。每个新终端都要重新source。可以从任何位置用该文件的真实位置source它。

| 变量 | 默认位置 | 用途 |
|---|---|---|
| `ROB2NAV_ROOT` | 自动定位当前仓库 | 源码、模型、配置、输出目录的基准 |
| `ROB2NAV_WORKSPACE` | 仓库的父目录 | 多项目缓存的父目录 |
| `ROB2NAV_UPSTREAMS` | 父目录下`Rob2Nav-upstreams` | 固定提交的外部项目 |
| `ROB2NAV_ENVS` | 父目录下`envs` | Web/CPU独立虚拟环境 |
| `ROB2NAV_DATA` | 仓库下`outputs/reproduction-data` | 自行准备的输入数据 |
| `CPU_PY` / `WEB_PY` | 对应虚拟环境的`bin/python` | MuJoCo推理 / Web后端 |
| `ISAAC_PY` | 父目录下`isaacsim/python.sh` | 必须改为实际安装的Isaac入口 |
| `ISAACLAB_ROOT` | 父目录下`IsaacLab` | 训练环境代码与配置 |
| `SCAN_WS` | 父目录下`scan-reproduction/upstream` | 已构建的SCAN ROS工作空间 |

已有环境可在source前覆盖变量，例如`export CPU_PY="$HOME/venvs/go2/bin/python"`。Isaac装在别处时，先`export ISAAC_PY="$HOME/isaacsim/python.sh"`；`$HOME`代表你的用户目录。命令中每个路径变量都应加双引号，目录含空格也能正确传参。

## 2. 只启动网站

```bash
python3.11 -m venv "$ROB2NAV_ENVS/rob2nav-studio"
"$WEB_PY" -m pip install -r studio/requirements.txt
cd studio/frontend
npm ci
npm run build
cd "$ROB2NAV_ROOT"
"$WEB_PY" scripts/deployment_check.py --mode web
"$WEB_PY" -m studio.api --root "$ROB2NAV_ROOT" --port 8765
```

终端保持运行，浏览器打开`http://127.0.0.1:8765/`。看得到页面只证明Web服务就绪，不代表MuJoCo或训练引擎已启动。按Ctrl+C关闭这个前台服务；不要为了恢复网页重复启动GPU任务。

Windows PowerShell在仓库根目录执行：

```powershell
$env:ROB2NAV_ROOT = (Get-Location).Path
py -3.11 -m venv .venv-web
& .\.venv-web\Scripts\python.exe -m pip install -r studio/requirements.txt
Push-Location studio/frontend
npm ci
npm run build
Pop-Location
& .\.venv-web\Scripts\python.exe scripts/deployment_check.py --mode web
& .\.venv-web\Scripts\python.exe -m studio.api --root $env:ROB2NAV_ROOT --port 8765
```

## 3. MuJoCo推理环境

本节针对Linux x86_64仿真主机。Go2机载电脑可能使用ARM架构，应在设备上另建环境，按部署手册安装SDK与推理依赖；不要把本节的CPU Torch版本、整个虚拟环境或Isaac安装直接复制到机载电脑。

Linux先安装EGL/OpenGL和ffmpeg系统依赖；Ubuntu示例为`sudo apt install libegl1 libgl1 libglib2.0-0 ffmpeg`。创建环境后安装本项目已记录的CPU特技依赖：

```bash
python3.11 -m venv "$ROB2NAV_ENVS/go2-skills-cpu"
"$CPU_PY" -m pip install --upgrade pip
"$CPU_PY" -m pip install -r skills/requirements-stunts-cpu.txt
# 导航还需要requirements.txt中的导航依赖
"$CPU_PY" -m pip install -r requirements.txt
"$CPU_PY" scripts/deployment_check.py --mode mujoco
export MUJOCO_GL=egl
```

不要把CPU版Torch安装进Isaac环境。无窗口服务器使用EGL；桌面可按自身OpenGL环境选择渲染后端。`ModuleNotFoundError`通常表示运行了错误的解释器，先检查`"$CPU_PY" -m pip --version`。

## 4. Isaac训练环境与固定源码

Isaac Sim、Isaac Lab、驱动和CUDA需要按其安装方式先配置；一个普通venv不是Isaac安装。仓库`docs/environments/`记录历史环境，但不能跨平台原样安装完整freeze文件。完成安装后，核对入口与导入：

```bash
test -x "$ISAAC_PY"
"$ISAAC_PY" -c 'import isaaclab, torch; print(isaaclab.__file__); print(torch.__version__, torch.cuda.is_available())'
mkdir -p "$ROB2NAV_UPSTREAMS"
git clone --branch PPO-backflip https://github.com/Robot-Nav/GO2_backflip.git "$ROB2NAV_UPSTREAMS/GO2_backflip"
git -C "$ROB2NAV_UPSTREAMS/GO2_backflip" checkout 954aa61ceb62c515689677f44a21e32109f6b62d
git clone https://github.com/unitreerobotics/unitree_rl_lab.git "$ROB2NAV_UPSTREAMS/unitree_rl_lab"
git -C "$ROB2NAV_UPSTREAMS/unitree_rl_lab" checkout 4960b84732b0c2ec593dccbfe963fda1bcd7b1e3
```

源码目录已经存在时不要再次clone或覆盖工作区，改用`git -C 目录 rev-parse HEAD`检查提交。后翻/侧翻启动器有固定源码校验，报不匹配时不要删除校验。外部动作数据和未随仓库发布的权重，按对应手册逐项获取并检查哈希。

## 5. 日志与排错

训练先用新输出目录做最小流程。保留实际命令、`env.yaml`、`agent.yaml`、模型、完成记录与评估结果；不要把旧目录改名后冒充新实验。GPU内存不足时降低`--num-envs`或`--num_envs`（以该模块帮助为准），这改变了实验配置，应记录。

找不到权重时先核对`test -f "路径"`，找不到模块时先回到根目录并source环境。端口冲突先确认已有进程，不要反复启动。远端访问使用你自己的`SSH_HOST`、`SSH_PORT`、`SSH_USER`建立隧道，文档不会预设某台服务器的IP或凭据。
