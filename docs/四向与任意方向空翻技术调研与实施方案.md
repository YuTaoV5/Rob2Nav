# 四向与任意方向空翻技术调研与实施方案

调研日期：2026-10-24。对象：Go2 EDU，目标为连续、无抽动、动作前后四足标准站立的空翻。本文是技术选型和后续实验计划，不代表新增动作已经训练成功。

## 1. 结论与推荐路线

有继续改进的依据，但不建议只提高旋转奖励或不断延长现有续训。本次 arXiv、作者项目和 GitHub 检索发现，最适合当前工程的路线是：

**动力学约束轨迹生成 → 单方向闭环模仿/残差强化学习 → 接触事件触发的落地稳定 → 四方向验收 → 带方向条件的多动作策略。**

最值得先复现的是 `se3_trajopt` 及其 Go2 四向空翻衍生项目；学习框架参考 OPT-Mimic；落地控制参考 Nguyen 的接触时序优化研究。它们提供的是不同模块，不能把几个仓库拼接后就宣称 Go2 EDU 实机可用。

本次检索没有找到可核验的、同时满足“Go2 EDU、任意斜向空翻、首尾 FIXSTAND、连续无抽动、可下载合格闭环权重”的现成方案。现有可用材料以轨迹优化代码、其他机器人上的学习框架和论文实验为主。

## 2. 先明确“任意角度方向”

| 参数 | 含义 | 实现差别 |
|---|---|---|
| 起跳前朝向 | 狗先转向，再做已有前翻或侧翻 | 能覆盖世界坐标中的方向，但不等于身体斜轴空翻 |
| 翻转轴方向 | 沿身体横向、纵向或二者之间的斜轴翻转 | 需要重新求解起跳冲量、接触与空中姿态，不能线性混合左右/前后策略输出 |
| 翻转圈数 | 一圈、两圈或部分翻转 | 常规水平轴半圈会倒置，不能直接作为四足 FIXSTAND 结束姿态 |
| 落地朝向和位置 | 翻转时同时转身，落到指定位置 | 与翻转轴、角动量、足端可达空间共同约束，不能独立任意指定 |

建议第一版限定“一圈、水平翻转轴、有限落点范围”，用起跳坐标系中的轴方位角和正负圈数表达命令。后续再增加落地偏航。任意三维轴和翻转加扭转属于进一步扩展，需要独立可行域。

一圈翻转的起终四元数可以完全相同。因此不能只插值起终姿态，也不能只用落地姿态奖励判断是否完成。需要连续参考路径、半圈关键姿态、正确旋转方向及完整过程验收。对固定轴累积旋转向量可作诊断；多轴旋转不交换，不能把其三个分量的和当作普适圈数证明。

## 4. 新发现的 Go2 四向轨迹：实际检查结果

固定源版本：[`d12fb093dc391d39815b252eb209a6e4c0692726`](https://github.com/yusongmin1/go2_flip_TO/tree/d12fb093dc391d39815b252eb209a6e4c0692726)。本次读取了优化脚本、积分方式、求解器退出逻辑、可视化代码和四份数据，进行了独立静态数值审计，没有运行优化求解器或闭环物理仿真。

| 数据 | 时长 | 主要方向累计旋转诊断 | 最大关节速度/源 URDF 速度上限 | 位置越限 |
|---|---:|---:|---:|---:|
| 后翻 | 2.48秒 | 俯仰 −6.281rad | 0.99923 | 0 |
| 前翻 | 2.48秒 | 俯仰 +6.284rad | 0.99939 | 0 |
| 左翻 | 2.52秒 | 滚转 −6.296rad | 0.99981 | 0 |
| 右翻 | 2.52秒 | 滚转 +6.296rad | 0.99990 | 0 |

方向正负按这份数据的坐标约定，导入当前机器人时仍须核对。速度按相邻关节位置差除以20ms计算；与下一节点记录速度对齐，符合其半隐式积分约定。不是任意对齐后发现不一致就判为数据错误。

这些结果说明四向参考值得研究，但尚有以下缺口：

1. **可视化不是物理验收。** 提供的回放写入 `qpos` 后调用 `mj_forward`，不是通过 `mj_step` 让电机和接触自然产生运动。
2. **求解结束不一定收敛。** 示例允许最大迭代次数退出后继续导出，必须检查约束残差和求解状态，不能只看文件是否生成。
3. **电机余量不足。** 四条轨迹速度均接近 URDF 上限；静态 effort 限制不能代替当前部署所用的逐关节力矩—速度曲线。必须按真实控制合约重新优化。
4. **20ms 节点合规不代表1ms物理子步合规。** 电机、碰撞、接触与跟踪误差可能产生更大峰值。
5. **端点相同不等于稳定站立。** 初末关节姿态相同仍需检验真实四足承重、速度衰减和持续保持。

复现审计，从仓库根目录运行（需要 Python、NumPy 和外网）：

```bash
python artifacts/flip_literature_20261024/audit_upstream_references.py
```

脚本只下载固定版本资源到内存并生成审计 JSON，不执行第三方训练代码。输出为[完整审计结果](../artifacts/flip_literature_20261024/upstream_reference_audit.json)，包含资源 SHA256、四元数误差、速度、限位与位移。其 `physics_verified=false` 必须保留。

## 5. 当前失败机制与应该做的改动

下面是项目证据与文献结合后的工程判断，不是论文已经证明了当前失败原因。

| 已观察问题 | 下一项有意义的验证 | 不应直接采取的做法 |
|---|---|---|
| 左翻2.78秒目标单周期跳约1.345rad，增大阻尼后仍跳 | 检查参考拼接、映射残差与全动作目标速率；验证现有连续性奖励，再与动力学优化参考做对照 | 仅靠加 Kd 或输出滤波宣称消抖解决 |
| 前翻旧模型不腾空 | 分开检查支撑冲量、质心竖直速度、角动量与起跳接触时序，再比较已排队起跳奖励对照 | 同时提高多项奖励后无法解释变化 |
| 首尾姿态或落地不稳 | 给落地增加接触反馈和动量耗散阶段，稳定后才交给 FIXSTAND；覆盖真实入口分布 | 在固定时间直接切到站立目标 |
| 参考轨迹疑似动力学不一致 | 在源机器人上检查全身动力学、无接触时质心弹道和角动量一致性，再迁移 | 把轨迹能播放当成机器人能完成 |

建议状态机：

```text
FIXSTAND入口确认 → 平顺下蹲 → 支撑期发力 → 腾空收腿/调整惯量
→ 预落地伸腿 → 按足端接触反馈减速与平衡 → 稳定FIXSTAND → 允许切换
```

落地可以借鉴论文的接触触发力分配/QP，也可以先用与现有部署兼容的接触反馈稳定器做对照。具体增益必须通过真实电机合约和物理验证确定，不能直接照抄 A1 或 Solo8 参数。

## 6. 分阶段落地计划与通过条件

### 第一阶段：先得到可信的四方向单项

保留当前右翻恢复训练及已排队的前翻起跳、左翻阻尼对照，等待独立评估，不因发现新论文重复开训练。连续性奖励烟测只说明配置已传入，不代表动作通过。

新开轨迹优化分支时，先锁定 Go2 EDU 模型、质量惯量、关节顺序、碰撞、电机曲线和控制频率。要求求解器成功、约束残差达标；再把四份参考转换到当前动作格式。49维源数据不能直接改后缀当作当前参考，必须按字段和关节名转换，并比较足端/机身运动。

先做32环境×2更新配置烟测，再选择一个失败机制明确的方向做有界对照。训练配置、实际 YAML、导出合约、参考哈希和独立种子一起保存。不同参考不能同时改多项奖励而失去归因。

### 第二阶段：从四方向扩展到斜向

四方向独立通过后，为水平翻转轴每45°求解一个参考，并区分正负旋转。逐一检查可行性，不默认对角方向一定可行。

先训练专家或多参考模仿策略，再加入命令条件或蒸馏成统一策略。当前固定69维策略没有任意轴命令输入；新增网页字段本身不会使策略具备方向控制能力。必须同步修改观测、网络输入、导出与运行时合约，并重新训练。

用未参与训练的22.5°等中间方向测试插值，随后扩展到更密角度网格。界面只开放已验证命令范围，并明确尚未验证的方向。

### 第三阶段：长期热切换与实机适配

在不重置物理状态的情况下反复执行走路→空翻→站稳→走路，覆盖不同朝向与历史动作。训练、单技能 MuJoCo、统一部署使用同一电机曲线、SDK关节顺序、动作历史和入口分布。

之后才进行真实参数辨识与实机验证，包括质量/惯量、延迟、摩擦、足端接触和电机能力。现有后翻仿真结果不能直接证明实机完成；完整原速录像复看和硬件结果仍要单独记录。

### 统一验收

每个方向至少四个独立种子：正确方向完整一圈、首尾 FIXSTAND、准备段安静、无非足端身体触地、每物理子步关节速度和限位合规、目标连续性合规，并复看原速未剪辑录像。斜向另外检查参考路径和落地朝向，不只看某个欧拉角。

不能用平均成功率掩盖某个方向完全失败。训练启动、配置烟测、优化器导出和视频播放均不是动作通过。

## 7. 网页与训练接口需要增加的能力（尚未实现）

建议参数包括：翻转轴及其坐标系、正负圈数、落地偏航/位移、腾空时间范围、参考库、接触时序模式、落地阶段模式、首尾保持时间、入口随机化、电机合约预设、目标速率奖励、独立方向与种子网格。

所有参数都应经过同一 schema、预检、实际训练 YAML 和导出合约校验，网页与命令行共用。参数超出已验证范围时预检拒绝或明确标为研究任务，不能静默截断后仍显示原命令。
