# Rob2Nav Studio：训练与仿真工作台方案

> 文档类型：研究记录。新环境先阅读[环境准备与路径约定](环境准备与路径约定.md)，从当前仓库根目录设置变量。历史报告中的成绩、模型编号和运行状态属于记录当时；当前是否可执行、是否通过，以对应技能中文手册及实际模型/评估文件为准。原始配置和日志仍保留在归档中，不能原样执行其中的机器路径。


2026-10-18。本文是产品与工程方案，不代表功能已经实现。当前机器人训练探索及 go2 自动化保持暂停。本方案不自动恢复任务、不发布站点、不启动训练。

## 1. 产品定位与目标

面向Go2感知运动控制和导航研究的自托管网页工作台，统一配置、训练、仿真、评估、诊断、权重和报告。重点不是重复制作TensorBoard，而是打通“某次配置改变→哪段训练→哪个权重→哪次仿真→为何失败”的证据链。

第一版以单服务器、单GPU、单用户为目标，架构保留多机器与多用户扩展能力。历史实验首先可看、可比较、可追溯；训练操作随后接入。网页可用不代表机器人任务已解决。

## 2. 工作流

导入历史实验 → 选择模板或复制实验 → 编辑配置与奖励 → 预检 → 提交队列 → 监控 → 保存检查点 → 独立评估 → 同步回放与诊断 → 比较 → 导出报告/发布材料。

运行配置不可原地修改。训练中的修改生成新配置和子实验，界面明确选择“仅权重初始化”或“恢复优化器/课程/RNG”。当前模拟器物理状态并未完整保存，恢复不得描述为逐物理步无缝暂停。

## 3. 页面与信息架构

### 项目总览

- 当前目标、最新经验证能力、失败任务与待办。
- 服务器连接、GPU显存/利用率、CPU、内存、磁盘、任务队列。
- 自动化和实验状态分开；用户暂停状态优先，不自动恢复探索。
- 最新结果始终带权重、日期、模拟器、种子数、几何版本、教师/学生标签。

### 实验配置器

提供“快速模板”和“高级配置”两个层级。参数以类型化schema生成控件，含单位、范围、默认值、解释、依赖与来源。

配置组包括：

1. 算法：PPO学习率/分组学习率、学习率计划、gamma、lambda、clip、熵、更新epoch、mini-batch、梯度裁剪、探索标准差。
2. 训练：环境数、每轮步数、迭代预算、保存/评估间隔、seed、设备、墙钟上限、磁盘预算。
3. 初始化：原MoE、历史checkpoint、仅权重初始化、完整可用训练状态恢复；显示父子实验和不恢复的状态。
4. 模型：原MoE、可见地形融合、完整地图教师、历史记忆长度、注意力、冻结/解冻阶段、残差幅度。仅显示后端真实支持的组合。
5. 奖励：任务/稳定/能耗/动作平滑/足端/终止等分类；显示公式说明、实现函数、权重、原始量单位与实际加权贡献。
6. 地形：阶梯、高台、障碍、水坑、深坑、原AME双列/交错窄桩、训练前置几何；尺寸、间距、坑深、摩擦、难度与课程。
7. 感知：相机/雷达安装位姿、FOV、射线或图像采样、更新频率、遮挡、失效、噪声、局部地图分辨率与有效期。
8. 评估：场景矩阵、重置种子、布局种子、成功判据、回合数、视频采样、是否运行MuJoCo。

原AME评估规格设为锁定模板；修改尺寸后创建新场景版本，不能继续沿用“原尺寸”名称。

奖励界面既显示配置值，也显示实际贡献；不能仅凭权重大于另一个奖励就判断主导程度。现有日志缺失的原始奖励量显示“未记录”，新增训练时补充记录。

提交前展示与父实验的差异、完整解析配置、只读命令预览和资源估算。网页不得执行任意命令、上传Python作为奖励或eval用户表达式。新增奖励先以受审代码注册为插件。

### 训练监控

- 总奖励、分项原始与加权奖励、回合长度、速度误差、value/policy loss、entropy、KL、动作标准差、梯度范数。
- 当前迭代/环境步数/墙钟时间/吞吐率、阶段、冻结参数组、学习率。
- 地形等级直方图与变化，课程晋级率、失败率、各地形成功率。
- GPU/显存/CPU/内存/磁盘曲线和结构化日志。
- 支持原始/平滑曲线切换、多实验对照、按迭代/环境步数/时间对齐；不同预算比较必须可见。
- 监控缺少数据、NaN、进程退出、日志停滞、磁盘不足；失联显示unknown而不是自动断言失败。

任务状态：draft/queued/preflight/running/checkpointing/evaluating/succeeded/failed/canceled/unknown。训练完成和评估过关是两个独立字段。

### 仿真与同步回放

第一阶段以MP4、轨迹与图表同步回放为可靠主线。视频时间轴链接机身位置/姿态、目标距离、动作、足端接触、局部地图、注意力、技能切换及终止事件。跳到“首次立面接触”“脚落在支撑边缘”“离开路径”“跌落”等已记录事件。

历史记录缺少关节/姿态/点云时，不伪造三维回放或传感器画面。当前已有视频与位置/足力可以展示；完整三维回放需要新增root pose、joint state、时间戳与模型版本记录。

第二阶段：

- MuJoCo服务器渲染评估实例，网页接收低帧率预览；用户操作经仿真会话API发送目标点或速度命令。
- 训练和交互仿真实例分离，资源调度避免挤占GPU；先支持训练后自动短评估，不承诺满负载训练时高质量直播。
- Three.js显示地形、机器人轨迹、足点、视锥和已记录点云。浏览器三维视图是展示，不是物理引擎或实机真值。
- Isaac Lab训练仍在服务器；高质量渲染、视频、训练吞吐率独立配置。

第三阶段再视网络与资源需求接WebRTC。网页相机鼠标旋转不等于改变机器人传感器安装位姿；这两个操作必须明确分开。

### 基准评估与对照

用矩阵而非单一分数展示策略×模拟器×地形×难度×传感器模式×种子。

指标包括完整成功率及置信区间、失败原因、跌倒/机身/小腿碰撞、到达时间、目标误差、足端支撑边缘裕量、跟踪误差、关节限位、力矩/功率、滑移、覆盖率与未知区域。

置信区间标明按回合还是按种子统计，避免把同一固定场景的并行环境当作独立地形泛化。教师/学生、宽前置/原窄桩、IK辅助/学习动作、Isaac/MuJoCo、同种子/独立种子始终可筛选且不可混算。

对照页支持两段视频同条件并排播放、配置差异、曲线差异、原始JSON下载。没有匹配条件时显示差异，不给出无依据的“提升百分比”。

### 模型与证据库

每个模型关联：文件哈希、源码提交与启动源码快照、父模型、配置、机器人/关节顺序、动作/观测接口、训练输入权限、训练阶段、评估成绩和部署限制。

模型可标注candidate/validated/rejected/archived；validated必须指定通过的评估规格，不能泛化成“全场景可靠”。选择best依据评估与能力保留，不能默认最后迭代最好。

报告Markdown保留原文，同时生成结构化卡片、表格、图和视频索引。历史的“正在训练”描述加历史快照标记，实时状态以worker与任务记录为准。

### 传感器实验室

网页调D435i/Mid360位姿，预览视锥、机身遮挡、脚周覆盖、前方有效距离、缺失区域与记忆年龄。对比已有候选安装扫描。

几何覆盖预测、模拟射线结果、深度图/点云实测和任务成功率分开展示。当前仅部分几何和射线模型可用，不能标为完整硬件数字孪生或“最佳安装已验证”。

## 4. 多项目接入方式

不把三个仓库强行改成一个训练器。统一接口为：capabilities、resolve_config、preflight、launch、poll、stop、collect、evaluate、export。

| 适配器 | 首批接入 | 后续接入/边界 |
|---|---|---|
| Rob2Nav MoE | 现有train/evaluate/suite、阶段冻结、地图与记忆、所有已完成探针 | 教师与学生分模板，实验性开关标注状态 |
| RoboGauge | MuJoCo评估、稳定/控制指标、原MoE推理 | 不是默认从任意部署权重恢复原始训练；异步评估API需核对安装版本 |
| NJU agility | 已适配的冻结BBC跳跃权重、技能仿真/评估 | 完整原训练流程要单独验证环境、数据和机器人适配，未接通前禁用训练按钮 |
| AME/criticaldamped | 现有Go2改造流程、阶段1/2、配置与历史日志 | 原论文结果、上游支持任务、本地Go2改造严格区分；许可证与资源来源保留 |
| 导航/IK历史原型 | 目标导航、技能调度、旧成功/失败视频 | 不挪用为新感知MoE成果；与学习策略分别评估 |

每个适配器声明支持的机器人、训练/推理/评估能力、传感器输入、sim后端、精确版本和已验证用例。无法支持的组合在提交前拒绝。

## 5. 技术架构

推荐：React+TypeScript前端，ECharts绘制曲线，Three.js做三维展示；Python FastAPI服务，独立Python worker执行现有CLI。初期SQLite保存元数据、服务器文件系统保存大文件，扩展后可迁移PostgreSQL/S3兼容存储。

浏览器 → HTTPS/API服务 → 元数据与指标索引。

API服务 → 持久任务队列/资源锁 → 服务器worker → Isaac Lab、MuJoCo、算法适配器。

worker → JSONL/TensorBoard/评估JSON/视频/检查点 → 索引器 → 页面。

曲线和状态优先用SSE（可断线续传），交互仿真指令用WebSocket。视频支持HTTP Range；曲线按区间降采样，原始数据保留。不要让前端反复下载全部训练日志或大权重。

Web后端不运行在Isaac Python进程内。复用服务器既有运行环境，避免为网页重新打包Isaac/驱动造成额外风险；Web/API可容器化，GPU worker先使用固定解释器路径和版本指纹。

初期单GPU一个重训练槽，评估默认排队或在明确资源预算内执行。浏览器关闭不影响任务，API重启后通过job ID、进程组、启动时间与心跳重新对账，不能只凭PID认领任务。

训练默认需要明确点击提交；页面加载、导入报告、播放视频不能触发训练。停止先请求checkpoint再退出，超时才强制结束并标注未保存更新。暂停是在检查点边界停止，不长时间冻结GPU进程。

## 6. 数据契约与历史迁移

核心实体：Project、Run、ConfigVersion、Checkpoint、Evaluation、Episode、MetricSeries、Artifact、Event、Machine、AdapterVersion。

Run最少包含run_id、parent_run_id、mode、backend、robot、role、resolved_config_hash、source_snapshot_hash、initializer_hash、timestamps、state、environment_steps、iteration、resume_scope。

Evaluation绑定checkpoint_hash、scenario_spec_hash、geometry_hash、reset/layout_seed、success_definition、robot/control_contract、physics_backend、perception_role、action_assistance。所有图表链接到相应实体和原始artifact。

优先导入：iterations.jsonl、TensorBoard events、status/completed/failed.json、summary.json、trace.json、map_diagnostic.json、manifest/source_manifest、MP4、archive_manifest。幂等导入不重复计算；半行JSONL等待补齐，历史损坏单独报告。

历史绝对服务器路径映射为artifact ID；网页不展示敏感路径或凭据。缺失的日志/种子/原始指标展示unknown，不能补造数据。摘要报告数字若与原始评估不一致，列入待核对，不自动用漂亮数字覆盖。

## 7. 权限、资源与发布

训练服务部署在GPU服务器或私有网络，浏览器只访问API，不直接持有SSH密码。初版可通过SSH隧道访问；多人使用再配置HTTPS、用户角色与审计。只绑定受控地址，不把root shell暴露给公网。

任务参数白名单与schema校验；subprocess参数数组执行，不拼接shell；文件路径限定工作目录，视频/报告接口防目录穿越。只反序列化受信任权重，外来权重先隔离验证。

公开展示与训练控制分离：可导出静态展示站/报告，但GPU训练控制保留私有权限；GitHub Pages等静态托管不能独立执行训练。权重、视频、源码是否公开按项目授权与上游许可证处理。

## 8. 实施顺序与工作量

以下为单名熟悉项目的全栈开发者的规划量级，非交付承诺，不含机器人策略训练收敛时间。现有服务器网络、依赖、磁盘和渲染能力需预检。

1. P0 历史证据工作台（约3–5开发日）：目录索引、结果矩阵、曲线、报告、视频、来源标签、导入错误提示。先让现有材料完整可看。
2. P1 可控训练闭环（约5–7日）：配置schema、奖励注册表、模板、预检、单GPU队列、worker、checkpoint停止/恢复、实时监控和MoE/AME首批适配器。
3. P2 仿真诊断与比较（约5–7日）：MuJoCo交互会话、同步视频/轨迹/地图/接触事件、传感器安装预览、RoboGauge和NJU推理评估接入。
4. P3 可靠性与展示（约3–6日）：权限、断线/重启恢复、批量评估/小规模扫描、模型证据库、自动报告、部署和端到端验收。

完整工程版约16–25开发日量级；首个历史展示版可先交付。高帧率直播、多GPU调度、完整NJU原训练复现、大规模多租户放在后续，不塞入第一版承诺。

## 9. 验收标准

- 选定历史实验：网页与原始文件的回合数、成功数、权重哈希、视频对应关系一致；失败结果与未知字段准确展示。
- 网页提交短训练：解析配置、启动源码、进程、指标、检查点及评估完整关联。普通页面操作不触发训练。
- 进程异常即使返回0，缺completed/有failed/缺指定权重时仍阻止评估；日志停滞/网络断开状态正确。
- 停止后检查点完整且无孤儿GPU任务；恢复明确包含/不包含的状态，并产生子实验记录。
- 曲线断线后补齐，不因降采样修改原始指标；导出曲线与原始记录可核对。
- 同一评估回合的视频、地图、轨迹和事件有时间戳对应；缺状态的历史视频不生成伪三维回放。
- 改窄桩尺寸后自动产生新geometry ID，不污染原AME排行榜；特权教师、学生和IK结果不能混算。
- 关浏览器/重启API不丢任务；新API实例与worker对账，不重复启动。

## 10. 竞争力与优先级

最有价值的三项：

1. 实验证据链：配置、来源、曲线、权重、视频、评估一键互查和复现。
2. 失败诊断驾驶舱：同步查看机器人实际发生什么、当时看到什么、策略输出什么，以及最终为什么失败。
3. 公平可比的多策略基准：用明确相同任务比较MoE、感知融合、AME、NJU技能与导航组合，报告退化与不确定性。

自动调参应在固定评估协议、可靠任务控制和资源预算完成后再做；先支持网格/随机小范围扫描，不以自动堆训练替代研究判断。网页调参体验和最终机器人能力分别验收。
