## 一、优先读哪些

- 想弄清相机如何进入 RL：先读 **Extreme Parkour**，再对比 **Robot Parkour Learning**。
- 想在 Go1/Go2 做仿真到实机：优先检查 **Robot Parkour Learning**；Go1 还可参考 **Eurekaverse** 的部署链路。
- 想用普通 RGB 相机：读 **LucidSim**，但它当前公开仓库尚未包含训练代码。
- 想读高飞团队低延迟、无占据地图规划的 RL：先读 **Flying on Point Clouds with Reinforcement Learning**，再读 **Safety-Shielded RL**；前者是 LiDAR，后者是深度相机。
- 想研究深度图到轨迹：读 **e2e_opt** 和 **Neural-Primitive**；本次找到的仓库主要是项目网页，不能作为完整开源算法使用。

## 二、宇树四足：视觉、RL、仿真与实机

### Q1. Extreme Parkour with Legged Robots

- 作者：Xuxin Cheng、Kexin Shi、Ananye Agarwal、Deepak Pathak。2023 预印本，ICRA 2024。
- [arXiv:2309.14341](https://arxiv.org/abs/2309.14341) · [论文全文](https://extreme-parkour.github.io/resources/parkour.pdf) · [项目页](https://extreme-parkour.github.io/) · [官方代码](https://github.com/chengxuxin/extreme-parkour)
- **匹配点**：Unitree A1，前向 RealSense D435 深度图，Isaac Gym 训练并完成实机跑酷。
- **相机如何进入学习**：第一阶段用本体状态、地形采样点 scandots、环境特权信息和航向指令训练 RL 教师。第二阶段用 CNN/GRU 从深度图估计地形表征及航向，以教师动作监督学生，并通过 DAgger 在学生访问的状态上收集标签。不能把它简化成“相机从第一步直接端到端 PPO”。
- **部署**：论文使用约 10 Hz 深度编码器、50 Hz 运动策略；两者在 Jetson NX 上运行。深度预处理分辨率为 58×87。
- **代码状态**：官方有训练、视觉蒸馏与模型导出；本次未确认官方提供可直接运行的完整 A1 部署工程。Go2 社区补充见 Q5。
- **建议精读**：III-B、III-C 和 IV-A；重点看 scandots 被深度 latent 替换，以及视觉航向预测如何避免分布漂移。

### Q2. Robot Parkour Learning

- 作者：Ziwen Zhuang、Zipeng Fu、Jianren Wang 等。CoRL 2023。
- [arXiv:2309.05665](https://arxiv.org/abs/2309.05665) · [项目页](https://robot-parkour.github.io/) · [官方代码](https://github.com/ZiwenZhuang/parkour)
- **匹配点**：论文在 Unitree A1/Go1 上展示深度视觉跑酷；现有仓库还提供 Go2 训练和部署示例，需区分论文原始实验平台与后来支持的平台。
- **相机如何进入学习**：先通过技能 RL 和课程训练获得特权专家，再把多种技能蒸馏到单一视觉策略，部署时接收机载深度图和本体状态。软动力学约束逐步过渡到真实接触约束，是其技能学习特色。
- **代码状态**：包含 `legged_gym`、`rsl_rl`、`onboard_codes`、`go1_ckpts`。README 链接了 [Go1 部署说明](https://github.com/ZiwenZhuang/parkour/blob/main/onboard_codes/Deploy-Go1.md) 和 [Go2 部署说明](https://github.com/ZiwenZhuang/parkour/blob/main/onboard_codes/Deploy-Go2.md)。Go2 文档使用 D435i、ROS 及分开的视觉/控制进程。
- **复现判断**：最适合把论文、仿真、视觉策略和硬件接口串起来阅读；仓库对部分训练配置明确说明不保证复现论文同等性能，不能理解为开箱即用。
- **代码阅读顺序**：机器人配置 → 环境观测构造 → `rsl_rl` 网络与蒸馏算法 → `onboard_codes` 图像预处理与动作下发。

### Q3. Eurekaverse: Environment Curriculum Generation via Large Language Models

- 2024，CoRL 2024。
- [arXiv:2411.01775](https://arxiv.org/abs/2411.01775) · [项目页](https://eureka-research.github.io/eurekaverse/) · [官方代码](https://github.com/eureka-research/eurekaverse)
- **匹配点**：Unitree Go1 + RealSense D435；Isaac Gym 训练、视觉蒸馏和实机验证。
- **方法重点**：在 Extreme Parkour 基础上自动生成与调整训练地形课程，研究“训练环境如何影响视觉运动技能泛化”。视觉接入仍以特权策略到深度策略的蒸馏为主。
- **代码状态**：仓库包含 `extreme-parkour` 和 `go1_deploy`；部署说明覆盖 LCM、Docker、相机与策略启动。作者说明 Docker 仅在 Go1 的 Jetson Xavier NX 上测试。
- **部署参考价值**：论文附录给出视觉编码 10 Hz、运动策略 50 Hz 的异步架构，以及裁剪、补洞、时间滤波、降采样的处理链。
- **适合用途**：研究课程生成、未见地形泛化，或补足 Go1 机载部署链路。

### Q4. Learning Visual Parkour from Generated Images（LucidSim）

- 作者：Alan Yu、Ge Yang、Ran Choi、Yajvan Ravan、John Leonard、Phillip Isola。CoRL 2024。
- [arXiv:2411.00083](https://arxiv.org/abs/2411.00083) · [项目页](https://lucidsim.github.io/) · [官方代码](https://github.com/lucidsim/lucidsim)
- **匹配点**：Unitree Go1 + 普通 RGB 相机；模拟训练后进行实机零样本迁移。
- **相机如何进入学习**：几何与物理仿真提供运动和结构一致性，生成模型提供丰富视觉外观；特权专家提供动作标签，视觉学生通过模仿和迭代收集自身访问状态的数据学习。
- **与深度方案的差别**：关键困难从几何测量噪声扩展到纹理、光照和场景外观的域差异，适合研究纯 RGB 的 sim-to-real。
- **代码状态**：官方仓库提供 MuJoCo 环境、渲染流程及专家 checkpoint；README 明确写着 **Training code is not yet included**。生成增强流程还依赖 weaver。不要把这个仓库列成完整训练/部署开源。

## 三、“相机信息放进 RL”应区分的三条路线

### 路线 A：先训练特权 RL 教师，再训练视觉学生

Extreme Parkour、Robot Parkour Learning 是主要入口。通用结构可概括为：

```text
仿真地形真值 + 本体状态 → RL 教师 → 教师动作
                                   ↓ 监督 / 蒸馏
相机深度图 → 视觉编码与时序模块 → 与本体状态融合 → 学生动作
```

这里的图是对共同思路的概括，各论文网络和损失并不完全相同。教师使用的 scandots 是仿真地形采样点，不能直接当作实机相机输出。

### 路线 B：视觉 Actor 直接参与 RL，Critic 使用特权信息

高飞团队的单目 RGB 飞行和 Safety-Shielded RL 可作为跨平台参照。部署 Actor 接收图像与真实可获得的状态，训练 Critic 可以接收深度、干净状态等特权信息。

这与教师—学生蒸馏的主要区别是：图像编码器可直接由策略优化训练；非对称 Actor-Critic 本身不等于另有一个可供模仿的教师。

### 路线 C：RGB 视觉学生 + 外观泛化

LucidSim 是四足入口，单目 RGB 飞行是无人机入口。需要分别解决视觉域差异和动力学域差异；丰富纹理不能替代相机时延、执行器误差等建模。

### 复现时建议记录的变量

| 环节 | 应核查内容 | 对结论的影响 |
|---|---|---|
| 图像输入 | RGB/深度、裁剪、分辨率、归一化、近远截断 | 改变策略实际能看见的几何和外观 |
| 融合方式 | 视觉 latent 与本体状态何时拼接、是否使用历史/GRU | 决定部分可观测性如何处理 |
| 优化方式 | PPO、动作蒸馏、latent 蒸馏、DAgger、是否微调 | 决定“视觉参与 RL”的准确含义 |
| 特权信息 | 仅 Critic、教师、奖励或 Actor 哪些地方使用真值 | 防止部署依赖仿真才有的输入 |
| 时间同步 | 相机、编码器、策略、底层控制的频率与延迟 | 仿真成功迁移失败的常见原因 |
| 动作接口 | 关节目标、PD 参数、动作缩放及顺序 | 直接决定与实机控制接口的对应 |

## 四、高飞参与的无人机无地图/未知环境导航

首先区分：**无预先地图**允许在线建图；**无融合地图**仍可保留历史点云；**策略不建地图**也不意味着训练奖励没有地图，更不意味着系统不做定位。

### U1. Flying on Point Clouds with Reinforcement Learning

- 作者：Guangtong Xu、Tianyue Wu、Zihan Wang、Qianhao Wang、Fei Gao。2025。
- [arXiv:2503.00496](https://arxiv.org/abs/2503.00496) · [方法全文](https://arxiv.org/html/2503.00496v1)
- **输入→输出**：Livox Mid-360 点云的任务相关表示 + 本体状态/目标方向 → PPO 策略 → 推力与机体角速度，50 Hz。
- **核心表示**：把有限历史帧点云变换到当前机体系，在球面角分区内记录最近障碍距离，并显式编码未知区域；不是直接把全部原始点云塞进 PointNet。论文实例采用 3200 个分区。
- **无地图边界**：规避传统占据栅格的规划输入，但仍保留历史感知，并依赖 LiDAR/IMU 局部状态估计；训练中也使用几何真值计算奖励/碰撞。
- **实机**：论文有细障碍、线材和树林环境实验。
- **代码状态**：本次未定位到对应 2025 RL 论文的可确认官方训练/部署仓库。
- **为何优先读**：直接回答高精度几何感知如何被压缩为低延迟 RL 输入，以及已知/未知空间如何影响决策。
- **同名陷阱**：[pointcloudTraj](https://github.com/HKUST-Aerial-Robotics/pointcloudTraj) 对应更早的传统轨迹生成工作，不是这篇 RL 论文的代码。

### U2. High-Speed Vision-Based Flight in Clutter with Safety-Shielded Reinforcement Learning

- 作者：Jiarui Zhang、Chengyong Lei、Chengjiang Dai、Lijie Wang、Zhichao Han、Fei Gao。2026。
- [arXiv:2602.08653](https://arxiv.org/abs/2602.08653) · [方法全文](https://arxiv.org/html/2602.08653v1)
- **输入→输出**：100×60 深度图 + 速度/姿态/目标/上一动作 → CNN + GRU + PPO Actor → 姿态参考与归一化推力；部署再加 HOCBF/QP 修正。
- **训练与部署区别**：训练利用 Dijkstra 势场和 ESDF 奖励；实机安全滤波从实时深度图重建的局部点云提取最近障碍约束。因此“在线无融合地图”不等于“没有几何处理或优化”。
- **实机**：D435i、Orin NX、VIO/IMU 状态估计、PX4；论文报告 100 Hz 命令及最高 7.5 m/s 的实验。
- **代码状态**：本次未找到可确认官方实现。论文的理论安全结论依赖模型与观测假设，不应外推成所有未见障碍下绝对安全。
- **值得读**：图 2、III-C/III-D，尤其是训练期全局信息如何帮助一个部署期局部策略。

### U3. Flying in Clutter on Monocular RGB by Learning in 3D Radiance Fields with Domain Adaptation

- 作者：Xijie Huang、Jinhan Li、Tianyue Wu、Xin Zhou、Zhichao Han、Fei Gao。2025。
- [arXiv:2512.17349](https://arxiv.org/abs/2512.17349) · [方法全文](https://arxiv.org/html/2512.17349v1)
- **输入→输出**：60×80 RGB + 无人机状态 → CNN/GRU Actor → 推力与姿态命令。
- **训练**：3D Gaussian Splatting 提供 RGB 观测，Isaac Sim 提供碰撞与深度；Critic 额外访问深度；使用对抗域适应和域随机化缓解迁移差异。
- **无地图边界**：部署视觉策略不依赖在线几何地图规划，但训练场景的 3DGS 重建本身需要场景表示。单目 RGB 指环境感知输入，并不代表不需要本体状态估计。
- **实机**：论文展示零样本迁移与光照变化实验。
- **代码状态**：本次未找到可确认官方训练/部署实现。
- **与四足方向的联系**：可与 LucidSim 对照“生成图像多样化”和“高保真渲染 + 特征域适应”两种 RGB 迁移策略。

### U4. Mapless-Planner: A Robust and Fast Planning Framework for Aggressive Autonomous Flight without Map Fusion

- 作者：Jialin Ji、Zhepei Wang、Yingjian Wang、Chao Xu、Fei Gao。2020 预印本，ICRA 2021。
- [arXiv:2011.03975](https://arxiv.org/abs/2011.03975) · [作者提供的论文](https://zhepeiwang.github.io/pubs/icra_2021_mapless.pdf)
- **方法**：有限内存保留未融合历史传感数据，通过近邻查询、自由空间骨架、飞行走廊和航点选择规划轨迹。
- **无地图边界**：不维护融合地图，但保留历史感知并提取局部自由空间结构；这是一种传统规划路线，不是 RL。
- **代码状态**：本次未找到可确认对应官方算法仓库。
- **适合用途**：理解为何“不融合地图”仍需要记忆与空间抽象。

### U5. Learning to Plan Maneuverable and Agile Flight Trajectory with Optimization Embedded Networks

- 作者：Zhichao Han、Long Xu、Liuao Pei、Fei Gao。arXiv 2024；项目页采用题名 **Dynamically Feasible Trajectory Generation with Optimization Embedded Networks for Autonomous Flight**。
- [arXiv:2405.07736](https://arxiv.org/abs/2405.07736) · [项目页](https://zju-fast-lab.github.io/e2e_opt/) · [仓库](https://github.com/ZJU-FAST-Lab/e2e_opt)
- **方法**：深度视觉网络提取空间安全约束，结合模型驱动轨迹优化，并把可微优化纳入训练。
- **无地图边界**：不依赖常规建图规划流水线，但仍有在线优化；不属于单纯的端到端 model-free RL。
- **实机证据**：早期 arXiv 技术报告主要展示仿真；当前作者项目页明确展示树林实机实验。引用实机结果时应指向项目页，避免混用版本。
- **代码状态**：当前仓库目录以 `resources`、`static`、`index.html` 为主，本次未见完整训练/推理工程；应标为项目资料公开。

### U6. Neural-Primitive: An Efficient End-to-end Local Planner with Primitive-based Imitation Learning for Autonomous Flight

- 作者：Zhitao Liu、Guangtong Xu、Zihan Wang、Jialiang Hou、Chao Xu、Fei Gao。2026。
- [arXiv:2608.20948](https://arxiv.org/abs/2608.20948) · [项目页](https://zhitaoliu.github.io/neural-primitive/) · [仓库](https://github.com/ZhitaoLiu/neural-primitive)
- **方法**：离线轨迹基元构造模仿学习数据，紧凑网络直接预测多项式轨迹系数，在线无需后端轨迹求解。
- **实时性**：论文报告机载平均 3.68 ms、内存低于 1.5 MiB；这些是其测试硬件与设置下的结果。
- **实机**：论文展示零样本 sim-to-real。
- **代码状态**：本次看到的仓库主要包含网页与资源，没有确认完整算法实现；不能因为仓库存在就判断代码已开源。
- **适合用途**：比较直接控制策略与轨迹输出策略的接口和计算代价。

### U7. Learning Speed Adaptation for Flight in Clutter（相关补充：使用局部地图）

- 作者：Guangyu Zhao、Tianyue Wu、Yeke Chen、Fei Gao。2024。
- [arXiv:2403.04586](https://arxiv.org/abs/2403.04586) · [方法全文](https://arxiv.org/html/2403.04586v2)
- **输入→输出**：局部占据地图的切片、速度、跟踪误差和规划轨迹等 → RL 外环 → 速度约束；内环仍为模型驱动轨迹规划器。
- **分类结论**：适用于未知环境，但明确在线构建并使用局部占据地图，**不满足严格“非建图”条件**。
- **实机**：论文有机载实验。
- **代码状态**：本次未确认官方训练/部署实现。
- **保留原因**：研究感知不确定性下何时加减速，及 RL 与已有规划器如何协同。

## 六、建议的阅读与实验顺序

1. **视觉四足机制**：Extreme Parkour III-B/III-C → Robot Parkour Learning 训练与蒸馏 → 官方 Go1/Go2 部署说明。
2. **部署工程**：核对相机安装、视场、深度预处理、视觉/运动频率与动作接口；Go1 可参考 Eurekaverse。
3. **无人机核心机制**：Flying on Point Clouds 的 III-A → Safety-Shielded RL 的 III-B/III-C/III-D → RGB 飞行的 III-B/IV。
4. **学习规划对照**：e2e_opt → Neural-Primitive → YOPO / agile_autonomy / DiffPhysDrone，分别理解可微优化、模仿轨迹、直接控制三条路线。

若目标是提出一个连接两方向的研究问题，我建议比较：**在部分可观测环境中，深度/RGB/点云表征如何编码未知空间，视觉历史与安全约束分别如何改善 sim-to-real**。这是本清单基础上的研究建议，不是任何单篇论文已验证的结论。
