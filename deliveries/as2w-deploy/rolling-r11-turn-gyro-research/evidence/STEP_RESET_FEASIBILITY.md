# 用踏步恢复 fixed stand 的可行性（操作员提问）

操作员问：左右转之后几条腿相对 fixed stand 有偏移，能否**转过去之后踏步恢复 fixed stand**？

## 1. 先确认「偏移」是什么

先前实测（`JOYSTICK_SEQUENCE2.md`）：刹停序列结束时腿姿与本回合零指令站姿相差 **0.198–0.416 rad**，且 upright ≥0.995、支撑 1.000、零终止。**偏移存在，但不是失稳。**

## 2. 读踏步控制接口后的关键发现

仓库里的踏步是**解析式时钟步态**（`as2w_stepping_control.calibrated_sequence`），有两个决定性细节：

**(a) 零指令时它输出全零动作。** CPU 验算：

```
cmd=zero   active=False   前 12 维全部 +0.00 / -0.00
cmd=tiny   active=True    前 12 维 ±0.007（幅度与指令成正比）
```

由于动作语义是 `q = a*0.35 + DEFAULT`，**全零动作 = 正好是 fixed stand 默认姿态**。**→ 也就是说「零指令保持站姿」本身就已经在把腿往 fixed stand 上压了。**

**(b) 步态摆幅与指令幅值成正比**（`active = |command|>0.015`，`reach ∝ stride_gain*vx*stride`）。指令 0.02 时前 12 维只有 ±0.007 rad，**不构成真正的抬腿踏步**；要真正抬腿需要 0.15–0.25 量级的指令，而那同时也会让机器人位移。

## 3. 因此偏移的成因被重新定位

如果零指令时目标本来就是 fixed stand（动作全零），那 0.198–0.416 rad 的残差**不是「目标错了」，而是腿部 PD 在负载下的静态平衡点**。这与「`turn_left_0.10` 末段支撑掉到 0.570」是同一类现象：**腿被机身重量和接触反力压离了参考姿态。**

**→ 这恰恰说明操作员的直觉是对的：要恢复固定站姿，需要改变**受力**，而不是改目标。**踏步（轮流抬脚、换脚支撑）正是改变受力的手段 —— 每次抬脚都会让该腿卸载，重新落地时向参考姿态收敛。

## 4. 结论与可行路径

| 问题 | 回答 |
| --- | --- |
| 偏移是否真实存在 | ✅ 0.198–0.416 rad，可复现 |
| 偏移是否「目标错」 | ❌ 零指令目标本身就是 fixed stand（动作全零） |
| 偏移成因 | **PD 在负载下的静态平衡点**（与支撑塌缩同源） |
| 踏步能否改善 | **理论上可以** —— 抬脚卸载会打破静态平衡、让腿向参考收敛 |
| 现有步态能否直接做到 | **不完全能**：摆幅与指令成正比，零/小指令不抬腿；大指令会同时位移 |

### 需要做什么（未执行，下一步）

1. **基线测试**：转弯后仅保持零指令 5 s，测腿误差是否衰减。若不衰减 → 确认是静态平衡而非跟踪误差。
2. **踏步复位**：给一个**足够抬腿但净位移约等于零**的指令序列。由 `stride = 2*(swing_forward-return_to_rear)-1`   可知一个完整周期内净步幅为 0，因此可用「一个完整周期的小幅前进 + 退回」实现原地踏步复位。
3. **判据**：踏步后与本回合零指令站姿的腿误差应显著小于 0.198–0.416 rad；同时不破坏支撑与 upright，   且不得引入非轮触地。

## 5. 与 goal 边界的关系

- goal 要求滚动与踏步**技能隔离**，但训练守则 §4 允许「旧策略 → 减速停稳 → fixed stand → 新策略」的技能切换。  **「转弯后踏步复位」属于切换流程的一部分，不违反隔离要求**，但必须按切换流程记录：首帧连续性、阶段时序、回站证据。
- 若采用该方案，交付须同时给出**带与不带踏步复位**两套回站流程，并标明各自可用包络与回退方式。
