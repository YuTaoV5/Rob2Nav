# ⭐ 首个可复现的分岔点：**Isaac 有 2 秒动作斜坡，MuJoCo 没有**

操作员要求「本轮交付以首个可复现的分岔点为准」。本轮按要求先做动作链与执行器的源码级对照，**在物理之前就找到了一个确定的、可复现的分岔点**。

## 1. 分岔点原文

`code/as2w_isaac_robust_env.py` 第 185–188 行：

```python
if self.cfg.robust_profile != "baseline":
    alpha = (self.episode_length_buf * self.step_dt / 2.).clamp(max=1.)[:, None]
    action = self.hold_action.lerp(action, alpha)
return super().step(action)
```

配套的 `hold_action` 初值（第 176、180 行）：

```python
self.hold_action = torch.zeros_like(action)              # 全 16 轴先归零
self.hold_action[:, :12] = (joint_pos - default)/.35     # 只有 12 个腿轴填保持值
```

## 2. 这意味着三处分岔

| # | 项 | Isaac | 我的 MuJoCo |
| --- | --- | --- | --- |
| 1 | **实际下发的轮目标** | **前 2 秒从 0 线性斜坡到策略值** | **立即等于策略值** |
| 2 | 观测 `[42:58]`（上一动作） | `env.policy_action`（**斜坡前**） | `prev`（**实际下发**，斜坡后） |
| 3 | 斜坡时长 | `alpha = min(1, t/2)` → **2.0 s** | 无 |

**第 1 条是关键**：`hold_action` 的腿部分填了保持值，但**轮部分（索引 12:16）保持为 0**，所以 **Isaac 的轮目标在前 2 秒被从 0 拉起来**，而 MuJoCo 立刻给满。

**第 2 条同样重要**：观测里报的是**斜坡前**的动作，实际下发的是**斜坡后**的动作 ——这是一个「观测与执行不自洽」的设计，**我的 MuJoCo 复现成了自洽的版本**，因此两端策略看到的输入不同。

## 3. 为什么这能解释此前观察到的差异

| 此前观察 | 由斜坡解释的部分 |
| --- | --- |
| Isaac 中段轮差 ≈0（0.10/0.15） | 前 2 秒轮目标被压到接近 0，**转向的第一推动力被推迟 2 秒** |
| Isaac 实测轮速只有 0.116（MuJoCo 0.744） | 12 s 均值里前 2 s 被压，但**不足以解释全部**（见第 5 节） |
| 两端偏航「一端欠、一端超」 | 斜坡让 Isaac 的转向晚起，**起转阶段积分量不同** |
| `obs_prevact` 在对齐前后都出现较大差异 | **第 2 条**：一方报斜坡前、一方报斜坡后 |

## 4. 顺带确认的两项（这两项是**一致**的，不是分岔）

| 项 | Isaac | MuJoCo | 结论 |
| --- | --- | --- | --- |
| 延迟缓冲初值 | `_initial_target` 返回 **zeros** | `prev = zeros(16)` | ✅ 一致 |
| 轮端执行器参数 | effort 13.5 / KD 6 / KP 0 / friction 0 / armature 0 | 同 | ✅ 一致 |
| 陀螺补偿默认关闭 | `_as2w_on = kp!=0 or gain!=0`，默认 **OFF** | 评测侧 `AS2W_GYRO_KP` 未设时为 0 → OFF | ✅ 一致 |

**→ 所以按操作员第 1、2 步的顺序，分岔在第 1 步（执行器/动作链）就出现了，且不需要物理层解释。**

## 5. 但斜坡**不足以**解释全部差异（必须说清）

末 3 秒的对比是 **MuJoCo 0.744 vs Isaac 0.116**。到末 3 秒 `alpha` 已经 =1 很久（2 s 后即满），**所以斜坡不能解释末段差距**。

**→ 结论分两层：**
1. **已确定**：前 2 秒的分岔由斜坡造成（这一条可立即修正并复跑）2. **仍未解释**：末段的 6.4× 轮速差距，需要按操作员第 1 步的「固定基座、轮子悬空」实验单独隔离，   重点查**隐式速度驱动 vs 显式阻尼**（Isaac 走 `set_joint_velocity_target_index` → PhysX 隐式驱动，   我在 MuJoCo 是显式 `tau = 6*(target − dq)` 再裁剪）
