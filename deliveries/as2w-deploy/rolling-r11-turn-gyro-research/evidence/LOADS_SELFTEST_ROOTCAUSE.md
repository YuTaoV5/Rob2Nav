# 载荷自检失败根因已定位：**刚性保持 DEF 姿态不是站立姿态**，与 `loads_n` 无关

上一轮 `loads_n` 自检 FAIL。本轮加了诊断（高度与接触数）并修正了索引，根因已明确。

## 1. 索引 bug 已修正（确认了上一轮的判断）

合同关节数组是 **part-major**：`[FL_hip, FR_hip, RL_hip, RR_hip, FL_thigh, ...]`。我原来写 `tgt[i*3+k]`（leg-major），已改为 **`tgt[k*4+i]`**。
**修正后「抬 FL」在 reset 时刻确实只让 FL 有载荷**（`loads=[128.19, 0, 0, 0]`），说明索引对齐已对。

## 2. 真正的根因：站立用例里机器人**塌陷了**

诊断输出（站立用例）：

```
[diag after reset]  z=0.3814  ncon=0  loads=[0.0, 0.0, 0.0, 0.0]
[diag after settle] z=0.1143  ncon=1  loads=[0.0, 0.0, 0.0, 0.0]
```

**→ 高度从 0.3814 掉到 0.1143（下落 0.267 m），接触数只剩 1，四轮全部失载 —— 机器人倒下了。**

### 为什么

我的自检脚本用 **PD 把 12 个腿关节刚性保持在 `DEF`**（`thigh=0.8, calf=-1.6, hip=0`），然后用 `d.ctrl = tau` 一直保持。**但 `DEF` 只是「动作默认偏移量」的定义值，不是本模型的稳定站姿。**

**关键对比：我所有能正常工作的脚本，settle 相位都是跑策略（policy），不是刚性持有 DEF。**例：`r11_mj_continuous_sequence.py`、`r11_mj_lift_in_place.py`、`r11_mj_state_trace.py` 的 settle 都由 actor 输出目标。此前对齐实验还量到「策略稳定结束时的腿关节角与 DEF 相差很大（`leg q max 1.7955`）」—— **正好印证 DEF ≠ 站姿**。
**→ 所以 `loads_n` 通道本身没有被证伪；是我把机器人摆成了一个会倒的姿态，然后去读它的轮载。**

## 3. 第二个问题：抬腿偏置仍过大

修正索引后，四个抬腿用例仍然会倒下（例：抬 FL 后载荷跑到 RR 的 871 N），说明 **髋 ±0.35 / 大腿 −1.4 / 小腿 +1.2 rad 对单侧支撑依旧过大**。

## 4. 修复方案（下一轮）

| # | 改法 | 判据 |
| --- | --- | --- |
| 1 | **settle 改用策略**（加载 checkpoint，跑 3 s），与所有正常脚本一致 | 站立时四轮各 >20 N、总和 ≈255 N |
| 2 | 抬腿偏置降到 **±0.15 rad 级**，并逐轴限幅 | 抬 X 腿时**只有**第 X 个读数归零，其余三个**上升**，机器人不倒 |
| 3 | 保留诊断输出（高度、接触数、四轮载荷）作为自检的固定部分 | 每用例都打印，便于比对 |

**→ 只有 1、2 都绿，才能判定 `loads_n` 可用，进而跑零/左/右三档。**
