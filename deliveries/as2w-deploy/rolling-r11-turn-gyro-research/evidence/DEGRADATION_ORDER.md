# 左原地转中 RL 为何卸载：**负载失衡先出现约 0.7–1.0 秒，然后才完全卸载**

操作员第 4 项要求先查「转向中为什么卸载」；训练侧要求「在有效支撑窗口里找出轮载、腿姿、实测轮差和偏航哪个先恶化」。本文件一次轨迹同时回答这两问。

## 1. 方法

左原地转（`wz=+0.05`，12 s），逐帧记录：四轮地载、实测轮速与轮差、偏航率、滚转/俯仰、逐腿关节误差、膝高。定位**首次任何一轮低于 20 N** 的帧，再在该帧**之前**找出哪个量最先偏离基线的 20% 量程。
对照两个权重：对照 `4bdf4d26` 与 B 组终点。

## 3. 三条结论

**(a) 卸载不是控制输入的瞬时产物。** 关节误差、实测轮差、膝高在 `t=0`（指令一施加）就偏离 —— 那是正常的起转响应；而 **RL 的完全卸载发生在 4.7 / 5.9 秒**，中间隔了 4–6 秒。

**(b) 真正的先兆是「负载失衡」，比完全卸载早 0.7–1.0 秒。**ctrl：3.98 s → 4.70 s（早 0.72 s）；armB：4.86 s → 5.88 s（早 1.02 s）。**→ 存在约 0.7–1.0 秒的早期预警窗口。**

**(c) 卸载是「载荷逐渐转移到其它三轮」的结果，不是腿姿突然变化造成的。**腿姿指标从 t=0 就是常规起转形态，没有在 4–6 s 附近出现新的偏离 —— 说明**问题在受力分配，不在姿态命令**。

## 4. 对操作员三点要求的直接回应

| 要求 | 回应 |
| --- | --- |
| 「先查转向中为什么卸载」 | **RL 载荷被逐渐转移到其它三轮；失衡从 3.98/4.86 s 开始，0.7–1.0 s 后完全离地** |
| 「这个瞬间不适合直接命令 RR 离地」 | **确认不适合。** 卸载那一刻 RL 已在 0 N，再抬任一腿会进一步破坏支撑 |
| 「转弯中的卸载归转向控制」 | **同意，且有依据**：卸载由受力分配引起，与腿姿命令无关 → 属转向控制问题 |

## 5. 一个可用的早期预警指标（建议）

**四轮负载失衡度** = `max|load_i − mean(load)|`。它在完全卸载前 0.7–1.0 s 就显著上升。可作为**转向阶段的支撑预警**：超过某阈值就判「本窗口支撑将失效」，而不必等到 RL=0。

**阈值暂不确定** —— 需要多工况统计后才能给。本轮只证明该指标**领先于**卸载事件。

## 6. 与 B 组的关系

**armB 卸载更晚（5.88 vs 4.70 s）、帧数更少（74 vs 89）** —— 与 B 组在 Isaac 上支撑全部 1.000、且纯转偏航变好的方向一致。但这是 MuJoCo 单工况单次，**不能当作统计结论**。
