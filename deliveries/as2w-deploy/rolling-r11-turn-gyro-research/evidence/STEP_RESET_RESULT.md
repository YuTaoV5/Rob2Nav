# 负面结果：现有踏步**没有**突破 0.19–0.20 rad 站姿平台，反而略差

## 1. 测什么

上一轮实测：转弯后仅保持 fixed stand，腿误差在 0.5 s 内收敛到 **0.193–0.197 rad** 平台，6 s 内不再改善。若该平台是**负载静态平衡**，那么「轮流抬脚卸载」的踏步应当能把它压下去。本轮直接检验。

序列（单条连续轨迹）：站态 3 s → 策略转弯 12 s → **保持站姿 4 s（基线）** → **踏步 5 个周期**（`calibrated_sequence`，指令 0.12，周期 0.8 s；步幅 `2*(swing_forward−return_to_rear)−1` 一周期净位移为 0）→ 再保持 4 s。

## 2. 结果

| 量 | 左转 wz=+0.05 | 右转 wz=−0.05 |
| --- | --- | --- |
| 转弯结束 | 0.399 | 0.454 |
| **保持基线** | **0.200** | **0.204** |
| 踏步后 | 0.214 | 0.243 |
| **最终（再保持 4 s）** | **0.225** | **0.245** |
| **相对基线变化** | **+0.025** | **+0.041** |
| 步态动作幅值 | 0.665 | 0.665 |

**→ 踏步没有降低站姿误差，反而使其增加 0.025–0.041 rad。**

## 3. 🔴 如实结论

**「转弯后踏步恢复 fixed stand」这个方案，用现有踏步实现在此条件下**不成立**（略差而非改善）。**

### 为什么（分析，未逐项验证）

1. **步态的支撑相足端位置不等于 fixed stand 的足端位置**。`calibrated_sequence` 算足端目标时带横向偏置   （`y = side*0.1054 + shift…`）与纵向 stride 项，而 fixed stand 的默认关节角对应另一组足端位置。   **踏步后足端落点变了**，再对同一组默认关节角求负载平衡，得到的腿误差自然不同（且略高）。2. **步态没有「回到默认站姿」的终态阶段**：踏步结束后我们直接下发零动作，系统又回到「对默认目标求负载平衡」，   但支撑多边形已经变了。3. 指令 0.12 下抬脚量有限（`lift` 与步幅均随指令缩放），可能不足以让每条腿真正完全卸载。

## 4. 那么什么才可能真正解决

平台成因是「PD 在负载下稳定在偏离目标的点」。踏步改变的是受力路径，但**没有改变那个平衡点本身**。更直接的两个方向：

**(a) 姿态偏置补偿（推荐先试）**：把站姿目标改成 `DEF + 实测负载偏置`，使**实际达到的站姿**等于真正的 fixed stand。这是腿轮协同允许范围内的静态偏置，只需一次标定，且可回退（偏置置零即回标准腿姿）。**代价**：偏置依赖负载，换载荷需重标；且它改变的是「指令脚」而非「受力」。

**(b) 放松腿 PD 柔度或调整站姿高度**：改变平衡点位置本身。需单独扫描，且要回归支撑与净空硬约束。

## 5. 与 goal 的关系

- 该负面结果**不影响** rolling 主体能力的判定（支撑/upright/终止均不涉及）- 若最终采用 (a) 偏置补偿，交付须给出**偏置版与标准腿姿版两套配置**，并写明偏置置零的回退步骤（符合「基线要求」）- 踏步方案若要保留，必须重做步态使其支撑相足端与 fixed stand 足端一致，并单独验收 —— **当前版本不得使用**

## 6. 边界

1. **仅 MuJoCo、单权重、1 种踏步参数（指令 0.12 / 周期 0.8 s / 5 周期）、两种转向方向**2. 未扫描踏步指令幅值、周期、周期数 —— **不能排除其它参数下有效**3. 未逐帧验证抬脚高度与卸载程度，机理分析为推断
