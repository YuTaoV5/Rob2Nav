# C5 观测畸变用例：已实现，待运行

C5 枚举里「观测冻结 / 时间戳跳变 / 重复帧」三项列为 not_run。本轮把其中**两项**实现在验收脚本里，**尚未运行**（GPU 被 B 组训练占用）。

## 1. 实现内容

`runtime/r11_acceptance_ff.py` 新增两个参数：

| 参数 | 语义 | 对应畸变 |
| --- | --- | --- |
| `--obs-freeze N` | 每 N 帧中有 N−1 帧把**上一帧观测**喂给策略 | **观测冻结 / 重复帧** |
| `--obs-stale-steps K` | 策略看到的是 **K 个策略步之前**的观测 | **陈旧观测（数据龄）** |

关键设计：**仿真器始终用真实状态推进**，只把「策略看到什么」替换掉 —— 这正是失联/卡帧/重复帧在策略侧的样貌。
因此它测的是**策略对陈旧输入的鲁棒性**，而不是改变物理。

## 2. 为什么「时间戳跳变」仍未实现

时间戳跳变在仿真里没有对应的可观测量 —— 策略的 65 维观测里**没有时间戳通道**（`0:3` 命令、`3:6` 角速度、`6:9` 重力投影、`9` 常数、`10:26` 关节、`26:42` 关节速度、`42:58` 上一动作、`58/59` 相位、`60:64` 轮差、`64` 零标志）。**时间戳与数据龄属于部署层（R3），不在策略输入里。** 因此该子项**不能在仿真里测**，应归到 R3 现场只读验证。

## 3. 补丁过程的一处自身失误（如实记录）

第一次打补丁时把多行 `help=` 字符串写成了真换行，导致语法错误；第二次插入点选在 `--payload-kg` 的**多行 `add_argument(...)` 调用内部**，同样语法错误。两次都从交付包恢复了干净副本。**→ 教训：给本仓库的 Python 打补丁，插入点必须选在语句边界（本次最终选在 `ap.parse_args()` 之前），且字符串只能单行。**
