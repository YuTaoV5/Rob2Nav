# 控制合同变更：把 gyro-1 放进**训练闭环**

## 1. 变更原因（操作员要求）

「开训前核对 `gyro-1` 是否也进入了原权重的训练闭环。若它此前只用于评测，本轮两组都采用相同的闭环实现，并登记为控制合同变更。」

## 2. 核对结果：**此前只在评测中，训练完全没有**

| 检查项 | 结果 |
| --- | --- |
| 训练代码中 `yaw_kp` / `ff_cap` / `S_WHEEL` | **0 处** |
| `train_armE_support2p0.py` 中 `gyro` | **0 处** |
| `yaw_kp` 出现的文件 | 仅 `r11_mj_matrix_v2.py`、`r11_acceptance_ff.py` 与交付文档 |

**→ 结论：所有既有策略都是在**没有** gyro 的闭环里训练，然后在**有** gyro 的闭环里评测。**
**→ 这是真实的控制合同不一致，已按操作员要求登记并修正。**

## 3. 变更内容

新增 `DelayedGyroVelocity(DelayedVelocity)`，在**训练侧**的速度设定值上施加与评测完全相同的偏置：

```
ff = S * clip( yaw_kp*(wz_cmd - wz_meas), ±ff_cap )     S = (-1,+1,-1,+1) for FL,FR,RL,RR
sp = target + ff / KD                                   KD = 6
```

- 与评测包装 `r11_acceptance_ff.py` 的 `sp = dq + tau/KD = target + ff/KD` **同一公式**
- **无积分、无滤波**（每个物理子步调用不会累积）
- 增益由环境变量 `AS2W_GYRO_KP` / `AS2W_GYRO_CAP` / `AS2W_GYRO_FF_GAIN` 提供，**默认 0 = 完全复现旧行为**
- 挂在 `pose-delay` 的 DELAY 分支上（原先把 `wheel_vel.class_type` 覆盖成 `DelayedVelocity`，这正是第一版补丁无效的原因 —— 已如实记录）

## 5. 开训前基线（同一权重 `4bdf4d26`，**未续训**）

三种闭环下的纯转/弧线（种子 7393，站态 2 s，工况 12 s，末 3 s）：

| 用例 | 无 gyro（旧训练闭环） | **gyro 在训练闭环内（新基线）** | 评测期 gyro-1（旧评测） |
| --- | --- | --- | --- |
| turn_left_0.05 | +0.07 | **−0.01** | +0.39 |
| turn_right_0.05 | +0.10 | **+0.06** | +0.35 |
| turn_left_0.10 | +0.02 | +0.06 | +0.18 |
| turn_right_0.10 | +0.22 | **+0.03** | +0.29 |
| arc_right 0.25 | +0.57 | +0.65（支撑 0.913） | +0.78 |
| arc_left 0.25 | +0.66 | **+0.41** | +0.50 |

**→ 把 gyro 放进闭环后，未续训的策略表现反而比「只在评测期加 gyro」更差**（如 turn_left_0.05 由 +0.39 降到 −0.01）。
**这正是必须续训的原因：策略从未见过这个闭环。**

**→ 本轮 A/B 两组都从这个新基线起跑，同一闭环、同一增益（60/4）。**
