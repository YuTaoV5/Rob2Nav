# armD-10k 三个留出检查点在 gyro-1 **开启**下的复评

> 背景：此前所有 Isaac 结果都是 gyro-1 **关闭**的基线口径（见 `GYRO_WAS_OFF_IN_EVAL.md`）。本轮用 `--yaw-kp 60 --ff-cap 4` 重评 6600 / 8600 / 10600 三个检查点，两种子。

## 1. 汇总

| 检查点 | 通过数 | 纯转最好值 | 弧线 |
| --- | --- | --- | --- |
| 6000（对照，gyro-OFF 历史） | 6/11 | 0.12–0.30 | 左 0.93 PASS / 右 0.17 FAIL |
| **6600** | **6/11** | 0.09 / 0.61 / 0.42 / 0.64 | 左 **0.98 PASS** / 右 0.44 FAIL |
| **8600** | **5/11** | 0.27 / 0.60 / **0.91 PASS** / 0.70 | 左 **0.87 PASS** / 右 0.97 **term=1** |
| **10600**（种子7393） | **7/11** | 0.01 / 0.37 / 0.20 / **0.72 PASS** | 左 0.63 FAIL / 右 0.44 FAIL |
| 10600（种子311） | 评测收尾中 | — | — |

## 2. 四条结论

**(a) 陀螺补偿对纯转是单调有效的。**同一批检查点上，纯转从 gyro-OFF 的 0.01–0.35 提升到 gyro-ON 的 **0.01–0.91**；**8600 上 turn_left_0.10 达到 0.91 并 PASS**，**10600 上 turn_right_0.10 达到 0.72 并 PASS**。**→ 这是本次工作里第一次出现「纯转在不同检查点、不同方向上分别跨过门槛」。**

**(b) 但补偿把机器人推向终止与支撑边界。**整个复评出现 **6 次 `term=1`**，集中在 8600 与 8600/311：

| 用例 | 检查点 | 跟踪 | 支撑 | 终止 |
| --- | --- | --- | --- | --- |
| turn_right_0.05 | 8600/7393 | 0.60 | **0.860** | **1** |
| turn_right_0.10 | 8600/7393 | 0.70 | 1.000 | **1** |
| arc_right | 8600/7393 | **0.97** | **0.867** | **1** |
| arc_right | 8600/311 | **0.99** | 0.993 | **1** |
| turn_right_0.05 | 6600/311 | 0.60 | 1.000 | **1** |
| turn_right_0.10 | 6600/311 | 0.49 | 1.000 | **1** |

**→ 最刺眼的是 arc_right：跟踪已经到 0.97–0.99（远超门槛），却因为 `term=1` 与支撑 0.867 而失败。****→ 补偿把「转不够」换成了「转过并摔」。**

**(c) arc_right 是 gyro-ON 下最稳定的失败项；arc_left 随训练退化。**
- arc_right：0.44 / 0.40 / 0.97(term) / 0.99(term) / 0.44 —— **五个观测里没有一个干净通过**
- arc_left：0.98 PASS → 0.78 PASS → 0.87 PASS → 0.93 PASS → **0.63 FAIL**（10600 掉出门槛）

**(d) 「训练越久弧线越差」在 gyro-ON 下不再简单成立。**gyro-OFF 时 arc_left 从 0.93 掉到 0.63；gyro-ON 下 arc_left 在 6600/8600 仍 PASS（0.98/0.87），而 arc_right 反而在 8600 冲到 0.97。**→ 该结论必须按 gyro 口径分开陈述，不能混用。**

## 3. 力矩与补偿的饱和证据

每个用例都记录到：
- `tau_max = 13.50 Nm`（**精确等于 90% 力矩限幅**）
- `ff_max = 4.00 Nm`（**精确等于 `--ff-cap`**）
- `caps` 从 8 一路累加到 **2237 次**

**→ 补偿持续顶在自己的限幅上，轮端也持续顶在力矩限幅上。**这与「实测轮速只有命令的 1/3」以及「turn_right / arc_right 容易触发终止」两条观察一致：**补偿在饱和状态下不再是温和的修正，而是一个持续的满幅力矩偏置。**

## 4. 已加的防复发守卫

`runtime/r11_acceptance_ff.py` 新增 `AS2W_GYRO_GUARD`：
- `yaw_kp <= 0` 且 `ff_gain <= 0` 且未传 `--allow-no-gyro` → **直接拒跑并说明原因**
- 真值表 5/5 通过（`GUARD_TRUTHTABLE_PASS`）：缺参拒跑、有逃生开关放行、给 `--yaw-kp 60` 放行、只给 `ff_gain>0` 放行、`yaw_kp` 很小但 >0 放行

**→ 该静默降级（训练开补偿、评测关补偿）从此不可能再发生。**

## 5. 评测太慢的原因与改进

**本轮实测：5 组用 2421 s，约 484 s/组。**

| 原因 | 量级 | 我的责任 |
| --- | --- | --- |
| 一次批了 3 检查点 × 2 种子 × 11 用例 = **66 次用例** | 单组纯仿真约 159 s，实际 484 s | **我的调度错误** |
| 与训练**抢同一张 GPU**（利用率 97%） | 评测被拖慢 2–3 倍 | 应错峰 |
| 11 用例**串行**跑，未用多环境并行 | 存在 11 倍理论加速空间 | 脚本待改 |

**改进：一次只跑一个检查点并即时汇报；训练空档期独占 GPU；把 11 例改为多环境并行。**

## 6. 边界

1. **10600 的种子 311 仍在收尾**，上表 10600 仅种子 7393
2. 6600/8600 的通过数是**两种子合并汇总行**，未逐种子拆开
3. `tau_max` 是**脚本侧限幅估算**，求解器实际施力仍 `not_measured`
4. 未在 MuJoCo 侧跑 gyro-ON
5. 本轮与训练争 GPU，墙钟时间不代表独占性能
