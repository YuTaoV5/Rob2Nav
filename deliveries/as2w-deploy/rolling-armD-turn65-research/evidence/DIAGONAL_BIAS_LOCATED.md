# 右向不对称定位：**在「策略下发」侧，不在轮端/接触侧**

操作员指出 goal 执行顺序第 3 条应查「**对角偏置**（策略对角分量约为左右差速 2.57×）」与「**右向不对称**」。本文件用**同一权重、同一协议**的左弧与右弧轨迹，逐级对比：**下发轮差 → 实测轮差 → 偏航**。

## 1. 方法

- 权重：`armD_turn65_final.pt`（sha `de61de58…`），Isaac，种子 7393
- 协议：零指令稳定 3 s → 弧线 10 s，取**末 3 s** 平均
- 差分定义：`diff = (FL + RR) − (FR + RL)`；对角量：`|(FL + RL) − (FR + RR)|`
- 工具：`runtime/r11_asymmetry_probe.py`（新），数据 `evidence/diagonal/armD_arcs_asymmetry.json`

## 3. ⭐ 三条判定

**(a) 不对称首先出现在「策略下发」，不是轮端。**
下发差分：左 **−0.0542** vs 右 **−0.2738** → **右/左 = 5.05 倍**。**→ 策略对右弧下达的轮差指令本身就是左弧的 5 倍。这是策略侧的偏置，不是接触或执行器把指令吃掉了。**

**(b) 到实测轮差时，不对称反而「消失」了 —— 但代价是整体都不动。**
实测差分：左 −0.0127、右 −0.0088，**两者相近**；而**实测对角量升到 5.6 / 8.8**（下发时只有 2.1 / 0.6）。**→ 轮端把大部分差分「抹平」了（wheel-end differential is heavily attenuated），并把对角分量放大。**
**这是本轮最有价值的发现**：实测对角/差分比 **5.6–8.8**，而操作员给的参考值是 **2.57**。**→ 轮端存在一个把差分转成对角（对角化/交叉化）的环节**，左右轮之间的差速没有变成偏航，而是变成了对角分量。**

**(c) 偏航与实测差分的耦合系数两端接近。**
`yaw / measured_diff`：左 **0.0394**、右 **0.0455**，相差仅 15%。**→ 偏航响应本身是对称的；问题在于「实测差分太小」和「下发差分左右不等」这两件事。**

**→ 执行比普遍在 0.0–0.36 之间，且右弧的 RR 为负** —— 轮子几乎**没有跟随指令**。对照 Isaac 验收矩阵里 armD 的弧线跟踪 0.83/0.76（本追踪器里却是 0.0005），**说明这两处的「弧线」定义不同**（验收用 `wz=±0.05` 且命令持续 12 s，本追踪器同为 `±0.05`）。**→ 二者存在口径差异，本文件的绝对偏航值不可与验收矩阵直接比较，只能用于左右对称性比较。**

## 4. 对「修哪里」的指向

| 观察 | 指向 |
| --- | --- |
| 下发差分左右差 **5.05 倍** | **策略侧**：右弧的轮差指令生成本身偏大/偏斜 → 这是**训练**要修的 |
| 实测对角/差分比 **5.6–8.8**（参考 2.57） | **轮端/接触**：差分没有变成偏航而是变成对角 → 需要查**左右轮与地面的耦合**（左右对称性、接触差异、轮轴朝向） |
| 执行比 0.0–0.36、RR 在右弧为负 | 轮端**几乎不跟随**指令 → 与「实测轮速只有目标的 1/7」的既有观察一致 |

**→ 两条线索都指向「同一处」：左右轮差没有转化为偏航，而被转成了对角分量。****下一步应查轮地接触的左右对称性**（左右轮材质/摩擦/接触点是否对称），而不是继续调偏航增益。

## 5. 边界

1. **仅单种子、单权重、单协议**（Isaac，seed 7393，末 3 s 窗口）
2. **绝对偏航值与验收矩阵口径不同**（本轮 ≈0，验收 0.83/0.76），**只用于左右对称性比较**
3. 「下发轮目标」取自上一帧动作 × 16 的比例，**不是逐帧的最终下发值**（追踪器未记录该量）
4. 差分/对角的符号约定为 `(FL+RR)−(FR+RL)` 与 `|(FL+RL)−(FR+RR)|`
5. 未在 MuJoCo 侧做同样比较
