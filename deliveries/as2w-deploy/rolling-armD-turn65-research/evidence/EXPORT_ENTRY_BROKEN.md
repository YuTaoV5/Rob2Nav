# 🔴 导出脚本实跑：**交付入口不可用，且无法复现包内 ONNX**

操作员要求「在干净检出里实际导出一次」，因为「AST 和 BOM 检查确认它能解析，实跑才能确认交付入口可用」。**照做后确认：入口不可用，而且问题比语法更深。**

## 1. 实跑条件

- 从 `/root/gpufree-data/Rob2Nav` **克隆一份干净检出**（不带工作树改动）- 运行 `runtime/export_policy_onnx.py`，输出目录预建 `weights/`（模拟干净检出里包内已有的 `weights/`）
## 2. 两个实测缺陷

### 缺陷 A：脚本跑不完 —— 缺 `onnxruntime`

```
ModuleNotFoundError: No module named 'onnxruntime'
```

导出本身成功后，脚本要继续做 **ONNX 与训练模型的同输入对齐**（第 50 行 `import onnxruntime as ort`），但该环境没有安装 `onnxruntime` → **脚本在验证环节崩溃**。
**→ 交付包声明的「导出 + 对齐」入口，在干净环境里无法完成。**

### 缺陷 B：产物格式与包内不一致，哈希不同

| 项 | 脚本实跑产出 | 包内实际发布 |
| --- | --- | --- |
| 文件 | `policy.onnx` **1,885 B** + `policy.onnx.data` **174,080 B** | `policy.onnx` **175,066 B 单文件** |
| 格式 | **external data（外部数据）** | **单文件** |
| sha256 前 16 位 | `81ea9531902f8318` | `680e0c720750fdaf` |
| 一致？ | ❌ **不同** |

**→ 按当前脚本重新导出，得到的不是一个等价于已发布权重的 ONNX，而是另一种格式的产物。**
**→ 任何人照 README 走「重新导出」这一步，都会拿到与 `SHA256SUMS` 不符的文件。**

## 3. 这为什么重要（比语法错误严重）

| 检查层 | 之前的结论 | 实跑后的结论 |
| --- | --- | --- |
| 语法（ast） | ✅ 通过 | ✅ 仍通过 |
| 编码（BOM） | ✅ 已修 | ✅ 仍通过 |
| **能否完成导出+对齐** | 未验证 | ❌ **不能（缺 onnxruntime）** |
| **产物是否等价于已发布权重** | 未验证 | ❌ **不等价（格式与哈希都不同）** |

**→ 这正是「AST/BOM 通过 ≠ 入口可用」的实证。** 静态检查只证明文件能读，不证明流程能走通、产物能复现。

## 4. 修复方案（下一轮执行）

1. **锁 ONNX 导出为单文件**：导出时关闭 external data（把大张量内联），使 `policy.onnx` 与发布件同格式   - 否则必须**把 `policy.onnx.data` 一并纳入交付并写进 `SHA256SUMS`**，同时更新 README 的加载说明2. **把 `onnxruntime` 列入交付依赖**并在预检里检查，或让对齐步骤在缺依赖时**明确失败并给出安装指引**，而不是抛裸 `ModuleNotFoundError`3. 修复后**再次在干净检出实跑**，并把新产物 sha256 与包内记录的对比结果写进证据4. 若重新导出无法逐字节复现原文件（ONNX 导出常含非确定性元数据），则应把**「发布件哈希」与「可复现性声明」分开写清**，不能声称完全可复现

## 5. 对「可冻结、可复跑」目标的影响

goal 要求交付「可复跑评测、部署与回退脚本」。**当前导出入口不满足「可复跑」。**在修好并实测通过之前，包状态保持 `research / deployable=false`，**不得声称导出链路可用**。

## 6. 边界

1. 只在**一个** venv（`/opt/isaaclab-venv`）里试过；若正式环境装了 `onnxruntime`，缺陷 A 可能不复现 —— **但缺陷 B（格式/哈希不同）与依赖无关**2. 未尝试关闭 external data 后能否逐字节复现包内文件（下一轮做）3. 未核对包内 `policy.onnx` 当初是用哪个版本的脚本导出的（无记录，故无法确认「脚本 = 发布件的来源」）
