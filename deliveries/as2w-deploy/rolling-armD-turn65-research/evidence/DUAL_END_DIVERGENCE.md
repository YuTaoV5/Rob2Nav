# 双端分岔定位：**两端连「同源初态」都不成立**，差异在站立平衡点而非转向策略

操作员要求「从同源初态和同一最终四轮目标序列开始，记录接管首 0.5 s 和 3–5 s 的目标、实测轮速、轮载与偏航，定位哪一级先分岔」。本轮建了两端状态追踪器并做了逐字段比较。

## 1. 方法

两端各写一个追踪器（`runtime/r11_mj_state_trace.py`、`runtime/r11_isaac_state_trace.py`），**同一 schema**：每步记录 **65 维观测 / 16 维动作 / q / dq / 四元数 / 世界系角速度 / 偏航率**。协议相同：**零指令稳定 3 s → 纯转 12 s**，均从标准 fixed stand 起。比较器 `runtime/r11_divergence_order.py` 按字段归一化后报**首次越阈帧**。

## 2. 🔴 最重要的发现：稳定相位就已经分岔

| 量 | MuJoCo | Isaac |
| --- | --- | --- |
| **稳定 3 s 结束时的腿关节角最大差** | — | **0.2419 rad** |

**→ 两端从同一个 fixed stand 初值出发，各自稳定到**不同的平衡点**，腿姿相差 0.24 rad。****因此「同源初态」这个前提在当前实现下**并不成立**。**

## 3. 转向相位的量化差异

| 量（12 s 转向期间均值） | MuJoCo | Isaac | 比值 |
| --- | --- | --- | --- |
| 轮动作差分量 `diff(act)` | **−0.0759** | **−0.0023** | **33×** |
| 实测轮速差分量 `diff(dq)` | **−0.9049** | **+0.1048** | 符号都不同 |
| 实测轮速幅值 `\|dq\|` | **0.744** | **0.097** | **7.7×** |
| 末 3 s 偏航率 | **+0.0653** | **−0.0014** | — |

## 4. 逐字段首次分岔顺序（左转，转向相位内）

| 字段 | 首次越阈 | 峰值 |
| --- | --- | --- |
| 腿关节角 / 腿动作 / 实测腿角 / 零指令轮差 | **0.000 s** | 1.9–5.2 |
| 机体角速度 / 腿速度 / **轮速（实测与观测）** / 偏航率 | **0.020 s** | 1.3–6.5 |
| 轮关节角（观测） | 0.10 s | 8.8 |
| 重力投影 | 1.36 s | 1.0 |
| **指令项 / 相位 / 轮动作** | **从未越阈** | ≤0.43 |

**注意「从未越阈」这三项**：指令、时钟相位、**轮动作输出**在两端基本一致 —— 说明**不是指令生成或策略本身出错**。

## 5. 结论：分岔在**站立平衡点**，不在转向策略

**证据链：**
1. 指令项与时钟相位两端**完全相同**（峰值 0.17 / 0.00）→ 命令与相位生成正确2. **稳定相位结束时腿姿已差 0.24 rad** → 两端站姿平衡点不同3. 由此产生的观测差（腿关节角）→ 策略输出不同的轮差分量（**33× 差异**）4. Isaac 的实测轮速只有 MuJoCo 的 **1/7.7**，且差分量符号相反

**→ 这不是「Isaac 转向策略弱」，而是**两端站姿/轮端响应不同**，导致策略在不同状态上工作。****→ 按操作员的三选一（执行器 / 接触参数 / 转向策略），本轮证据指向**前两者**，不是转向策略。**

## 6. 必须立刻做的下一步（顺序明确）

**先解决「同源初态」这个前提，否则后续比较仍然无效：**

1. **对齐初态**：把 MuJoCo 稳定结束的 q/dq/姿态**强制写入** Isaac 作为起始状态（或反向），   再跑同一目标序列 —— 这样才满足操作员要求的「同源初态」2. 若对齐后轮差仍相差 33×，则差异确在**轮端执行器/接触**，再分头查：   - 轮端增益与力矩限幅（两端是否同一个 13.5 N·m 生效）   - 轮地摩擦/合成模式（Isaac 侧扭转与滚动摩擦仍未读回）3. **对齐后仍须重测**，不能用本轮数字判断「谁对」

## 7. 过程中修掉的两个缺陷（自身）

| 缺陷 | 症状 | 修法 |
| --- | --- | --- |
| **`as2w_*` 的 import 放在 `launch_simulation` 之前** | app 启动即崩：`libusd_tf.so: undefined symbol pxrInternal_...` | 移到 `with launch_simulation(...)` **内部**（known-good 脚本都是这样） |
| **`get_observations()` 返回 TensorDict** | `o[0]` 取到键名 `'policy'`，`float('policy')` 报错 | 改 `o["policy"]` |

**第一条值得记**：我一度以为是环境污染（`LD_LIBRARY_PATH`、磁盘、缓存），查了四轮才发现是**自己的 import 顺序**。**教训：新脚本报「库加载失败」时，先跟 known-good 脚本逐行 diff 结构，再怀疑环境。**

## 8. 边界

1. **只比了左/右原地转**；未比弧线与直行2. **只比了对照权重**；B 组终点未比3. 归一化尺度是我按「对该量的有意义幅值」选的，换尺度会改变具体帧号，但**「稳定相位已分岔 0.24 rad」与「轮动作差 33×」这两个量本身与尺度无关**4. 未做操作员要求的「接管首 0.5 s」单独窗口分析 —— 本轮是全 12 s 均值，下轮补5. 未对齐初态前的任何「谁对」判断都不成立
