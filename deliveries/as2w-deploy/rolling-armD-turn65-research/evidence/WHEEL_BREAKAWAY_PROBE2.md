# 轮地脱困阈值：重设计仍然无法测出，但暴露了一个真实的机制

这是第二次尝试，按 `WHEEL_BREAKAWAY_PROBE.md` 的重设计方案做（四轮共模斜坡、基线门、精细分档驻留）。

- 脚本：`runtime/r11_isaac_wheel_floor2.py`
- 权重 `armE_support2p0_final.pt`（`4bdf4d26`），种子 7393，站态 2 s，基线 1 s，档距 0.02 rad/s，驻留 0.5 s，目标上限 0.40 rad/s
- 原始数据：服务器 `results/eval/wheel-floor2-*` 与 `wheel-floor3-*` 的 `wheel_floor2.json`

## 1. 两次都判 VOID_BASELINE

| 试验 | 腿 | 轮目标 | 基线 |dq| 峰值 | 判定 |
| --- | --- | --- | --- | --- |
| 第一次重设计 | 跟随策略 | 强制 0 | **0.3534 rad/s** | VOID_BASELINE |
| 第二次重设计 | **冻结 fixed stand** | 强制 0 | **0.4348 rad/s** | VOID_BASELINE |

基线门是 `|dq| < 0.02 rad/s`。**两次都远未达标，因此阈值仍未测出。**

## 2. ⭐ 这不是探针 bug，而是一个真实机制：**轮速驱动没有驻停能力**

腿冻结在 fixed stand、四轮目标**强制为零**的情况下，轮子仍以最高 **0.43 rad/s** 的速度转动。
原因在控制律本身：

```
tau_wheel = KD * (target - dq) = 6 * (0 - dq) = -6*dq
```

**零目标下轮驱退化为一个 kd=6 的弱阻尼器，不是刹车。** 机器人的重力/姿态不平衡只要能提供一个
等效驱动力，轮子就会收敛到 `6*dq = 该驱动力` 的速度 —— 即**稳态爬行**，而不是静止。

**→ 这直接解释了 goal 里提到的「零指令轮差偏置」：零指令下轮端根本不驻停，而是持续爬行。**

## 3. 斜坡数据（VOID 试验，仅作参考，不作阈值结论）

即便基线无效，逐档稳态数据仍可看趋势。第二轮（腿冻结）为例：

| 目标 rad/s | dq_ss（FL/FR/RL/RR） | tau_ss（N·m） |
| --- | --- | --- |
| 0.02 | +0.019 / +0.066 / +0.140 / −0.071 | +0.46 / −0.06 / −0.35 / +0.45 |
| 0.10 | −0.030 / +0.094 / +0.043 / +0.018 | +0.62 / +0.16 / +0.45 / +0.59 |
| 0.20 | +0.269 / −0.008 / +0.434 / −0.070 | −0.20 / +0.91 / −0.68 / +1.30 |

**趋势：目标 0.40 rad/s 时稳态轮速仍只有 0.13–0.52 rad/s，力矩只有 0.2–1.4 N·m。**
与上一轮「小目标严重欠跟踪」一致，但**不能**据此给出脱困阈值。

## 4. 结论

1. **阈值仍未测出**，两次重设计都被自己的基线门判 VOID —— 门工作正常，是设计前提不成立。
2. **根本障碍是控制律**：kd 速度驱动在零目标下没有驻停能力，机器人不可能静止，因此「从静止开始加扭矩找脱困点」这个实验范式**在当前控制律下不可用**。
3. **这本身是一个应当报告的机制发现**：零指令下轮端爬行最高 0.43 rad/s，与 goal 里的「零指令轮差偏置」一致。
4. **我不再继续盲目改这一版设计**。正确做法见下。

## 5. 正确的下一步设计（未执行）

要让「脱困」有意义，必须把机体锁住，让轮子单独对地打滑：

1. **把机身固定到世界**（Isaac Lab 里把 root 设为 kinematic，或用固定约束），使机器人不可能整体移动
2. 四轮目标从 0 起按 0.02 rad/s 分档、每档驻留 0.5 s
3. 阈值 = 稳态 |dq| 由 <0.02 跳到 >0.05 的那一档；此时记录实测投影力矩
4. 左右分别评估，量化左右阻力差

**注意**：机体锁定后的摩擦条件与真实滚动不同，结果只能作为**相对比较**（左右差、随载荷变化），
不能直接作为真实滚动阻力的绝对值。
