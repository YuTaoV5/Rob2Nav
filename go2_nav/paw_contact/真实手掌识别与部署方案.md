# Go2 真实相机伸手托爪：向下60°安装后的完整实机方案

先阅读[新手复现总览](../../docs/新手复现总览.md)与[环境准备与路径约定](../../docs/环境准备与路径约定.md)。本指南的环境变量均由当前机器配置；每个新终端先在仓库根目录source `scripts/docs_env.sh`。


更新：2026-10-21。先阅读[D435i/MID360安装与标定总手册](../../docs/D435i与MID360安装标定手册.md)，已有[网页MuJoCo技能与接触控制说明](虚拟手托爪仿真与部署手册.md)继续适用。

## 1. 直接回答：装好相机后现在能运行吗

**当前不能直接运行“真实手掌→Go2托爪”闭环。** 已有程序执行的是网页虚拟手目标 + MuJoCo接触；源码 `server.py` 接收target/start等网页命令，`handshake.py` 的 HandObservation 是位置/置信度等仿真观测。当前没有导入pyrealsense2、真实RGB-D同步采集或MediaPipe HandLandmarker的该技能适配模块。网页里的camera操作是MuJoCo观察视角，不是D435i驱动。

安装RealSense驱动后，驱动可以提供真实RGB/深度；还必须实现手掌识别、米制定位、外参/时间转换、机器人状态与接触力接入，以及真实柔顺控制的SDK适配。通用SDK框架存在，不意味着握手技能这些环节已完成或已在硬件通过。

相机固定在Go2机身上，必须有**相机→机身外参标定**。它常被宽泛叫“手眼标定”，但不必用机械臂末端相机的AX=XB算法；60°安装角不包含平移、真实光学frame或支架误差，不能替代标定。MID360不是原地托爪必须条件，也不能靠近场雷达点云代替可靠掌面深度或接触力。

## 2. 目标架构与需要新增的组件

```text
D435i ROS驱动 → 同步RGB+对齐深度+CameraInfo → hand_tracker（待实现）
                                              ↓
                      有效掌面点云/平面/法向/速度/协方差
                                              ↓
                      标定TF与测量时刻机身状态 → HandTarget
                                              ↓
              只读预览 → 目标稳定/可达/单手确认 → 现场人工开始
                                              ↓
Go2关节/IMU/支撑估计 → 真实WBC/阻抗/接触状态机（待适配）
前爪测力/触觉反馈 ──────┘                      ↓
                      单写入SDK控制与本地保护 → Go2
```

以下名称是**建议新增接口名**，不是当前已经安装的可执行节点：

| 组件 | 输入/输出 | 完成标准 |
| --- | --- | --- |
| `hand_tracker` | 图像/深度/K→掌心、掌面、法向、手势/身份 | 真实录制数据有误差/置信度/掉帧报告 |
| `hand_target_adapter` | 相机系目标+TF+状态→base/局部锚点目标 | 时间和坐标正确，陈旧/乱序/跳变被拒绝 |
| `paw_contact_hardware` | 状态、目标、接触力→关节指令 | 三足支撑、柔顺接触、退出轨迹、故障保护均经台架验证 |
| `task_arbiter` | 导航/托爪/遥控请求→唯一控制权 | 只有站稳后可启用托爪，导航执行器不可并发写入 |
| `hand_preview` | 真实图像、掌面、base位置、合法区、状态 | 明确“感知只读/实机”，不展示虚拟手冒充检测结果 |

不在文档里给虚构的 `ros2 run paw_contact_hardware ...` 命令。只有这些组件实际实现并有发布清单后，才把真实启动命令填进现场runbook。

## 3. 60°机位验证：先确认看得到

按总手册启动相机驱动，先不启用任何运动。将软质平面目标放在左右侧多个位置、高度，并在机器人标准站姿和拟托爪的重心转移姿态下检查：

1. 彩色图像完整看见掌心和识别所需手指，且掌心区域也有有效深度；不能只看RGB“有手”。
2. 深度距离、ROI边缘、反光/黑色手套、强光、背景遮挡均有实测；优先使用未经补洞伪造的原始有效深度做接触目标。
3. 模拟脚从地面到掌上方的整个路径，检查脚/小腿挡住掌心的时间。完全遮挡时不能持续盲压；需要调整机位、增加第二视角或限制允许的接近方向。
4. 将**整只掌面和脚垫安全余量**而不仅是一个中心像素投影到图像，检查离边界有余量；同一机位不保证左右完整工作区都覆盖。
5. 接近D435i最小Z时降低分辨率可能改变可用范围，但不能把理论Min-Z当作实际皮肤深度精度保证。用目标平面测量有效率和误差再决定。

网页建议范围X=0.31–0.43、|Y|=0.09–0.19、Z=0.15–0.24m使用的是**仿真初始站立世界锚点**，不是base_link里的z值。实机base原点通常在机身内部，手掌在base下方可能为负z。先通过实际站立高度/TF转换，再求腿可达范围，不能原样复制网页坐标作为相机外参或硬件目标。

## 4. 标定与验证：究竟标什么

### 4.1 相机内部和深度

读取当前流的CameraInfo/工厂内参、畸变、depth-to-color变换及深度单位，先用已知平面和多距离量距验证。工厂参数通常作为起点，不要求每次安装都重做双目工厂标定；验证失败时按厂商工具处理，而非手改fx或depth_scale让数据“看起来正确”。

对齐深度到彩色后，用对应color optical的投影模型。若使用librealsense原生API，使用其内参/深度比例和匹配的反投影函数；若走ROS，确认16UC1/32FC1单位，按CameraInfo畸变模型校正。不要将一个相机内参用于另一个分辨率。

### 4.2 相机到base与交互锚点

用总手册的已知板位姿夹具/PnP或外部测量方案求 `^B T_C`，保存真实序列号、流配置、矩阵方向、误差和标定日期。验证左右不同高度的独立位置；只验证一个中心点无法发现角度/尺度错误。

掌心反投影简化针孔式仅适用于已校正图像：

```text
X_C = (u-cx) Z / fx
Y_C = (v-cy) Z / fy
p_B(t) = R_B_C p_C(t) + t_B_C
n_B(t) = R_B_C n_C(t)
p_F(t) = ^F T_B(t) p_B(t)       # F为站稳建立的局部交互锚点
```

法向只旋转不平移；方向与重力/掌面朝向一致性另检查。世界/交互锚点使用测量时刻的机身位姿，不能用一帧旧图像配最新TF。外参固定不等于机身不动：重心转移会使相机随身运动，必须使用真实状态估计更新目标到锚点的转换。

### 4.3 误差与视野验收起点

建议初始工程目标：独立参考点三维误差P95≤10mm、最大≤20mm；法向误差P95≤10°；启动前连续稳定观测≥0.5s。它们不是D435i保证指标或人体接触安全阈值，最终要求由掌面可用面积、脚垫大小、支撑/接触误差预算决定。

掌面有效边界需要向内收缩，余量至少覆盖定位不确定性、运动延迟误差和足端跟踪误差。例如速度0.2m/s、总延迟0.1s会多出20mm误差，不能只看静态标定残差。误差超预算时先缩小交互区域/降低速度/改善机位，不能调高置信度数值使其通过。

至少采集左右×近中远×多个高度的独立验证网格；区分拟合点和holdout点，保存3D位置、法向、有效深度比例、延迟和判定。相机安装变动后重新检查。

## 5. 真实手掌识别与三维定位算法

建议首版先用带标记手套/软垫验证坐标与控制，再接自然裸手识别。AprilTag/ArUco的标记平面到实际掌面还存在厚度/偏移，需要标定，不能把标签中心直接当皮肤接触面。

自然手方案：使用[MediaPipe Hand Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/python)等模型给出手部关键点/身份，读取同一时刻对齐RGB-D。模型文件需额外下载并固定来源/版本/SHA；这是新增的感知模型，不是现有托爪控制器的训练权重。接入时使用匹配的 `hand_landmarker.task`，不要混用手势识别器等其他task文件。

推荐处理顺序：

1. 明确采集后端：ROS图像订阅或librealsense直接采集二选一。设置固定设备序列号、有限队列和图像/深度配对时差上限；忙时丢旧帧，不堆积延迟。
2. 从RGB找手腕/MCP等关键点，构造掌面内部ROI/掩膜，排除手指边缘、背景和运动中的机器人脚。人手左/右分类不等于机器人左/右爪，爪侧由任务和可达区独立选择。
3. 在掌面ROI取有效深度，去掉0/NaN、边缘混合、越距与异常离群点；反投影为米制点云。不能只取一个中心像素，更不能把背景深度当掌心。
4. 稳健平面拟合（如RANSAC后最小二乘），检查内点数、残差、掌面连通面积；得到表面接触中心、法向和可用多边形。手很弯或内点不足就拒绝。
5. 结合手指/姿态判断张掌、朝上和足够大。平面法向有正负歧义；用重力、可见面和手部几何共同确定，不靠cross乘的任意顺序固定正负。
6. 以可靠时间戳变换到base/交互锚点，估计速度和协方差，做有界滤波。多只手、身份切换、低置信、跳变或过快目标进入拒绝/人工重选，不能自动换到另一只手。
7. 接近接触时脚可能遮挡掌面。短时失效停止下探，不能靠补洞预测一直下降；长时失效先卸载，再按已验收轨迹收爪。保持阶段主要依靠接触反馈，不把视觉持续可见当唯一接触证据。

MediaPipe的world_landmarks原点在手的几何中心，**不是Go2/相机世界中的绝对掌心位置**；其归一化z也不是RGB-D量到的距离。不能把该字段直接写到机器人目标。手背朝上、握拳、背景图案和“只有爪没有手”都必须是负例。

## 6. HandTarget消息契约与启动门控

实际节点建议发布自定义消息或等价结构，至少包含：

```text
stamp_measurement, stamp_received, frame_id
position_m[3], palm_normal[3], velocity_mps[3]
position_covariance[9], normal_uncertainty
valid_depth_ratio, plane_residual_m, confidence, open_palm
hand_track_id, requested_leg=FL|FR, session_id, sequence
calibration_id, camera_serial, reason_if_invalid
```

驱动掉线时仍输出明确invalid/心跳，不能默默重复最后一个valid目标。置信度不能只复用神经网络的检测分数，还要包含深度、几何、时间和跟踪质量。

初始门控建议：测量年龄≤100ms、RGB-D配对时差≤20ms、稳定≥0.5s；只是一组待实测调整的工程起始值。确认掌面朝上、有效区包含脚垫及误差余量、目标位于选定腿可达区、其余三腿有稳定支撑、求解器与执行状态健康，才能允许人工点击开始。感知有效不自动授权动作。

现有仿真HandObservation缺少完整时间/法向/协方差字段，不能把新消息中的位置三元组简单塞进去就宣称硬件适配完成。需要抽离/扩展目标接口，并与真实机器人状态、支撑锚点及控制循环联调。

## 7. 机器人端还必须做的工作

| 环节 | 必须完成的实机工作 |
| --- | --- |
| 状态/FK | 关节顺序/零位/符号、真实限位和足垫偏移；IMU姿态、支撑足位置与机身运动估计 |
| 模型/负载 | 带相机/雷达/支架后的质量与惯量；动力学雅可比和真实电机约束 |
| 接触测量 | 在独立测力台标定前爪力/触觉，核对零偏、线性、滞回、带宽；不能把LowState足力直接视为准确小力测量 |
| 控制器 | 真实WBC/QP/阻抗；三足支撑、质心裕度、约束残差、低刚度接近/卸载/收爪；不可直接把MuJoCo动力学API用于实机 |
| SDK/保护 | 单写入、已验证模式切换、限幅/速率/时效与本地看门狗；状态丢失时有保持支撑的有界保护 |
| 任务仲裁 | 导航、托爪、遥控不得同时接管电机；模式切换需要稳定状态和确认握手 |
| 人机交互 | 标明所选腿、已锁定手、目标误差/年龄与停止原因；相机识别成功也须等待现场动作启用 |

原厂SportClient速度接口适合第一版导航，不能直接承担“把某只脚以3N放到掌上”的精细接触控制。若采用厂商高级动作接口，必须确认其开放能力并单独验收；不能假设 Move 或一个预置握手动作已经实现视觉引导的柔顺托爪。

已有仿真约3N目标、18N退出等参数只是仿真实验设置，不能直接作为真人可承受阈值。以软垫测力台先低力闭环验证峰值/超调/卸载时间，再由现场风险评估确定实际限值。严重失稳/状态过期不能无条件瞬间清零所有关节力矩导致失撑。

## 8. 标定完成之后的现场操作顺序

1. **只读感知**：启动驱动→加载与序列号/分辨率匹配标定→手掌检测→叠加3D目标/法向/合法区。确认程序未创建任何电机写入器，记录不同手形/光照/遮挡的数据。
2. **目标回放**：用真实bag离线驱动仿真HandTarget适配，验证坐标、过期/丢帧/多手/突变拒绝。此项测的是目标适配，不是假装真实脚已安全。
3. **状态与接触台架**：只读SDK反馈和FK，测力/负载标定；现场支持保护条件下验证单腿小幅方向与低刚度响应，随后验证四足→三足支撑转移。
4. **假手/测力台闭环**：固定软垫位姿开始，验证抬爪、接近、首次接触、保持、目标移开、卸载与收爪。先固定目标，再给视觉目标闭环，逐项测力/姿态/滑移。
5. **故障注入**：断相机、冻结旧图像、增加延迟、遮挡掌心、目标越界、推移手台、停止SDK状态/网络、人工接管；每项都必须有可复核的退出表现，不能只看进程未报错。
6. **有限真人测试**：前述阶段均完成并经现场负责人确认后，在已验证的窄工作区、低速/低力、专人保护和独立急停条件下开始；逐步增加目标位置/缓慢运动，记录失败和峰值。

这六步没有在当前真实Go2上执行。公开仿真42/42、随机组合32/32不能用作它们的通过记录。

## 9. 与SCAN联合工作时如何操作

先导航到预定交互点→取消路线并确认实际速度降至站稳阈值→确认四足支撑与估计器健康→通过仲裁释放导航运动控制权→进入托爪准备模式→识别/人工选爪/开始→卸载收爪并恢复四足→确认目标清除和接触解除→再交回导航。

保持同一base定义和标定ID。LIO重定位跳变、急停或导航需要重新定位时，中断托爪任务，不能通过跳变后的世界目标拉动脚。任何未完成的控制模式交接都保持任务未启用。不要在持爪接触中自动开始走动或执行翻转特技。

## 10. 可交付验收材料与已知缺口

应交付：安装图/序列号、软件/模型锁定、CameraInfo与标定矩阵、独立3D误差/法向/延迟报告、真实手掌负例/遮挡bag、FK/力标定、WBC约束与跟踪报告、SDK模式/看门狗检查、假手接触日志、每项故障测试及有限真人测试记录。

本次交付是完整安装/集成方案与离线几何检查工具；缺少的仍是硬件实测数据和上述待实现节点。后续真正进入开发时，应先实现“真实相机只读检测并显示米制目标”，再适配接触控制和SDK，不能以安装驱动完成代替整个功能。
